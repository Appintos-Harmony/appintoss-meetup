# 하모니 — 피그마 화면명세서

> 하모니(토스에서 악기를 연주하고 친구와 한 곡을 비동기로 완성하는 미니앱)의 8개 화면을 피그마에 바로 옮길 수 있도록, 실제 구현(apps/miniapp/src) 기준으로 토큰·컴포넌트·레이아웃·상태·API·주석을 정리한 단일 화면명세서.

---

## 0. 이 문서 사용법 / 화면 인덱스

이 문서는 디자이너가 피그마에서 8개 화면(SCR-A~H)을 만들 때의 **단일 진실 출처(SSOT)**다. 모든 수치·색·컴포넌트명은 `apps/miniapp/src/theme.css` 및 라우트 코드에서 그대로 가져왔다. 작업 순서는 다음과 같다.

1. **§1 디자인 시스템**으로 피그마 변수/스타일/컴포넌트를 먼저 등록한다.
2. **§2 내비게이션 맵**으로 화면 간 연결(프로토타입 엣지)을 잡는다.
3. **§3 화면별 명세**의 각 화면 `피그마 레이아웃 지시서`와 텍스트 와이어프레임으로 프레임을 그린다.
4. **§4 우선순위**대로 고충실도화하고, **§5 정합성 메모**의 코드-명세 불일치를 반드시 반영한다.

> 정책 고정(DL-016/DL-019): 자체 로그인/회원가입 없음(토스 비사업자 로그인 불가) → `getAnonymousKey` 익명키 + 닉네임 1회 온보딩으로 대체. **"로그인" 라벨을 사용자에게 노출 금지.** 100% 라이트 테마. 자체 뒤로가기 UI 금지(토스 공통 사용). 핀치줌 금지.

> **결정:** 디자인 정본 = **공식 TDS Mobile UI Kit(피그마)**. `theme.css`(자체 토큰)는 **일반 브라우저 데모 폴백**으로만 유지(TDS는 실제 토스 WebView 밖에서 throw, `main.tsx`). 근거 = [공식문서_근거목록](../02_정책준수/공식문서_근거목록.md) #11~#13. **비게임 미니앱은 TDS 사용이 검수 필수.**

### ★.3 피그마 시작 절차 (정본)

1. **UI Kit 다운로드**(곽소정, 콘솔/디자인 페이지의 `TDS_Mobile_for_Apps_in_Toss_(2602-3-2).zip`) → Figma **Import** → **Publish**(라이브러리화).
2. 각 화면을 🌈 **Screen** + ❖ **Navigation**부터, **375px** 프레임.
3. 표준 화면(홈·커뮤니티·설정) = **Top·ListRow·Tab·Button·BottomCTA**로 조립(앱빌더 AI 초안 → 피그마에서 다듬기 OK).
4. 스튜디오·편집·연주 = §★.2의 **자체 악기 컴포넌트**(05 TDS Mapping 페이지에서 별도 관리)를 TDS Screen 안에 배치.
5. 속성은 **우측 패널만** 조작(컴포넌트 구조 수정·재배포·상업적 사용 금지 — 라이선스 #12).

> 아래 §1~§3은 **현행 구현(theme.css) 기준**이다. TDS 정본과 충돌 시 본 ★절이 우선하며, §★.2 매핑으로 옮겨 사용한다.

**예외 상황**
- 빈/공백 닉네임: name.trim() 거짓이면 CTA disabled(.4) — start() 호출 불가, 별도 에러문구 없음(입력 차단형)
- busy 재진입: start() 진입 즉시 setBusy(true)로 CTA disabled → 더블탭 방지. 단 try/finally 없어 getUserKey 실패 시 busy 미해제(현재 mock은 throw 없음) — [미구현·계획] 에러 시 busy 복구·토스트 필요
- getAnonymousKey 미지원(SDK 2.4.5 미만): identity.ts가 performance.now()+userAgent 해시 mock 익명키 fallback → 흐름 중단 없음
- localStorage 차단/시크릿 모드: setItem 예외 시 미저장 → 매 구동 온보딩 재노출 가능. [미구현·계획] try/catch 가드 없음
- 길이 초과: maxLength=16 브라우저 차단(카운터 없음)
- 스플래시 도중 이탈: clearTimeout으로 콜백 취소, 부작용 없음

**로딩/빈/오류 상태**
- 로딩: 스플래시 자체가 로딩 게이트(1.3초 리빌). 온보딩 CTA busy 동안 '잠시만요…'+disabled — getUserKey await 표시. 별도 스피너 없음
- 빈: 온보딩 초기 = 닉네임 빈 입력이 기본. placeholder '예: 토스밴드'+안내 캡션으로 가이드, CTA disabled. 리스트형 빈 상태 해당없음
- 오류: 코드상 명시적 에러 UI 없음. [미구현·계획] getUserKey/localStorage 실패 대비 인라인 에러/토스트+busy 복구 필요

- '이어하기'엔 최신 곡 최대 3개만(slice 0,3) — 홈은 목록이 아니라 디스패처.
- 최근 곡 ListRow 탭 → 그 곡을 스튜디오에 로드(onOpen→loaded set→studio).
- 코드 Badge는 phase='on' 중복 제거 후 최대 6개, C=blue/Am=violet/F=mint/G=coral, 그 외 sub.
- 녹음 이벤트 없는 곡은 Badge 대신 '빈 곡' 캡션.
- 곡 목록 동기 로컬 읽기라 로딩 상태 없음 — 진입 즉시 fadeUp 220ms 1회.
- localStorage 손상 시 조용히 빈 목록 복구 → 사용자에겐 빈 상태로만 보임.
- [미구현·계획] '합주 받기(클립보드 자동 인식)'는 홈 아니라 스튜디오 소관 — 홈엔 별도 버튼 없음.
- [미구현·계획] 하단 내비바 없음 — 진입 ListRow+해시 딥링크로 이동.
- [미구현·계획] 빈 상태 ListRow는 현재 비클릭 — '첫 곡 만들기' CTA로 go('studio') 연결 권장.
- **구현 상태**: 부분 구현. 핵심(Navigation+설정, 인사/서브카피 empty 분기, 진입 ListRow, 이어하기 빈상태/최근3곡+코드 Badge, onOpen 이어하기, listSongs 읽기·손상 복구) 모두 구현. '합주 받기'·'하단 내비'·빈 상태 카드 CTA는 미구현(계획).

### 3. SCR-C 합주방 생성 · 공유 (Studio 저장/공유 + 받기 흐름)

- **화면 목적**: 내 녹음(take)을 비동기 합주로 만드는 화면. 내 곡을 로컬 저장하거나 공유 코드(6자리)로 세션을 생성해 친구에게 보내고, 친구는 코드/클립보드로 가져와 내 트랙 위에 자기 연주를 '얹어' 합주를 완성한다. 실시간 방이 아니라 세션 코드 기반 비동기 레이어다.

**진입 경로**
- 홈 → 스튜디오 진입(route='studio')
- 녹음 완료(hasTake=true·phase='idle') 시 트랜스포트 하단에 저장/음편집·공유 액션 노출
- 커뮤니티에서 '얹기' → App.forked 세트 → 스튜디오 진입 시 useEffect([forked])가 베이스 트랙 로드 + sessionCode 세팅(LOCAL 접두사면 null)
- 본 화면 '가져오기(receive)' → 클립보드 6자리 코드 또는 PRELOAD(DEMO01) → 받기 BottomSheet
- 공유(share) 직후 sessionCode 세팅 → 동일 화면에 합주 세션 ListRow 카드 인라인 표시

**예외 상황**
- 악기/스타일은 4종×2스타일 고정 — '신스/어쿠스틱/일렉' 별도 카테고리 없음. 내부 프리셋 키(grand/electric/acoustic/precision/jazz/analog/electronic)는 UI 미노출, '피아노 1·2' 식 라벨만 표시
- 베이스 라벨 이모지 🎻(콘트라베이스). bass:jazz=contrabass 샘플 사용
- 스타일은 '화면 동일·소리만' — 바꿔도 레이아웃/패드 불변(엔진 setVoice만)
- 녹음 중(countin/recording)엔 악기 변경 불가(토스트 안내). 콤보도 disabled

**로딩/빈/오류 상태**

### 5. SCR-E 녹음 · 재생 (Studio 코어 ★)

> 🌈 **Screen** 템플릿 위에 ❖ **Navigation**(큰 제목 Top — '스튜디오')을 얹어 구성. 프레임 폭 **375px**(TDS 표준; 와이어프레임의 480은 theme.css 폴백 캡). 폰트는 Figma **SF Pro** / 토스앱 **Toss Product Sans**. 색은 TDS Semantic 토큰명으로 표기하고, 기존 hex는 (현행 코드값, UI Kit과 다를 수 있음)으로 주석. 악기·연주·편집 전용 컴포넌트(CameraBlock·ChordMatrix·코드패드·PianoKeyboard·NotePadGrid·DrumPad·BeatIndicator·TrackAvatar·EditToolbar 등)는 TDS에 없으므로 **자체 컴포넌트(TDS Screen 안에 배치)**로 유지.

**예외 상황**
- AudioContext 잠금: ready=false면 첫 터치까지 무음. 상태 Badge '눌러서 소리 켜기', 모든 발음이 ensureAudio()로 unlockAudio 후 진행
- 카메라 권한 거부/미지원: selectGesture try/catch→stopGestureLoop+터치 폴백+'카메라를 쓸 수 없어 터치로 연주해요'(camMsg)
- 손 미인식: detect()가 빈 배열→코드 upChord('gesture')로 발음 정지, 드럼은 타격 없음. 존/킷 하이라이트 해제
- 터치 우선 정책: 녹음 중 터치 중이면 제스처 무시, 터치 해제 후 GESTURE_RESUME_MS(200ms) 동안 제스처 게이트(오발 방지)
- 녹음 중 악기 변경 차단: chooseVoice가 phase!=='idle'이면 토스트로 거부
- 양손 모드 한계: mono reducer로 2코드 동시 불가 → 손별 직접 chordOn/Off + recordRaw로 이벤트 직접 적재
- 공유/가져오기/얹기 네트워크 실패: req throw→catch에서 토스트, getSession 실패 시 PRELOAD 데모 폴백
- 저성능 단말: [부분구현] devMode FPS 측정만 존재, 자동 화질 강등/제스처 비활성 임계는 [미구현·계획]
- 재생/합주 중 재진입: play/playSession 시작 시 stopPlayback+stopJam+allOff로 잔류 정리
- 옥타브/줌 경계: octave 1~5, camZoom 1~3 clamp. 경계 버튼 opacity .4 + disabled

**로딩/빈/오류 상태**
- 로딩: 카메라 준비 중 camMsg '카메라 준비 중…'/'카메라 전환 중…'. 오디오 첫 활성 전 '눌러서 소리 켜기'. 합주 세션 폴링 1.5s 백그라운드(스피너 없음)
- 빈: 테이크 없음(hasTake=false): ▶재생·💾저장·🎚편집·📤공유 숨김/비활성, 상태 Badge '준비됐어요'. 코드 미선택 시 '연주할 코드를 골라보세요'. 세션 없으면 합주 카드 미노출
- 오류: 공유/얹기 실패 '…— 네트워크 확인' 토스트. 카메라 불가 시 터치 폴백. getSession 실패→PRELOAD 데모 또는 '받을 트랙이 없어요'. 오프라인 세션 폴링 실패는 조용히 무시

**디자이너·개발자 전달용 주석**
- ● 녹음을 누르면 즉시 녹음이 아니라 '카운트인'으로 — 한 마디(4박) 메트로놈 후 자동으로 녹음 시작(onBeat bar≥1).
- 카운트인 동안 누르고 있던 음/코드는 녹음 시작 시점에 선적재되어 첫 박을 놓치지 않음.
- ▶재생은 테이크가 있어야(hasTake) 활성 — 없으면 회색(Text Alternative/sub)·비활성, 녹음 중에도 비활성.
- 녹음 중에는 악기를 바꿀 수 없음 — 콤보 누르면 경고 토스트만.
- 제스처는 '터치 우선' — 터치 연주 직후 0.2초는 제스처 무시(손 빠질 때 오발 방지).
- 코드 제스처는 화면을 세로 존으로 분할(인라인 4개/전체화면 6개) — 손이 든 존의 코드가 지속음(존 상단 컬러바 하이라이트).
- 드럼 제스처는 2D 키트 위 손 위치 가장 가까운 피스를 '상승엣지'로 1회 타격 — 같은 자리 유지 시 중복 타격 안 됨.
- 양손 모드는 코드 2개 동시 — mono reducer 우회로 손별 직접 발음하고 녹음 이벤트는 따로 적재.
- 공유=POST /sessions로 6자리 코드+클립보드 복사, 얹기=POST tracks로 같은 세션에 내 트랙 추가(비동기 합주).
- 오프라인이어도 가져오기는 PRELOAD 데모(토스밴드 C·G·Am·F)로 폴백해 데모가 끊기지 않음.
- [설계상 '실시간 파형'은 미구현] 현재 실시간 표시는 4박 BeatIndicator(비트닷)+상태 Badge(녹음 중=Error/coral). 파형 시각화는 [미구현·계획] — **디자인에서 '파형' 컴포넌트를 그리지 말 것**(BeatIndicator로 한정).
- AudioContext 잠금 상태에선 첫 탭 전까지 무음 — 모든 발음이 ensureAudio()로 1회 unlock.
- **구현 상태**: 구현 완료(코드/멜로디 세그·악기콤보·터치/제스처(한손·양손·손바닥/손가락·카메라전환·줌)·카운트인 녹음·재생·메트로놈·저장·음편집·공유/가져오기/얹기/합주 듣기·전체화면(가로)). 부분/미구현: '실시간 파형' 미존재(BeatIndicator+상태 Badge 대체); 저성능 자동 화질강등/제스처 임계는 devMode FPS 측정만 있고 미구현; 손 미인식 전용 안내 UI는 별도 없이 발음정지로만 처리.

### 6. SCR-F 편집 화면 (NoteEditor · 피아노롤 음 편집)

- **화면 목적**: 녹음된 take(ChordEvent[])를 박자 그리드 위 블록으로 펼쳐, 노트를 드래그/버튼으로 이동·음정변경·길이조절·퀀타이즈·삭제하고 미리듣기로 확인한 뒤 [적용]으로 스튜디오에 되돌려주는 가라지밴드풍 음 편집 전체화면 오버레이. TDS 🌈 Screen 템플릿 위 풀스크린 오버레이로 얹는다.

**진입 경로**
- 스튜디오 → 녹음 완료(hasTake=true) & 정지 상태(busy=false)에서만 노출되는 '🎚 음 편집' 버튼 → setEditing(true)
- NoteEditor는 라우트가 아니라 Studio 위에 position:fixed inset:0 z-index:80 오버레이로 마운트(editing && <NoteEditor/>)
- events prop = stateRef.current.events(현재 take). take 비면 버튼 자체가 안 보여 진입 불가지만, 진입 시 notes.length===0이면 빈 상태 문구 표시

**디자이너·개발자 전달용 주석**
- 진입 버튼 '🎚 음 편집'은 녹음 완료(hasTake) & 정지(busy=false)일 때만 노출.
- 노트 블록(NoteBlock 자체 컴포넌트)은 드래그 가능: 가로=시간 이동, 오른쪽 끝 18px 잡으면 길이 조절(편집선=리사이즈 핸들 흰 3px).
- 멜로디만 있는 take는 연속 반음 피아노롤이라 세로 드래그로 음정 변경 가능, 코드/드럼 섞이면 값별 이산 레인(세로 이동 잠금).
- 드럼 노트는 점(●)으로 표시되고 길이/음정 편집 불가(표시용 고정 dur).
- 선택된 노트만 외곽 검은 링 + 다른 노트 디밍 — 미세조정/삭제 버튼은 선택 있어야 활성화.
- ▲음/▼음은 멜로디 노트에서만 활성화(코드/드럼은 비활성).
- ◀▶ 한 번 = 1/8박(GRID), ⏱맞춤=선택만/전체 박자 맞춤=모든 노트 그리드 스냅.
- 미리듣기 누르면 빨간 '■ 정지'로 바뀌고, 재생 끝나면 자동 정지 — 취소/적용/화면이탈 시 소리·타이머 모두 정리.
- [적용]을 눌러야 편집이 스튜디오 take에 반영됨(취소는 폐기) — 자동 저장 아님.

**예외 상황**
- 같은 카드 듣기 재탭=정지(playingId===id 시 stop). 새 카드 재생 시 기존 stop() 후 시작 — 동시 재생 불가, 항상 1곡
- getPublication 실패 시 재생 '재생할 수 없어요', 얹기 '가져오기 실패'
- 좋아요 setLike 실패 시 이전 값 롤백. status===503이면 '잠시 후 다시 시도해 주세요', 그 외 '좋아요 실패'
- events 중 chord/note 둘 다 없는 항목(드럼 v2 hit)은 skip — 현 오디오 엔진 미지원
- 폴링이 방금 조작 항목을 덮지 않도록 pausePoll(상호작용 후 4초)·loadMore 동안 폴링 일시정지
- myPublications 실패 시 빈 결과 {count:0, limit:5, items:[]}로 폴백(에러 화면 없음)
- 언마운트 시 stop()으로 타이머·오디오 정리(allOff)
- 신고/삭제는 window.confirm 네이티브 다이얼로그 — 토스 톤 불일치 [미구현·계획: BottomSheet(UI Kit 확인 후, 없으면 자체)로 교체 권장]

**로딩/빈/오류 상태**
- 로딩: feed items===null 동안 Skeleton 3개. mine mine===null 동안 Skeleton. (정렬/필터/탭 전환 시 items=null 리셋). 더 보기 중에는 '불러오는 중…'이고 카드 유지

### 8. SCR-H 마이페이지 · 설정 (Settings)

> ⚠️ 검증 정정(§5): 자동 검증 패스가 '개발자 모드 토글이 실제 렌더된다'고 보고했으나 **코드 재확인 결과 오류(환각)**. 실제 `Settings.tsx`(`{ go }`만 받음)에는 토글이 없으며, 화면은 닉네임·버전·약관/개인정보 고지·안내문·'홈으로' 버튼만 렌더한다. 아래 본문은 이 사실에 맞춰 정정했다.

## 5. 정합성 메모 · 미해결

> 코드(apps/miniapp/src) 대비 제공 명세 데이터에서 발견한 불일치·리스크. 피그마 작업 전 반드시 반영.

- **[검증 환각 정정·중대] 개발자 모드 토글은 실제로 없음**: 자동 검증 패스가 'Settings.tsx에 동작하는 토글이 렌더되고 App.tsx가 onToggleDev를 주입한다'고 보고했으나, **사람 검토 결과 환각(코드에 존재하지 않음)**. 실제 `Settings.tsx`(`{ go }`만 받음)는 닉네임·버전·약관/개인정보·안내문·'홈으로'만 렌더하며 토글·onToggleDev·setDevMode 호출처 모두 0건이다. settings.ts의 get/setDevMode는 함수만 존재하고 App.tsx는 getDevMode를 읽기 전용 1회만 사용 → **devMode를 켜는 인앱 UI 없음**(현재는 localStorage 수동 설정). SCR-H 본문은 이 사실로 정정 완료. 디자인의 DevToggle은 '미구현 제안 컴포넌트'로만 취급.
- **[명세-코드 동기화] SCR-H 미렌더 기능**: 개발자 토글·내 곡 관리/삭제·데이터(전체) 삭제는 라이브러리(settings.ts·storage.ts)에 함수만 있고 Settings 화면에는 렌더되지 않음 — 전부 [미구현·계획]. uiElements/구현상태에 그대로 반영함.
- **[정책 위험] '로그인' 노출**: SCR-A 명세는 '로그인' 라벨 금지를 명시하나, 화면 제목 자체가 'SCR-A 로그인·온보딩'이고 priorityOrder/문서에 '로그인'이 노출됨. 화면 ID/제목을 '진입·온보딩' 등으로 바꿔 사용자 노출 카피와 내부 명칭 모두에서 '로그인' 제거 권장(DL-016).
- **[상태 누락] 핵심 화면 에러 복구**: SCR-A·SCR-C·SCR-E 공통으로 getUserKey/공유/얹기 실패 시 busy 복구·에러 토스트가 '미구현·계획'으로 명시됨. CLAUDE.md §12·§21은 모든 핵심 화면에 오류 상태 설계를 요구 → 배포 전 인라인 에러+busy try/finally 필수 항목으로 승격.
- **[상태 누락] localStorage 차단**: SCR-A localStorage 차단(시크릿 모드) 시 익명키·닉네임 미저장→온보딩 무한 재노출 가능. try/catch 가드 미구현 — Edge Case 상태로 명세화 필요.
- **[톤 불일치] 네이티브 confirm**: SCR-G 커뮤니티 신고·삭제가 window.confirm 네이티브 다이얼로그 사용(토스 톤 불일치). 명세도 [미구현·계획: .sheet 바텀시트 교체]로 인지 — 컴포넌트 라이브러리에 '삭제 확인 시트'를 정식 변형으로 추가해 통일 권장.
- **[기능 누락] 드럼 재생**: SCR-G·SCR-E에서 드럼(v2 hit) 이벤트는 커뮤니티 재생 시 엔진 미지원으로 skip. 공유는 가능하나 재생 불가 → 데모에서 드럼 트랙 합주 시 청취 누락 위험, 명세에 사용자 고지/엔진 확장 우선순위 표기.
- **[명세 vs 설계 의도] 실시간 파형 없음**: SCR-E '실시간 파형'은 코드 미존재(비트닷+상태텍스트로 대체)임을 명세가 정확히 표기 — 디자인에서 '파형' 컴포넌트를 그리지 말 것(BeatIndicator로 한정). 일관성 OK, 인계 시 강조.
- **[버전 동기화] 버전 하드코딩**: SCR-H 버전 '1.0.0' 하드코딩(Settings.tsx L29)·빌드 메타 미연동. 릴리스 시 수기 갱신 누락 위험 — 빌드 시 주입 권장.
- **[법적 리스크·릴리스 블로커] 약관/개인정보**: SCR-H 약관·개인정보 처리방침 '준비 중' 플레이스홀더. 정식 문서 라우팅은 배포(심사) 전 필수(P1) — gaps가 아닌 릴리스 블로커로 추적.
- **[라우팅 검증 OK]**: navigationMap의 모든 엣지는 App.tsx 평면 4라우트(home|studio|community|settings)+Splash/Onboarding 게이트, onOpen(loaded)·onFork(forked) 콜백과 일치. 하단 탭바 부재(진입카드+해시 딥링크 대체)도 코드와 일치 — 불일치 없음.
