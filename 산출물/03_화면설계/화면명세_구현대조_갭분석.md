# 화면 명세 ↔ 구현(as-built) 대조 갭분석

> **이 문서는 김민혁(reviewer) 산출물이다.** 기존 화면명세 Draft 5종(인덱스 + 상세 4)을 `develop` 통합 앱(030 풀스튜디오 + 031 셸)의 **실제 코드(as-built)** 와 대조해 갭을 식별한 리뷰다. 화면명세서 본체(소유 = 곽소정/이상혁)를 **직접 수정하지 않는다.** 모든 정정은 **"제안 패치(소유자 통합 대기)"** 로만 제시하며, 디자인/정책 결정이 필요한 항목은 단정하지 않고 Open Question으로 남긴다.
>
> 방법: 화면명세 아키텍트 페르소나(`.claude/agents/screen-spec-architect.md`)로 화면 7개(스플래시·온보딩·홈·스튜디오·커뮤니티·설정·앱셸)를 **화면별 갭분석 → 적대적 코드검증(날조 색출) → 완전성 비평** 3단으로 분석. 모든 갭은 `파일:줄` 근거를 가지며, 적대적 검증을 통과한 항목만 싣는다.

## 2. 우선순위 갭 목록

### HIGH

- **[H1] SCR-HOME 본문 명세 부재 + §A-1 stale.** 인덱스(화면설계서.md:19)는 SCR-HOME을 하모니_화면명세서.md로 링크하나 그 문서에 SCR-HOME 절이 **없다**(grep 0건). 가장 가까운 §A-1 "홈" 행(하모니_화면명세서.md:64)은 *"최근 곡 1~3 + 합주 받기(보관함 흡수)"* 라는 **구 MVP v1 개념**으로, as-built 디스패처 허브(Home.tsx:51 스튜디오 카드 / :60 커뮤니티 카드 / :69 이어하기 읽기전용 / :43 설정 기어)와 불일치. 현재 홈을 기술하는 명세가 어디에도 없음. → §3-C 제안.
- **[H2] DrumPiece 입력 계약 ID 불일치.** 스튜디오 명세 §410·§331·§457은 `DrumPiece='kick'|'snare'|'hat'|'crash'` 4종이나, 코드 events.ts:12는 8종 `'kick'|'snare'|'hihat'|'ride'|'crash'|'hitom'|'midtom'|'floortom'`. 명세의 `'hat'`은 코드에 없고 `'hihat'`. §307·§341이 "8피스 확장"을 보강했으나 타입정의(§410)·이벤트표(§331)·악기표(§457) 토큰이 코드 진실원(events.ts:12)과 충돌.
- **[H3] SCR-ST-00 오디오 오류/권한 상태가 명세 클레임과 달리 미구현.** 명세 §73("오류→토스트 '소리를 켤 수 없어요'+콤보 롤백"), §74("권한거부→'소리 권한이 필요해요'"), 상태매트릭스 §442가 **구현으로 단언**하나, `ensureAudio`(Studio.tsx:311-317)는 try/catch 없이 `await unlockAudio()`→`setVoice()`만 호출 → 실패 시 토스트·롤백 경로 전무(unhandled). 세 토스트 문자열 전 src grep 0건. **§12 '오류'·'권한'이 미구현인데 구현으로 기술됨.**
- **[H4] 커뮤니티 라우트 ↔ SCR-ID 매핑이 인덱스에 없음.** 인덱스(화면설계서.md:21)는 커뮤니티 행을 SCR-C01~04(미구현 게시판, 커뮤니티 명세서:31 "어느 것도 구현하지 않았다")로만 링크. 실제 Community.tsx가 구현하는 건 **SCR-ST-06 진입 스캐폴드**(데모 목록·들어보기·fork; Community.tsx:1 자기명시)인데 인덱스 커뮤니티 행에서 직접 참조되지 않음. 라우트 `community`의 as-built 화면을 가리키는 SCR-ID가 인덱스에 부재.

### MED

- **[M1] §A-1 화면목록에 커뮤니티/스플래시 누락 + SCR-prefix 부재.** §A-1(하모니_화면명세서.md:60-66)은 SCR-00/홈/스튜디오/설정만 나열 — 커뮤니티 라우트(App.tsx:39)·스플래시 게이트(App.tsx:29) 빠짐. 제목도 "라이트 3라우트"인데 코드는 4라우트.
- **[M2] 스플래시 전용 본문 명세 없음.** 인덱스(화면설계서.md:18)가 SCR-00을 "스플래시·온보딩"으로 묶었으나 정본 어디에도 스플래시(Splash.tsx — 매 구동 1.3초 브랜드 리빌, App.tsx:29 게이트) 전용 행이 없음(§C 폐기원안 line 201 나열에만 등장). §12 6상태 판정 불가.
- **[M3] TrackMeta 형상 불일치 (신규 발견).** 스튜디오 명세 §418은 `interface TrackMeta { instrument; style }` 2필드이나 코드 events.ts:15-19는 **`{ owner; instrument; style }` 3필드**(owner 추가). 또 명세 §401-405 `Style`은 7값 유니온인데 events.ts:19는 `style: string`(느슨). AutoSaveOnStop·합주 fork가 `owner`에 의존(Studio.tsx:243 `base.owner`)하므로 명세의 owner 누락은 실질 갭.
- **[M4] FR 추적표 SCR 표기 ↔ 인덱스 ID 불일치.** 추적표(요구사항_추적표.md:27,32)는 화면을 "SCR-00"·"홈(SCR 미정)"으로 적는데 인덱스는 같은 화면을 "SCR-00"·"SCR-HOME"으로 부름. **인덱스가 발명한 SCR-HOME/SCR-SET를 추적표가 인정하지 않아** 3자 정합이 깨진 채 남음.

### LOW

- **[L1] 식별키 심볼 혼선.** 인덱스(화면설계서.md:18)·§A·추적표가 식별키 발급을 `getAnonymousKey`로 부르나, 실제 Onboarding.tsx:11이 호출하는 함수는 **`getUserKey()`**(identity.ts:7). `getAnonymousKey`는 identity.ts:1·8 주석의 '프로덕션 교체 예정 SDK 함수'명일 뿐 현재 호출 심볼이 아님(mock 대역).
- **[L2] SCR-SET 개발자 모드 상태 명세 부재.** 인덱스(화면설계서.md:22)는 SCR-SET를 "설정·개발자 모드"로 등재하나 정본 본문은 "최소(법적정보, 고객센터=토스 공통)" 한 줄(하모니_화면명세서.md:50,66)뿐 — Settings.tsx:32-67 개발자 모드 토글(FPS·네트워크·손 스켈레톤)을 기술하는 명세가 없음. (덤: 버전 "1.0.0" 하드코딩 Settings.tsx:29 vs package.json `0.0.0` — stale.)
- **[L3] 커뮤니티 미리듣기 음색 불일치.** Community.tsx:64는 fork 전 미리듣기를 항상 `createVoice('piano','grand')`로 고정. SCR-ST-06 명세(§382 "트랙별 TrackMeta대로 음색 복원")와 어긋남(스캐폴드라 허용 범위이나 명세에 '스캐폴드=피아노 고정' 명문 없음).
