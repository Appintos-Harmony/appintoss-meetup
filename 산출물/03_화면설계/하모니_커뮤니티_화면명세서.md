# 커뮤니티 + 음원 게시판 — 화면 명세서

> **상태 갱신(2026-06-23): 구현됨.** 본 문서 §1~§6의 SCR-C01~C04는 2026-06-22 당시의 **원안(4화면 피드형, 이후 보류)**이다. 그 뒤 TASK-006/009로 커뮤니티가 **단일 보드 화면**으로 실제 구현됐다(서버 공유 보드 + 출처 파생 루프 + 댓글 + 좋아요 + 재생 바). **현행 화면은 아래 §7 "as-built"가 기준**이며, 원안 §1~§6은 설계 이력으로 보존한다. 기능 정의는 [기능명세서 v4](../05_개발설계/하모니_커뮤니티_기능명세서.md), 화면 이미지는 [이미지 명세서](하모니_커뮤니티_이미지명세서.md)·[도움말 가이드](커뮤니티_이미지/커뮤니티_도움말_가이드.svg).
> 공유 단위는 **연주 이벤트(NoteEvent JSON)**다. 오디오 파일이 아니다. 와이어·저장 형식은 하위호환을 위해 `ChordEvent`(`{tick, phase, chord, source}`) 모양 그대로 두고, `NoteEvent`(코드/멜로디/드럼 판별유니온)는 그 위에 `kind`를 입힌 타입 뷰다(`apps/api/server.mjs`·`apps/miniapp/src/lib/share.ts`·`apps/miniapp/src/audio/events.ts`의 `normalizeEvents`). "음원" 정의는 미해소(아래 §5).

## 0. 배경 · 기존 기능과의 연결
- 기존: 코드 기반 비공개 합주 — `sessions(code)`/`tracks(events)`, 클라 `share.ts`(createSession/getSession/addTrack), 1.5s polling, 실패 시 프리로드 폴백.
- 게시판 = 이 모델을 공개 목록으로 확장한다.
- 연결점(반드시 정의):
  - 스튜디오 녹음 → 게시판 공개(신규 공개 플래그/엔드포인트).
  - 게시판 곡 → 받기·얹기(기존 `getSession`/`addTrack` 재사용 — 신규 최소화).
  - 익명키(getAnonymousKey) = 작성자(owner) + 좋아요 주체(중복 방지 키).

## 2. 화면별 명세
### SCR-C01 커뮤니티 피드
- 목적: 공개된 음원을 탐색·정렬·진입.
- 요소: 정렬 탭 [최신 | 인기], 곡 카드(제목·작성자 닉·길이(초/마디)·❤️수·▶듣기), limit/무한스크롤.
- 상태: 정상 / 로딩 / 빈("첫 곡을 올려보세요") / 오류(재시도) / 실시간 갱신(신곡·좋아요수).
- 연결: 카드 탭 → C02.
### SCR-C02 음원 상세·듣기
- 목적: 재생 + 반응 + 내 스튜디오로 가져오기.
- 요소: 재생/정지, 트랙 구성(작성자·음색), ❤️좋아요(토글·중복방지), "내 스튜디오로 얹기"(기존 받기/오버더빙 재사용), 신고(⋯).
- 상태: 정상 / 로딩 / 재생오류 / 이미 좋아요.
- 연결: 얹기 → 스튜디오(기존 `addTrack` 플로우).
### SCR-C03 공개하기(업로드)
- 목적: 스튜디오에서 만든 곡을 게시판에 공개.
- 요소: 제목 입력, (음색·길이 미리보기), 공개 버튼. 5개 초과 시 차단/교체 안내.
- 상태: 작성중 / 업로드중 / 실패 / 5개 초과.
- 연결: 스튜디오 "공유" → 여기, 성공 → C01/C04.
### SCR-C04 내 음원
- 목적: 내가 공개한 음원(최대 5) 관리.
- 요소: 내 곡 리스트(좋아요수), 공개취소/삭제, 5/5 표시.
- 상태: 빈 / 5개 도달.

## 3. 데이터 · 규칙
- 정렬: 최신(created_at desc) / 인기(좋아요수 desc).
- 5개 제한: 익명키당 공개 음원 ≤ 5(초과 시 차단 또는 최古 교체 — 미해소).
- 좋아요: 익명키 기준 1회(중복 방지).
- 인기 산정: 좋아요수(재생수 포함 여부 미해소).

## 4. 정책 체크 (UGC/소셜)
- 공개 UGC 게시판이면 앱인토스 소셜/커뮤니티 분류에 걸릴 수 있어 분류 재검토가 필요하다. 현 정책문서는 "코드 기반 비공개·불특정 연결 없음"(POL-03) 기준이다.
- 신고 최소 1개(콘텐츠 신고) 권장. 차단/모더레이션 범위는 미해소.
- 완화 논거: 공유 단위가 사람-사람 만남이 아니라 연주 음원이고, 불특정 인물 매칭·위치·채팅이 없다.

## 5. 미해소 핵심 쟁점
2026-06-22 회의에서 커뮤니티+음원게시판을 정밀 합의하려고 4-AI 토론(DEBATE-20260622-012)을 준비했다. 프롬프트 팩은 [토론_프롬프트팩_커뮤니티_음원게시판.md](../09_AI개발파이프라인/토론_프롬프트팩_커뮤니티_음원게시판.md)에 있으나 토론은 진행·기록되지 않았다(`토론기록/DEBATE-20260622-012_…`·예정 DL 모두 미생성). 같은 날 DL-022로 곽소정 원안 풀버전 복귀가 결정되면서 커뮤니티 게시판은 D-4 범위에서 빠졌고, 별도 토론은 불필요해졌다. 따라서 DEBATE-20260622-012는 결번이며, 이 영역의 방향은 DL-022가 대체한다. 아래 쟁점은 게시판을 다시 범위에 넣을 때 결정한다.

1. "음원" 정의 — 이벤트 JSON(현행) / 오디오 파일 / 하이브리드?
2. 데이터·엔드포인트 모델 — 기존 sessions·tracks 확장 vs 신규 테이블(posts·likes).
3. 실시간 — WebSocket vs polling(현행 1.5s).
4. 정책 — 분류·신고·공개범위.
5. 연결 — 기존 합주(얹기)·식별(익명키)·스튜디오 공개 동선.
6. 규칙 — 5개 제한·인기 산정·정렬.

라운드1에서 정리한 Claude 입장(이벤트 JSON 유지·기존 모델 확장·polling 재사용·신고 1개·기존 얹기 재사용)은 프롬프트 팩에 남아 있다. 재개 시 출발점으로 쓴다.

## 7. as-built 화면 (구현됨, 2026-06-23 · `Community.tsx` 기준)

원안의 4화면 피드 대신 **단일 보드 화면 + 펼침 패널**로 구현됐다. SCR 매핑: 원안 SCR-C01·C02·C03·C04 → as-built **SCR-CM(단일 커뮤니티 보드)** 1화면에 통합.

### 7.1 레이아웃
- **앱바:** `‹ 스튜디오` · `커뮤니티`(타이틀) · `↻ 새로고침` · `＋올리기`.
- **안내 카피:** "마음에 드는 음원을 담아… 들어보고 좋아요·한마디 코멘트도!"
- **카드 목록(`listCommunity`):** 카드마다 이모지 아바타 · `음원명 – 작성자` · `트랙 N · ▶ 재생수 · 이어 파생수` · (파생이면) 보라색 출처 `🎵 소스: A님의 「곡명」 음원 사용` · 버튼행 `[들어보기][담기][❤ 좋아요수][💬 댓글수]`.
- **하단 가져오기 바:** 담은 항목 ≥1일 때 `🎚 가져오기 (N개) → 스튜디오에 얹기`.
- **토스트:** 작업 피드백("보드에 올라갔어요", "같은 곡이 이미 보드에 있어요" 등).

### 7.2 재생 바(트랜스포트) — FB1
- `들어보기 ▶` → 카드 하단에 재생 바 표시. 버튼이 `❚❚ 일시정지`/`▶ 재생`으로 토글(위치 유지).
- 진행 바의 흰 동그라미를 **드래그(스크럽)**해 원하는 구간부터 재생. `0:08 / 0:15` 시간 표시.
- 한 번에 한 카드만 재생(다른 카드 재생 시 기존 정지). 트랙별 음색 복원, 곡 중간 재생 시 sustain 코드 보정.

### 7.3 올리기 시트(＋올리기)
- 내 곡 목록(`listSongs`) → `올리기`. 같은 곡(작성자+첫 트랙 동일) 재게시는 **중복 방지** — "같은 곡이 이미 보드에 있어요"(새로 안 만듦). 빈 곡 차단.

### 7.4 댓글 패널(💬)
- 평면 댓글(≤200자) 목록(작성자·텍스트)·입력("한마디 남기기")·보내기.
- **신고:** 누르면 `신고됨`으로 바뀌고 조용히 접수(즉시 안 사라짐). 서로 다른 이용자 3명 누적 시 자동 숨김.

### 7.5 상태
- 로딩("불러오는 중…") / 빈("아직 음원이 없어요 — 첫 곡의 주인공") / 실패("불러오지 못했어요 · 다시 시도") / 시드곡 콜드스타트.

### 7.6 동작 요약(FB1~6, 리허설 반영)
| 항목 | 동작 |
|---|---|
| 재생 바(FB1) | play/pause·스크럽·sustain 보정 |
| 중복 방지(FB2) | origin 없는 원곡 재게시 멱등(첫 트랙 해시) |
| 좋아요(FB4) | 서버 reactions, 다른 사람에게 교차 반영 |
| 신고(FB5/FB6) | 조용히 접수("신고됨"), distinct N명 누적 자동 숨김 |

> 신고 키 회전 검열 벡터는 IP 식별 전환으로 해소(72cdfbf). 남은 정책 게이트: shadow moderation 투명성·dedup 시간창 → [DECISION-20260623-001](../09_AI개발파이프라인/결정요청서/DECISION-20260623-001_커뮤니티_모더레이션_중복정책.md).

### 7.7 정렬·페이징·아이콘 (TASK-20260624-040, 2026-06-24)
- **정렬 토글:** `최신순`(서버 `created_at` desc 기본) / `인기순`(**하트(좋아요) 수** desc). 클라 정렬이라 목록 즉시 반영, 동률은 안정 정렬로 최신 순서 유지. 새 컬럼/테이블 없음(reactions 집계 재사용) → [테이블 정의서](../04_시스템설계/테이블_정의서.md) 무변경.
- **반응형 페이징:** 음원 목록은 페이지당 개수를 화면 높이에서 **동적 산출**(개수 하드코딩 없음, 리사이즈·회전 재계산·현재 페이지 자동 보정) + `‹ 이전 / n·총 / 다음 ›` 페이저. 댓글은 동적 개수만큼 먼저 노출하고 `댓글 N개 더 보기`로 증분.
- **아이콘 버튼:** `들어보기/담기`를 텍스트 → 아이콘(▶·❚❚ / ＋·✓)으로 통일(좋아요·댓글 칩과 일관). 의미는 `aria-label`·`title`로 보존.
