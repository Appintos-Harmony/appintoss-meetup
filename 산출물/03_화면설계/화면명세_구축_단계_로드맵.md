# 화면 명세서 구축 · 단계 로드맵

## 1. 단계 리스트 (Phase)

> 표기: PASS 완료 / ⏳ 진행가능(본 세션 산출) / 소유자·게이트 대기. 각 단계는 **담당(소유)·산출물·완료조건·게이트**를 가진다.

### 단계 0 · 기존 체계 확정
- **담당:** 곽소정(인덱스)·이상혁. **완료조건:** 인덱스 + 상세 4 존재(Draft). **상태:** 완료(a2d97ea 인덱스 추가).

### 단계 1 · as-built 갭분석 ⏳(본 세션 완료)
- **담당:** 김민혁(reviewer) + 화면명세 아키텍트 페르소나. **산출물:** [화면명세_구현대조_갭분석.md](화면명세_구현대조_갭분석.md)(화면 7개 × 갭/§12상태/제안패치 + 적대적 검증). **완료조건:** 모든 갭 `파일:줄` 근거 + 적대적 검증 통과(날조 0). **상태:** 완료.

### 단계 2 · SCR-ID 4출처 정합 결정 ★선행
- **담당:** 이상혁(제품정책) 결정 + 곽소정(인덱스). **입력:** 갭분석 §1(코드·인덱스·§A-1·추적표 4출처 불일치; SCR-HOME·SCR-SET는 인덱스 단독 발명). **결정:** ⓐ 정식 채택해 §A-1·추적표에 역전파 / ⓑ 인덱스에서 "라우트만, SCR 미부여"로 하향. **완료조건:** 4출처가 한 규약으로 일치. **게이트:** 이상혁 결정(Open Question 1). *이후 단계 3·6·7의 ID 표기가 여기에 종속되므로 먼저.*

### 단계 3 · 누락 화면 명세 신설 (제안 패치 통합)
- **담당:** 이상혁(본문 소유) + 김민혁 제안 패치. **대상:** 스플래시(§4-A)·**SCR-HOME 디스패처 허브(§4-C, [H1])**·SCR-SET 개발자모드(§4-F)·SCR-APP 앱 셸(§4-G). **산출물:** 하모니_화면명세서.md §A에 각 절 신설(또는 인덱스 정합). **완료조건:** 각 화면 §12 6상태 판정 가능. **게이트:** 이상혁 통합 승인.

### 단계 4 · 스튜디오 공통계약 동기화
- **담당:** 곽소정(스튜디오 명세 소유) + 김민혁 제안 패치(§4-D). **대상:** DrumPiece 4→8·`'hat'`→`'hihat'`([H2]) / TrackMeta `owner` 추가·`style:string`([M3]) / 셸 UI 세그먼트→칩+바텀시트 / 피아노 옥타브 1→2 / 미구현 토스트 표기. **완료조건:** §397-419 공통계약 코드블록이 events.ts와 일치. **게이트:** 곽소정 통합.

### 단계 5 · §12 오류·권한 상태 재판정 ★결정필요
- **담당:** 곽소정/이상혁. **입력:** [H3], SCR-ST-00 오디오 오류/권한이 명세는 '구현'인데 ensureAudio(Studio.tsx:311-317) try/catch 없음. **결정:** ⓐ 코드 구현(try/catch+토스트+롤백) → 구현 백로그 / ⓑ 명세를 '미구현'으로 하향. **주의:** 6/24 구조변경 금지 게이트와 충돌 검토. **게이트:** 이상혁/곽소정(Open Question 2).

### 단계 6 · 커뮤니티 라우트 ↔ SCR 매핑 명시
- **담당:** 이상혁/곽소정(인덱스). **대상:** [H4] · 인덱스 커뮤니티 행에 "현 도달=SCR-ST-06 스캐폴드 / SCR-C01~04=미구현 게시판" 2줄 분리(§4-E). 뒤로가기 홈진입 복귀·미리듣기 음색은 Open Q. **완료조건:** 라우트 community의 as-built 화면을 가리키는 SCR-ID가 인덱스에 존재.

### 단계 7 · FR 추적표 ↔ SCR-ID 정합
- **담당:** 이상혁/양록빈(QA). **대상:** [M4] · 요구사항_추적표.md의 SCR 표기를 단계 2 결정 ID로 통일. **완료조건:** FR-### ↔ SCR-### 양방향 추적 일관.

### 단계 8 · 부가 점검 (Figma·CTA·접근성)
- **담당:** 곽소정(UI). **대상:** Figma ↔ 화면설계서 ↔ 라우트 3자 일치(§12), CTA 예측성 화면별 점검, 접근성(`prefers-reduced-motion` 부재 · 스플래시/모션 가드), 식별키 심볼 표기 통일([L1]).

### 단계 9 · 검토 → 승인 → 인덱스 동기화
- **담당:** reviewers(곽소정/이상혁/양록빈) + 조장 승인. **완료조건:** 단계 2~8 반영 → 상세 4 + 갭분석 status `In Review` → `Approved`, 인덱스 화면 구성표 최신화. **게이트:** 조장 승인 + (코드 변경 동반 시) `검증_전체 --strict` + 독립검토서.

## 2. 의존성·순서

```
단계0 ✅ ─ 단계1 ⏳ ─ 단계2(ID결정) ─┬─ 단계3(누락 화면)
                                      ├─ 단계6(커뮤니티 매핑)
                                      └─ 단계7(FR 추적)
              단계4(스튜디오 계약) ── 병렬 가능(ID 비종속)
              단계5(오류상태 결정) ── 병렬 가능(코드 결정 포함)
   단계3~7 ─ 단계8(부가점검) ─ 단계9(검토→승인)
```
- **단계 2가 3·6·7의 선행**(ID 표기 종속). 단계 4·5는 ID와 무관해 병렬 착수 가능.
- 단계 5·7(P-4 구현/QA)에 코드 변경이 들어가면 **구현→로컬테스트→푸시→독립검토** 게이트 적용(tsc/vitest는 필요조건일 뿐).

## 4. 본 세션 범위 vs 후속

- **본 세션(김민혁 reviewer, 완료):** 단계 1 · 페르소나 제작 + 화면 7개 갭분석 + §12 상태 매트릭스 + 제안 패치 §4-A~G + 본 로드맵. **별도 산출물**로만 작성(소유 문서 미수정).
- **후속(소유자/조장 게이트):** 단계 2~9. 명세 본문 통합·코드 정정(P-4 등)·검토·승인은 소유자(곽소정/이상혁)와 조장 권한. 코드 변경 동반 시 절차 게이트(테스트·독립검토·푸시 승인) 적용.
