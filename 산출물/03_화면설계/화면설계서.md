# 화면 설계서

> 기준: PRD(`5888cbf`)·[서비스_기능정의서](../01_서비스기획/서비스_기능정의서.md). 트랙 **초대 코드형**, 인증 **익명키(getAnonymousKey, DL-016)**. 화면 ID=`SCR-###`로 라우트·Figma·[요구사항_추적표](../01_서비스기획/요구사항_추적표.md)와 일치시킨다(§10·§12). Figma 실제 작성·TDS 매핑은 곽소정(피그마_디자인인계서). 현재 프로토타입 `apps/miniapp`이 본 정의서를 따른다(UI 재구현은 본 정의서 기준).

## 1. 디자인 원칙 (§12 · NFR-004)
- 컬러: **Toss 블루 `#3182F6` · 흰 · 회**. 강조 1색, 위험은 빨강.
- 아이콘 중심, 한 화면 **핵심 메시지 ≤ 3줄**, 큰 터치 영역(≥44px), 명도 대비·스크린리더 라벨(NFR-004).
- **토스 공통 내비게이션 바·뒤로가기 사용** → 자체 뒤로가기 UI를 중복 제작하지 않는다.
- 사용자는 **CTA 문구만 보고 다음 행동을 예측**할 수 있어야 한다.
- 정밀 위치 미표시(POL-003): 목록·상세는 "넓은 지역"만, 정확한 집결지는 승인자에게만 별도 안내.
- 모든 핵심 화면에 상태 설계: 정상 · 로딩 · 빈 · 오류 · 네트워크 지연 · 권한/접근 불가 · 모집 마감 · 승인 대기 · 거절 · 모임 취소 · 데이터 없음.

## 2. 공통 요소
- **헤더**: 앱명(탭 시 홈) + 닉네임. (전역)
- **버튼**: Primary(파랑·꽉찬 폭) / Ghost(외곽선) / Small(승인·거절). disabled 시 흐림.
- **배지**: 모임 상태(모집중·마감·취소) / 참가 상태(대기·확정·거절·취소).
- **카드·리스트·입력(label+input)·텍스트영역**.
- **공통 패턴**: 로딩("불러오는 중…") · 빈 상태(안내+행동 유도) · 오류(메시지+재시도).
- **앱인토스 제공**: 공통 내비게이션 바·고객센터(콘솔 설정). TDS 컴포넌트 매핑은 인계서에서 확정(예정).

## 4. 화면별 상세

### SCR-001 진입·닉네임 온보딩 (FR-001, FR-002)
- 목적: 익명 식별자 발급 + 최초 1회 닉네임 등록(가입·로그인 없음).
- 진입: 미니앱 최초 진입. 재방문 시 닉네임 있으면 건너뜀(→ SCR-002).
- 구성: 앱명·한 줄 소개, 닉네임 입력, [시작하기].
- 상태: 정상(입력) / 로딩(식별자 발급 중) / 오류(식별 실패→안내) / 빈(닉네임 미입력 시 버튼 disabled).
- CTA: "시작하기"(닉네임 필수). 약관·안전 규칙 동의 포함.
- 예외/검증: 닉네임 공백 차단. 식별키 미지원(SDK<2.4.5) 안내.

### SCR-002 홈 — 내 모임 + 초대코드 입장 (FR-014, FR-004)
- 목적: 내가 만든·신청한 모임만 보기 + 초대코드로 새 모임 진입. **공개 추천·탐색 없음**.
- 진입: 온보딩 후 기본 화면.
- 구성: [+ 모임 만들기], 초대코드 입력+[입장], "내 모임" 리스트(제목·일시·넓은 지역·남은자리·상태 배지).
- 상태: 정상 / 빈("아직 모임이 없어요…") / 오류 코드(없는 코드 안내) / 로딩.
- CTA: "모임 만들기"→SCR-003, "입장"→SCR-004(코드 유효 시), 항목 탭→SCR-004/005.
- 예외/검증: 무효·만료 코드 거부 메시지. 대소문자 무시.

### SCR-003 모임 생성 (FR-003)
- 목적: 모임 개설(+안전 규칙을 기능으로 입력).
- 진입: 홈 [+ 모임 만들기].
- 구성: 제목·일시(datetime)·넓은 지역·정원·준비물·**안전 규칙(여러 줄, 필수)**·[모임 만들기]·[뒤로].
- 상태: 정상 / 검증 오류(필수 누락·과거 일시·정원≤0·안전규칙 0 → 인라인 메시지) / 로딩(생성 중).
- CTA: "모임 만들기"→생성 후 SCR-004(주최자는 SCR-005 뷰).
- 예외/검증: 과거 일시 차단, 정원 1+ 정수, 안전 규칙 1+ 필수(§14). 정확한 주소는 적지 않도록 안내(POL-003).

### SCR-004 모임 상세 — 참가자 뷰 (FR-004, FR-005, FR-007)
- 목적: 모임 정보·안전 규칙 확인 후 신청/상태 확인/취소.
- 진입: 홈 항목 탭 또는 초대코드 입장.
- 구성: 제목·상태 배지·일시·넓은 지역·남은자리·준비물, **초대 코드(공유용)**, 안전 규칙 목록, 내 신청 상태/액션.
- 상태: 정상 / 신청 전(참가 신청 버튼) / 승인 대기 / 참가 확정 / 거절 / 모집 마감(신청 불가) / 모임 취소 / 데이터 없음(모임 없음).
- CTA: "참가 신청(닉네임)"→대기, "신청 취소"→취소(정원 복구).
- 예외/검증: 중복 신청 차단, 마감/취소 시 신청 버튼 비활성+사유 표기.

### SCR-005 모임 상세 — 주최자 관리 뷰 (FR-006, FR-009)
- 목적: 신청자 승인/거절, 모집 마감·모임 취소.
- 진입: 주최자가 자기 모임 상세 진입(동일 라우트, host 분기).
- 구성: SCR-004 정보 + **신청자 목록**(닉네임·상태·[승인][거절]) + [모집 마감][모임 취소].
- 상태: 정상 / 신청자 없음(빈) / 정원 도달(승인 시 차단 안내) / 마감 / 취소 / 권한 없음(비주최자는 SCR-004로).
- CTA: "승인"(정원 내), "거절", "모집 마감", "모임 취소"(참가자 상태 일관 갱신·통지).
- 예외/검증: 주최자만(권한), 정원 초과 승인 차단(CAPACITY_EXCEEDED), 대기 상태만 승인/거절.

### SCR-006 공지 (FR-008) — 후속
- 목적: 주최자가 공지 작성→참가자 노출. 상세 내 섹션/모달. 미구현(후속 TASK).

### SCR-007 신고 (FR-011) — 후속
- 목적: 사용자·모임·콘텐츠 신고 접수. 진입: 상세 더보기. 미구현.

### SCR-008 최소 운영자 (FR-012) — 후속
- 목적: 신고 큐·비노출·처리 기록(감사 로그). 권한 분리. 미구현.

### SCR-009 내 정보·탈퇴/삭제 (FR-002, FR-013) — 후속
- 목적: 닉네임 수정, 계정 탈퇴·데이터 삭제 요청(접근 불가 처리). 미구현.

## 5. 네비게이션 맵
```
SCR-001 온보딩 ──▶ SCR-002 홈
                     │  ├─[+만들기]──▶ SCR-003 생성 ──▶ SCR-004/005 상세
                     │  ├─[초대코드 입장]──▶ SCR-004 상세(참가자)
                     │  └─[내 모임 탭]──▶ SCR-004(참가자) / SCR-005(주최자)
SCR-004/005 ──[뒤로(토스 네비)]──▶ SCR-002
(후속) 상세 ─▶ SCR-006 공지 / SCR-007 신고,  SCR-002 ─▶ SCR-009 내정보,  운영자 ─▶ SCR-008
```

## 7. 추적성 · Figma
- SCR↔FR는 [요구사항_추적표](../01_서비스기획/요구사항_추적표.md)를 단일 기준으로 갱신한다(본 TASK에서 `화면` 칸 채움).
- Figma 페이지(00 Cover ~ 10 Design QA, §12)·TDS 매핑·고해상 시안은 곽소정 **피그마_디자인인계서**(별도 산출물, 추후 작성)에서 확정.
- 미구현(SCR-006~009)은 후속 TASK에서 본 정의서를 확장한다.
