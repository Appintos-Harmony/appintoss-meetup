# 하모니 화면명세서 (v0.1 초안)

> 설계 원안: **곽소정**(Miniapp & Design Lead). 기술 검증: 코드 연주 카메라 제스처가 토스 WebView 실기기에서 작동 확인됨(커밋 50f57b6, DL-018 ⓑ). 본 문서는 4-AI 설계 회의 입력용 초안이며, 회의 후 v1로 확정한다.

## 0. 제품 한 줄
토스 안에서 **악기를 연주하고, 친구가 만든 트랙 위에 내 악기를 얹어** 한 곡을 완성하는 미니앱.

## 1. 디자인 원칙 (토스 감성)
- **명료·절제:** 한 화면 한 목적. 장식 최소, 정보 위계 뚜렷.
- **큰 터치 타깃:** 악기·코드 버튼 ≥ 56px, 간격 ≥ 12px. 한 손 조작 고려.
- **단일 강조색:** 토스 블루 `#3182f6`(+pressed `#1b64da`). 배경 메뉴=라이트(`#f2f4f6`/흰색), **연주 화면=다크 무대**(소리·손·악기에 몰입, 강조색 글로우).
- **타이포:** Pretendard. 제목 24/700, 본문 15/400, 캡션 13/400.
- **모션:** 진입 fadeUp 200ms, 탭 피드백 80ms + 햅틱. 과한 애니메이션 금지.
- **플랫폼:** TDS(`@toss-design-system/mobile`) 정렬. **자체 뒤로가기 UI 금지**(토스 공통 사용), 핀치줌 비활성(viewport 메타).

## 2. 무드/톤
| 영역 | 톤 | 이유 |
|---|---|---|
| 메뉴(악기·코드·공유·메트로놈) | 라이트·깔끔(토스 기본) | 빠른 선택, 친근 |
| 연주(코드·멜로디) | **다크 무대 + 강조색 글로우** | 카메라/건반/소리 몰입, 손 랜드마크 가시성 |

## 3. 화면 목록 (SCR)
| ID | 화면 | 핵심 |
|---|---|---|
| SCR-01 | 악기 선택 | 피아노·드럼·기타·베이스 |
| SCR-02 | 코드 선택 | C~B ×(／m／7／m7) 중 4~6개 |
| SCR-03 | 연주법 선택 | 코드 연주 / 멜로디 연주 |
| SCR-04 | 코드 연주 | 4분할 존 + **카메라 제스처** + 녹음 |
| SCR-05 | 멜로디 연주 | 피아노 건반 / 기타·베이스 지판(**터치**) |
| SCR-06 | 녹음·합주 트레이 | 메트로놈·악기추가·음원추가·저장/공유 |
| SCR-07 | 공유·음원 추가 | 목록(제목·제작자·길이·들어보기) |
| SCR-08 | 메트로놈 | 박자·BPM |

## 4. 화면별 명세

### SCR-01 악기 선택
- 구성: 2×2 카드(피아노/드럼/기타/베이스), 큰 일러스트 아이콘 + 이름.
- 상호작용: 탭 → 코드 선택(SCR-02). (드럼은 코드/멜로디 대신 패드로 분기 — *회의 안건*)
- 상태: 정상 / (식별 로딩) / 비활성(준비중 악기).

### SCR-02 코드 선택 (4~6개)
- 구성: 코드 매트릭스 — 행=루트(C·D·E·F·G·A·B), 열=종류(／m／7／m7). 선택 시 칩 하이라이트 + 상단 **선택 카운터(예: 3/6)**.
- 규칙: 최소 4, 최대 6. 선택한 코드가 SCR-04의 연주 존이 됨.
- 상호작용: 4개 미만이면 "다음" 비활성. 완료 → 연주법 선택(SCR-03).
- 상태: 정상 / 4개 미만(안내) / 6개 초과 시도(토스트).

### SCR-03 연주법 선택
- 구성: 큰 선택 카드 2개 — **코드 연주**(반주, 카메라 제스처) / **멜로디 연주**(터치).
- 카피: CTA만 보고 다음 행동 예측 가능하게("코드로 반주하기" / "음 하나씩 연주하기").

### SCR-04 코드 연주 ★ (검증된 핵심)
- 구성: 화면 **4분할 존**(선택한 코드, 예 G·D·C·Em) + 카메라 프리뷰(다크) + 손 랜드마크 오버레이.
- 입력: **카메라 제스처** — 손 위치=코드 존, **편 손=지속음, 주먹=멈춤**. (존이 넓어 의도치 않은 오발 적음)
- 하단 **녹음 바**: ● 녹음 / ▶ 다시 듣기(=원안 "돌아보기", 내 녹음 재생) / ⏸ 일시정지 / ⏹ 정지 + 실시간 파형 + "녹음 중" 표시.
- 트레이(SCR-06)로 연결: 메트로놈·악기 추가·다른 사람 음원 추가·저장/공유.
- 상태: 정상 / **카메라 권한 요청·거부** / 손 미인식(안내) / 녹음 중 / 저성능(FPS 낮음 경고) / 오류.

### SCR-05 멜로디 연주 (터치)
- 피아노: 가로 스크롤 건반(흰/검은 건반), 1~2 옥타브. 다크 배경.
- 기타/베이스: **지판(프렛 그리드)** — 가로=현(기타 6/베이스 4), 세로=프렛. 칸=프렛, **계이름 표기 옵션**.
- 입력: **터치**(정밀). *원안 메모(곽소정): 멜로디를 모션으로 하면 손이 지나가며 인접음을 의도치 않게 트리거 → **터치 채택**.*
- 녹음 바·트레이 동일.
- 상태: 정상 / 스크롤 힌트 / 녹음 중 / 오류.

### SCR-06 녹음·합주 트레이 (공통)
- 진입: 연주 화면 하단 칩 — **매트로놈 / 악기 추가 / 다른 사람 음원 추가 / 녹음본 저장·공유**.
- 합주 모델: **비동기 레이어** — 내 트랙 녹음 → 저장/공유 → 다른 사람이 그 위에 얹음. 공유 기준 클럭=메트로놈.
- 상태: 트랙 0~N(레이어 목록), 재생/뮤트/삭제(트랙별).

### SCR-07 공유·음원 추가
- 구성: 리스트 — **제목 · 제작자 · 음 길이 · 들어보기(▶)**. (들어보기 강조)
- 상호작용: 들어보기=미리듣기, "내 곡에 추가"=레이어로 가져오기.
- 상태: 정상 / 빈 목록 / 로딩 / 재생 중.

### SCR-08 메트로놈
- 구성: **박자 설정**(콤보: 4/4·3/4·6/8) + **BPM 설정**(숫자 up/down, **기본값 100**) + 시작/정지 + 박 시각 표시.
- 상태: 정지 / 재생(비트 플래시) .

## 5. 상호작용 모델 요약
- **코드 연주 = 카메라 제스처**(넓은 존 → 오발 적음) / **멜로디 = 터치**(정밀, 인접음 오발 방지).
- **녹음 = 이벤트 기반**(음/시각 데이터), 마이크 불필요.
- **합주 = 비동기 "얹기"**(녹음→공유→레이어), 실시간 오디오 스트리밍 없음.

## 6. 컴포넌트/토큰
- 재사용: `theme.css` 토큰 + `ui.tsx`(Screen/AppBar/Card/Button/Badge/Field/Empty).
- 신규 제안: `ChordPad`(4분할), `InstrumentCard`, `ChordMatrix`, `PianoKeyboard`, `Fretboard`, `RecordBar`, `TrackLayer`, `ShareRow`, `Metronome`.

## 7. 페이지 아키텍처 (웹/앱 반응형) · 인증
**우리 산출물 = 토스 미니앱(모바일 WebView) 1개.** "웹/앱" 구분은 별도 제품이 아니라 **반응형 동작**으로 처리(별도 웹 제품은 해커톤 범위 밖 권장).
- **넓은 화면(웹/태블릿):** 연주 페이지에서 코드 선택·연주법·하단 기능(녹음·메트로놈 등)을 **옆/아래 인라인 패널**로.
- **모바일(미니앱 기본):** 같은 서브 기능을 **풀페이지 이동**으로(작은 화면 가독·터치).
- 한 코드베이스, 화면폭에 따라 패널 ↔ 페이지 전환.

**인증 (정책·중요):** ⚠️ **자체 로그인/회원가입은 토스 미니앱에서 금지**(토스 로그인만 허용·비사업자 불가, DL-016). → **getAnonymousKey 익명 식별 + 닉네임 온보딩 1회**로 "가입 같은" 경험. 자체 회원가입 페이지 = 심사 반려 위험.

**추가 페이지(원안 + 보강):** 스플래시/온보딩(닉네임) · 내 곡(저장된 녹음) · 설정 · **문의하기**(원안) · 약관·개인정보(필수 고지) · (합주 공개 시 신고).

## 8. 미해결 / 회의 안건
- ⚠️ **로그인/회원가입(원안)**: 미니앱 자체 로그인 금지 → getAnonymousKey+닉네임 대체 제안. (별도 웹 제품이면 가능하나 범위 밖) — 회의 확정.
- **웹 별도 제품** 범위 여부(해커톤은 미니앱 집중 권장).
- 드럼 연주 방식(패드 그리드? 코드/멜로디 분기 없음?).
- 멜로디 음역 범위(피아노 옥타브 수, 지판 프렛 수).
- 합주 트랙 수 상한, 공유 저장 백엔드(스토리지) 범위.
- 5분 데모 동선(어느 화면을 시연 메인으로).
- 접근성(색약·소리 없는 환경 대응).
