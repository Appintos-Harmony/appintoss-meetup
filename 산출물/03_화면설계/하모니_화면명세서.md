## A. 정본 — MVP v1

근거: 4-AI 설계 회의 [DEBATE-20260621-011](../09_AI개발파이프라인/토론기록/DEBATE-20260621-011_하모니설계회의.md) / TASK-027. 폐기 처리는 Codex REVIEW-028 H28-002 반영.

- **MVP 한 문장:** 친구가 공유한 4마디 트랙을 토스에서 열고, 네 개의 손 제스처로 코드 한 레이어를 녹음해 다시 공유한다.
- **테마:** 100% 라이트. 전면 다크는 비게임 심사 위험이라 폐기했다. 다크 패널을 라이트 셸 안에 넣는 theme-in-theme도 금지(라운드3에서 손 랜드마크 가시성 문제를 가시성 처리로 대체). 풀 다크모드 토글은 검수 후 후속, 기본 제출은 라이트.

### P0 — 남길 것
라이트 `partner` 셸·TDS 내비 / SCR-00 온보딩(닉네임 + getAnonymousKey) / 피아노 1음색 / 고정 4코드(C·Am·F·G) / 손 제스처 4영역 / 4/4·BPM100 / 1마디 카운트인 / 4마디 이하 이벤트 녹음 / 친구 기본트랙 + 내 오버더빙 1레이어 / 재생·뮤트·삭제 / 로컬 저장 + 재진입 복구 / 이벤트 JSON 업로드 + 비공개 공유 링크 / 카메라 거부·네트워크 실패·미저장 이탈 처리.

### 범위 밖 — 컷
드럼 · 기타/베이스 지판 · 공개 공유 피드 · 3/4·6/8 · 웹 반응형 패널 · 별도 설정/문의/메트로놈 페이지 · 자체 회원가입 · 외부 오디오 업로드.

### 킬러 데모 루프
친구 4마디 트랙 열기 → 제스처 4코드 → 1마디 카운트인 녹음 → 두 트랙 동시 재생 → 뮤트로 전후 차이 → 재공유 링크.

### 필수 상태
식별키 로딩/로컬전용 · 카메라 미요청·거부(OS·앱)·손 0개·다수 손·저신뢰 · 녹음 빈결과·백그라운드 전환 · 미저장 이탈(토스 뒤로가기 + TDS 모달) · 공유 업로드 실패·받은곡 삭제·버전 불일치 · AudioContext 잠금.

### 이벤트 계약
tick 기반 `Session{bpm,meter,bars,chordSlots}` · `Event{tick,dur,type,value}` · `Track`. 벽시계 ms는 쓰지 않는다(기기 간 정렬 오차).

### 용어
"녹음" = 연주 기록으로 통일. 인증 문구는 "닉네임 정하기"(로그인·가입 아님).

### 일정
DL-018 주제는 Proposed 유지 — 팀 확정 전 구현 확대 금지.

### 라운드3 확정 (DL-019 — P0보다 우선)
- **라우트 3개 + 온보딩:** 온보딩(닉네임·getAnonymousKey) → 즉시 어쿠스틱 피아노 스튜디오(첫 소리 1초) / 홈(최근 곡 1~3 + 합주 받기, 보관함 흡수) / 스튜디오(연주·녹음·트랙·메트로놈·음색 = 한 화면 + 바텀시트) / 설정(최소, 고객센터 = 토스 공통).
- **입력:** 제스처 기본 + 동일 4코드존 터치 폴백(카메라 거부·저성능·손 미인식 시 데모 지속용). 상단 세그먼트 컨트롤 [👋 제스처로 반주 | 👆 터치로 멜로디] + 물리 이동(제스처 = 중앙 카드 + 카메라 PIP / 터치 = 하단 건반).
- **음색(밴드감):** 스튜디오 하단 칩 → 바텀시트(어쿠스틱/일렉/신스베이스). UI 1개·샘플러 맵 교체. 트랙 = 토스 프로필 얼굴 + 시그니처 컬러 + bounce 모션.
- **합주 받기:** 클립보드 자동 인식 → 바텀시트("○○님 트랙을 복사했어요. 얹을까요?") → [내 연주에 얹기]. 코드 타이핑·QR 없음.
- **백엔드(AWS Ubuntu 26.04 · 조건부):** Node + SQLite, `POST /sessions` · `GET /sessions/:code` · `POST /sessions/:code/tracks`, 2장비 = 1.5초 polling(실시간 아님). 프리로드 = 장애 백업.
- **녹음 reducer(중복 방지):** activeChord 변경만 기록 — 같으면 noteOn 중복 금지 / null 전환 시만 noteOff / touch 중 gesture 무시 / touch 종료 200ms 후 gesture 재개.
- **테마:** 100% 라이트(다크 패널 없음 — theme-in-theme 금지). 흑건 `#333D4B` · TDS elevation 그림자(OP-1풍 촉각감).
- **추가 제외:** WebSocket 실시간 · 계정/권한 · 오디오 파일 업로드 · 운영자 · 보관함 · `intoss://` 공유(출시 후).
- **AI 25점 증명:** 제스처 자체가 아니라 인식 안정화·테스트·사람 승인 로그(라운드1~3 토론)로.

### A-1. 화면 목록 (라이트 3라우트)
| 라우트 | 화면 | 핵심 |
|---|---|---|
| SCR-00 | 온보딩 | 닉네임 정하기 + getAnonymousKey |
| 홈 | 홈 | 최근 곡 1~3 + 합주 받기(보관함 흡수) |
| 스튜디오 | 연주·녹음 | 코드 4존(제스처/터치) + 카메라 PIP + 녹음 바 + 트랙 레이어 + 메트로놈·음색 바텀시트 |
| 설정 | 설정 | 최소(법적정보, 고객센터 = 토스 공통) |

### A-2. 입력 모델
- 코드 연주 = 카메라 제스처(넓은 4존 → 오발 적음). 손 위치 = 코드 존, 편 손 = 지속음, 주먹 = 멈춤.
- 멜로디·폴백 = 터치(정밀, 인접음 오발 방지). 카메라 정상이면 제스처, 실패하면 터치로 자동 전환.
- 녹음 = 이벤트 기반(음·시각 데이터), 마이크 불필요.
- 합주 = 비동기 "얹기"(녹음 → 공유 → 레이어), 실시간 오디오 스트리밍 없음. 공유 기준 클럭 = 메트로놈.

## B. 빌드 실행 컷라인·Phase (정본, Codex REVIEW-028 반영)

스파이크는 기술검증용이다 — 제품으로 직접 빌드하지 않고 로직만 이식한다. 빌드 대상은 MVP 앱(라이트 셸 + 3라우트)이고 `index.html` redirect가 아니다.

**Phase 순서:**
0. **Shell:** 라이트 테마·viewport(핀치줌 off)·appName 라벨·온보딩+홈+스튜디오+설정 라우트 shell·토스 뒤로가기 중복 금지.
1. **첫 소리:** getAnonymousKey(2트랙: 토스 실호출/브라우저 폴백)·닉네임·AudioContext unlock·터치 4코드 패드·activeChord reducer(순수함수 + 단위테스트).
2. **스튜디오:** 카운트인·tick clock·이벤트 녹음/재생·로컬 저장/복구.
3. **제스처 이식:** 스파이크의 MediaPipe 루프만 이식(UI는 라이트 shell). 저성능·권한 fallback 기준 구현.
4. **조건부 공유:** AWS 3엔드포인트 + polling. 실패 시 프리로드.

**시간 컷라인 (T+):**
| T+ | GO 조건 | 실패 시 |
|---|---|---|
| 1h | 3라우트 shell 뜸(redirect 아님) | shell만 |
| 2h | 스튜디오 터치 첫 소리 1초 | 터치+녹음부터 |
| 4h | activeChord reducer 단위테스트 통과 + tick 기록 | 공유/백엔드 착수 금지 |
| 6h | 제스처→reducer 입력 + 터치 폴백 전환 작동 | 제스처는 영상 데모로 분리 |
| 8h | 로컬 녹음·재생·뮤트·삭제·재진입 복구 | 백엔드 공유 컷 |
| 10h | HTTPS healthz + SQLite CRUD + sessions GET/POST | 프리로드 회귀 |
| 12h | POST tracks + polling + 2장비 조회 | 공유 데모 컷 |
| 14h | 2장비 저장·조회·재생 안정 | 프리로드 트랙만 발표 |

**정정(REVIEW-028):**
- 세그먼트는 입력 모드 선택이 아니라 현재 입력 상태·전환을 보여준다(카메라 정상 = 제스처, 실패 = 터치 자동). 동시 바인딩 금지(H28-004).
- 클립보드 자동인식 실패 시 수동 붙여넣기 fallback(H28-006).
- appName 빌드 라벨: 스파이크 검증 시점은 meetup-lite였고, 2026-06-25 `harmony`로 교체(granite.config.ts:8)·토스 콘솔 정식 등록·심사 제출 후 2026-06-26 테스트 트랙 출시(20260626-1, 등록 곽소정) → 2026-06-26 정식 전체공개(프로덕션) 출시 완료. H28-010의 'harmony 등록 + Gate0 재실행 선행'은 충족됨.

### C-1. 디자인 원칙 (토스 감성)
- 명료·절제: 한 화면 한 목적. 장식 최소, 정보 위계 뚜렷.
- 큰 터치 타깃: 악기·코드 버튼 ≥ 56px, 간격 ≥ 12px. 한 손 조작 고려.
- 단일 강조색: 토스 블루 `#3182f6`(+pressed `#1b64da`). 배경 메뉴 = 라이트(`#f2f4f6`/흰색), 연주 화면 = 다크 무대(폐기). 〔정본: 100% 라이트, 다크 무대 없음〕

### C-4. 화면별 명세

**SCR-01 악기 선택**
- 구성: 2×2 카드(피아노/드럼/기타/베이스), 큰 일러스트 아이콘 + 이름.
- 상호작용: 탭 → 코드 선택(SCR-02). 드럼은 코드/멜로디 대신 패드로 분기(회의 안건).
- 상태: 정상 / 식별 로딩 / 비활성(준비중 악기).

**SCR-02 코드 선택 (4~6개)**
- 구성: 코드 매트릭스 — 행 = 루트(C·D·E·F·G·A·B), 열 = 종류(／m／7／m7). 선택 시 칩 하이라이트 + 상단 선택 카운터(예: 3/6).
- 규칙: 최소 4, 최대 6. 선택한 코드가 SCR-04의 연주 존이 됨.
- 상호작용: 4개 미만이면 "다음" 비활성. 완료 → 연주법 선택(SCR-03).
- 상태: 정상 / 4개 미만(안내) / 6개 초과 시도(토스트).

**SCR-03 연주법 선택**
- 구성: 큰 선택 카드 2개 — 코드 연주(반주, 카메라 제스처) / 멜로디 연주(터치).
- 카피: CTA만 보고 다음 행동 예측 가능하게("코드로 반주하기" / "음 하나씩 연주하기").

**SCR-04 코드 연주 (검증된 핵심)**
- 구성: 화면 4분할 존(선택한 코드, 예 G·D·C·Em) + 카메라 프리뷰(다크) + 손 랜드마크 오버레이.
- 입력: 카메라 제스처 — 손 위치 = 코드 존, 편 손 = 지속음, 주먹 = 멈춤. 존이 넓어 의도치 않은 오발이 적다.
- 하단 녹음 바: ● 녹음 / ▶ 다시 듣기(= 원안 "돌아보기", 내 녹음 재생) / ⏸ 일시정지 / ⏹ 정지 + 실시간 파형 + "녹음 중" 표시.
- 트레이(SCR-06)로 연결: 메트로놈·악기 추가·다른 사람 음원 추가·저장/공유.
- 상태: 정상 / 카메라 권한 요청·거부 / 손 미인식(안내) / 녹음 중 / 저성능(FPS 낮음 경고) / 오류.

**SCR-05 멜로디 연주 (터치)**
- 피아노: 가로 스크롤 건반(흰/검은 건반), 1~2 옥타브. 다크 배경.
- 기타/베이스: 지판(프렛 그리드) — 가로 = 현(기타 6/베이스 4), 세로 = 프렛. 칸 = 프렛, 계이름 표기 옵션.
- 입력: 터치(정밀). 원안 메모(곽소정): 멜로디를 모션으로 하면 손이 지나가며 인접음을 의도치 않게 트리거하므로 터치 채택.
- 녹음 바·트레이 동일.
- 상태: 정상 / 스크롤 힌트 / 녹음 중 / 오류.

**SCR-06 녹음·합주 트레이 (공통)**
- 진입: 연주 화면 하단 칩 — 메트로놈 / 악기 추가 / 다른 사람 음원 추가 / 녹음본 저장·공유.
- 합주 모델: 비동기 레이어 — 내 트랙 녹음 → 저장/공유 → 다른 사람이 그 위에 얹음. 공유 기준 클럭 = 메트로놈.
- 상태: 트랙 0~N(레이어 목록), 재생/뮤트/삭제(트랙별).

**SCR-07 공유·음원 추가**
- 구성: 리스트 — 제목 · 제작자 · 음 길이 · 들어보기(▶). 들어보기 강조.
- 상호작용: 들어보기 = 미리듣기, "내 곡에 추가" = 레이어로 가져오기.
- 상태: 정상 / 빈 목록 / 로딩 / 재생 중.

**SCR-08 메트로놈**
- 구성: 박자 설정(콤보: 4/4·3/4·6/8) + BPM 설정(숫자 up/down, 기본값 100) + 시작/정지 + 박 시각 표시.
- 상태: 정지 / 재생(비트 플래시).

### C-5. 상호작용 모델 요약
- 코드 연주 = 카메라 제스처(넓은 존 → 오발 적음) / 멜로디 = 터치(정밀, 인접음 오발 방지).
- 녹음 = 이벤트 기반(음/시각 데이터), 마이크 불필요.
- 합주 = 비동기 "얹기"(녹음 → 공유 → 레이어), 실시간 오디오 스트리밍 없음.

### C-6. 컴포넌트/토큰
- 재사용: `theme.css` 토큰 + `ui.tsx`(Screen/AppBar/Card/Button/Badge/Field/Empty).
- 신규 제안: `ChordPad`(4분할), `InstrumentCard`, `ChordMatrix`, `PianoKeyboard`, `Fretboard`, `RecordBar`, `TrackLayer`, `ShareRow`, `Metronome`.

### C-7. 페이지 아키텍처 (웹/앱 반응형) · 인증
산출물 = 토스 미니앱(모바일 WebView) 1개. "웹/앱" 구분은 별도 제품이 아니라 반응형 동작으로 처리(별도 웹 제품은 해커톤 범위 밖 권장).
- 넓은 화면(웹/태블릿): 연주 페이지에서 코드 선택·연주법·하단 기능(녹음·메트로놈 등)을 옆/아래 인라인 패널로.
- 모바일(미니앱 기본): 같은 서브 기능을 풀페이지 이동으로(작은 화면 가독·터치).
- 한 코드베이스, 화면폭에 따라 패널 ↔ 페이지 전환.

인증(정책): 자체 로그인/회원가입은 토스 미니앱에서 금지(토스 로그인만 허용·비사업자 불가, DL-016). → getAnonymousKey 익명 식별 + 닉네임 온보딩 1회로 "가입 같은" 경험. 자체 회원가입 페이지는 심사 반려 위험.

추가 페이지(원안 + 보강): 스플래시/온보딩(닉네임) · 내 곡(저장된 녹음) · 설정 · 문의하기(원안) · 약관·개인정보(필수 고지) · 합주 공개 시 신고.

### C-8. 미해결 / 회의 안건 (원안 시점 기록)
- 로그인/회원가입(원안): 미니앱 자체 로그인 금지 → getAnonymousKey + 닉네임 대체 제안. 별도 웹 제품이면 가능하나 범위 밖 — 회의에서 확정.
- 웹 별도 제품 범위 여부(해커톤은 미니앱 집중 권장).
- 드럼 연주 방식(패드 그리드? 코드/멜로디 분기 없음?).
- 멜로디 음역 범위(피아노 옥타브 수, 지판 프렛 수).
- 합주 트랙 수 상한, 공유 저장 백엔드(스토리지) 범위.
- 5분 데모 동선(어느 화면을 시연 메인으로).
- 접근성(색약·소리 없는 환경 대응).
