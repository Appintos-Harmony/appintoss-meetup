## 2. 제품 설명 (심사 제출용)

하모니는 사용자가 악기 음색(피아노·기타·베이스·드럼)을 고르고 코드·멜로디·드럼을 연주·녹음한 뒤, 친구가 공유한 트랙 위에 자기 악기를 얹어 비동기로 한 곡을 완성하는 음악 창작 도구다. 입력은 터치와 카메라 손 제스처(MediaPipe) 중 택1이며, 합주는 공유 코드 + 1.5초 폴링으로 처리한다(실시간 세션 아님). 자체 로그인·회원가입은 없고 토스 익명 식별과 닉네임만 사용한다.

기능 정본은 [서비스 기능정의서](../01_서비스기획/서비스_기능정의서.md)(FR-ID-01 ~ FR-JAM-01), 사용자 흐름은 [PRD](../01_서비스기획/제품요구사항정의서_PRD.md) 2절을 따른다. 여기서는 중복하지 않는다.

## 3. 비게임 분류 근거

콘솔 등록 카테고리는 '생활 > 일상 > 취미'(§1)이며, 아래 표는 게임/소셜/금융이 아니라 비게임 음악·창작 도구임을 논증하는 분류 판단이다.

| 분류 후보 | 판단 | 근거 |
|---|---|---|
| 음악·창작 도구 | 주 분류 | Web Audio 기반 악기 연주·녹음·합주가 핵심 |
| 게임 | 해당 없음 | 점수·경쟁·사행·랜덤 보상 없음 |
| 소셜/만남 | 해당 없음 | 오프라인 만남 모집 아님. 공유 코드 기반 합주로 불특정 사용자 추천·연결 없음(POL-03) |
| 금융/결제/리워드 | 해당 없음 | 결제·광고·현금성 리워드 없음 |

상세 판단은 [서비스 분류검토서](../02_정책준수/서비스_분류검토서.md), 정책 영역별 적용은 [앱인토스 정책준수표](../02_정책준수/앱인토스_정책준수표.md).

## 4. 사용자 식별·인증

- 토스 로그인·자체 로그인·소셜 로그인 모두 미사용. 비게임 전용 `getAnonymousKey`로 미니앱별 고유 익명키를 받고, 닉네임 1회 입력만 받는다(DL-016, 근거목록 #2~#4).
- `getAnonymousKey`는 클라이언트 식별용이며 서버 인증 토큰이 아니다(근거목록 #4). 공유·합주 엔드포인트는 입력 검증으로 보호한다([PRD](../01_서비스기획/제품요구사항정의서_PRD.md) 6절).
- `apps/miniapp/src/lib/identity.ts`의 `getUserKey()`는 `isToss()` 분기로 2트랙을 배선한다(머지 f506717): 토스(WebView/샌드박스)에서는 실제 `getAnonymousKey`를 호출해 `toss_<hash>`를 반환하고, 일반 브라우저(AWS)에서는 암호학적 난수 익명 폴백(`anon_…`)을 쓴다. — 상태: **코드 반영 완료**. per-user 식별 검증은 정식 배포·토스앱 QR 진입(실기기)에서만 가능하다(사람 단계).
