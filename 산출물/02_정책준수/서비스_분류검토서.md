# 서비스 분류 검토서

CLAUDE.md §3.2·§4에 따라, 정책 분류를 기능 구현보다 먼저 판단한다. 이 문서는 DL-018 피벗 이후 **하모니(harmony)** 기준 정본이다.

## 제품 성격 (확신도: 높음)

- 사용자가 악기 음색을 고르고 코드/멜로디/드럼을 연주·녹음한다.
- 친구가 받은 공유 코드로 트랙을 얹어 비동기 합주를 만든다.
- 자체 로그인/회원가입은 없고, 토스 익명 식별(`getAnonymousKey`)과 닉네임 온보딩만 사용한다.
- 위치, 결제, 광고, 오프라인 만남 모집, 실명 프로필은 MVP 범위 밖이다.

## 정책 분류 판단

| 분류 후보 | 판단 | 근거 |
|---|---|---|
| 음악·창작 도구 | 주 분류 | Web Audio 기반 악기 연주·녹음·합주가 핵심 |
| 소셜/만남 | 낮음 | 오프라인 만남 모집이 아니라 공유 코드 기반 합주. 공개 만남·채팅·실명 프로필 없음 |
| 게임 | 낮음 | 점수·경쟁·사행·랜덤 보상 없음 |
| 금융/결제/리워드 | 해당 없음 | 결제·현금성 리워드 없음 |

공식 근거: [공식 문서 근거목록](공식문서_근거목록.md) #1~#10, 특히 #1 금지 카테고리, #4 `getAnonymousKey`, #8 WebView 속성, #10 별도 앱 등록 기준.

## 결정 상태

- **하모니 악기 앱 트랙 확정** — [의사결정 기록](../00_프로젝트관리/의사결정_기록.md) DL-018.
- 인증 방식은 [DL-016](../00_프로젝트관리/의사결정_기록.md)에 따라 토스 로그인 제외, `getAnonymousKey` 채택.
- `appName=harmony` 교체 완료로 `meetup-lite` 임시 상태 해소(테스트 트랙 출시 버전 20260626-1).
