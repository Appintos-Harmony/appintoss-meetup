# 서비스 분류 검토서

CLAUDE.md §3.2·§4에 따라, 정책 분류를 기능 구현보다 먼저 판단한다. 기능 이름만 바꿔 강화 요건을 회피하지 않는다.

## 제품 성격 (확신도: 높음)

- 오프라인 놀이 모임의 개설·신청·승인·공지를 관리하는 미니앱.
- 모임 정보(일시·넓은 지역·정원·준비물·안전 규칙)와 참가 상태가 중심.

## 정책 분류 판단 (확신도: 낮음 — 미검증)

- **공개 모집형**은 앱 내 불특정 사용자 연결을 포함하므로 앱인토스 **소셜·만남 분류** 대상이 **될 가능성이 크다.**
- **초대 코드형**은 앱 내부에서 사용자를 추천·연결하지 않으므로 소셜·만남 노출이 **상대적으로 낮다.** 다만 "낯선 사람 오프라인 대면"이라는 안전 리스크는 트랙과 무관하게 남는다([리스크 관리대장](../00_프로젝트관리/리스크_관리대장.md) R-003).
- 공식 문의 회신 전에는 어느 트랙도 **"심사 가능"으로 단정하지 않는다.**

## 트랙별 영향

| 항목 | 공개 모집형 | 초대 코드형 |
|---|---|---|
| 소셜·만남 요건 노출 | 상 | 하~중 |
| 본인확인 강도(추정) | 상 | 중 |
| 모니터링·신고 부담 | 상 | 중 |

세부 비교: [트랙 비교검토](트랙_비교검토.md).

## 결정 상태

- **초대 코드형을 P0 기본 트랙으로 제안** — [의사결정 기록](../00_프로젝트관리/의사결정_기록.md) DL-002, Gate 0 승인 대기.
- 분류 확정 전제: [공식 문서 근거목록](공식문서_근거목록.md)에 "소셜·만남·채팅 분류 기준" 근거 행 추가.
