# 트랙 비교 검토 — 공개 모집형 vs 초대 코드형

CLAUDE.md §3.2·§22-4에 따라 두 출시 트랙을 정책·일정·개발 비용 관점에서 비교한다. 결정은 [의사결정 기록](../00_프로젝트관리/의사결정_기록.md) DL-002.

## 정의

- **공개 모집형**: 앱 내 공개/추천 목록으로 불특정 사용자에게 모임을 노출하고 모집한다.
- **초대 코드형**: 앱 내부에서 불특정 사용자를 추천·연결하지 않는다. 모임 링크/코드는 외부(친구·동아리·지역 채널)에서 공유하고, 앱은 코드로 진입한 사용자의 신청·승인·공지만 관리한다.

## 비교표

| 기준 | 공개 모집형 | 초대 코드형 |
|---|---|---|
| 소셜·만남 정책 노출 | 상 (불특정 연결) | 하~중 (앱 내 연결 없음) |
| 정책 검증 의존성 | 높음 — 검증 전 출시 차단 위험 | 낮음 — 핵심 기능이 검증 비의존 |
| 6/22 배포 적합성 | 낮음 (정책 회신 대기) | 높음 |
| 안전 리스크 표면 | 큼 | 상대적으로 작음 |
| 개발 비용 | 큼 (목록·추천·노출 제어) | 작음 |
| 사용자 발견성/유입 | 높음 | 낮음 (외부 공유 의존) |
| 핵심 흐름(§3.3) 지원 | 지원 | 지원 |

> "상/하" 추정은 [앱인토스 정책준수표](앱인토스_정책준수표.md)가 미검증인 상태의 잠정 판단이다. MCP 연결·정책 확인 후 갱신한다.

## 권장 (제안)

- **초대 코드형을 P0 기본 트랙으로 권장.** 근거: ① 소셜·만남 정책 미검증(R-002)·약 3일 일정(R-008)에서 공개형은 출시 차단 위험, ② 핵심 흐름이 정책 검증에 비의존, ③ §3.2가 차단 위험 시 초대 코드형 축소를 권장.
- **공개 모집형은 확장 옵션으로 보류.** 정책 검증이 6/22 전 통과하면 기능 플래그로 공개 목록을 추가한다.
- 발견성 저하는 외부 공유(코드/링크)로 보완하며, 이는 출시 리스크를 줄이기 위한 제품 결정이다(실패 아님).
