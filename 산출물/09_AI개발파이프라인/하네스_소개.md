# 하네스 소개 (학과 공유용)

> 비전공자도 1분에 이해하는 요약. 이 프로젝트가 **AI를 "많이" 쓴 게 아니라 "통제 가능하게" 쓴** 방법.

## 한 문장
ChatGPT Pro·Claude Code·Codex 세 AI의 **역할을 분리**하고, 모든 작업을 `문서 → 구현 → 검증 → 사람 승인 → 기록`으로 **추적 가능**하게 만든 운영 체계(하네스)다.

## 왜 필요한가
AI가 빠르지만 **틀리기도** 한다. 그래서 한 AI가 만든 걸 **다른 AI가 독립 검토**하고, **사람이 최종 승인**하며, 모든 근거를 git과 문서에 남긴다. → "AI가 했으니 믿어라"가 아니라 **증거로 보여준다.**

## 3층 구조
```
[통제면]  ChatGPT Pro  - 요구사항·작업지시·품질 감사
[실행면]  Claude Code  - 설계·통합·문서 / Codex - 구현·테스트·독립 검증
[승인면]  사람(팀원 4)  - 범위·병합·배포 최종 책임
```
원칙: 같은 AI가 자기 작업을 자기 승인하지 않는다. 사람이 승인자다.

## 작동 흐름
`작업지시서(TASK) → 구현 → 검증(자동) → 독립검토(다른 AI) → 토론·합의 → 사람 승인 → 커밋/머지 → 재사용`
자세히: [라이프사이클_흐름](라이프사이클_흐름.md)

## 실제로 남은 증거
- 독립검토서 28건(`독립검토서/` top-level 28, REVIEW-006~054 범위, `ls REVIEW-*.md`로 산정; 템플릿 제외, `archive/`의 Superseded 1건 별도), 합의기록 5건(합의-001~005)
- git 이력(부트스트랩→머지), 자동 검증(문서·링크·비밀값·작업지시서) PASS
- 한 번 실패→수정→통과 사례: TASK-010(REVIEW-011 NO-GO → 수정 → REVIEW-012 GO)

## 다음 팀이 재사용하려면
`CLAUDE.md`·`AGENTS.md`·`.claude`·검증 스크립트·템플릿을 복사 → 이름만 치환 → `git init` → 검증. 절차: [재사용_운영지침](재사용_운영지침.md)
