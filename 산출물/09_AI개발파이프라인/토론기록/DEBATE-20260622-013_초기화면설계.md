## 1. 결론

**맨 처음 초기화면은 콘텐츠를 만들지 않는 "얇은 허브(Home Hub)" 단 1장이며, 사용자를 '만들기(스튜디오)'와 '함께하기(커뮤니티)' 두 문으로 1탭 안에 보내는 순수 디스패처다.**

왜: 하모니 코어 루프(연주→녹음→공유→커뮤니티)는 '혼자 만들기'와 '남에게 얹기' 두 대등한 축으로 성립한다. v2 풀스튜디오가 곽소정, 커뮤니티가 이상혁에게 넘어간 지금, 초기화면이 할 수 있는 유일하게 안전한 역할은 어떤 내부 UI도 그리지 않고 두 영역으로 '보내기'만 하는 것이다. 비중복·단순라우트(DL-019)·핵심가치 최단경로를 동시에 만족한다.

## 3. 화면 명세 · Home Hub

### 3.1 목적
정확한 다음 화면(스튜디오/커뮤니티)으로 1탭에 보내는 **디스패처 + 아이덴티티 부트스트랩**. 콘텐츠·편집·목록·공개 UI를 자체 생성하지 않는다.

### 3.2 레이아웃
- **AppBar(`.appbar`):** 좌=` 하모니` + `안녕하세요 {닉}님`(1줄 ellipsis) / 우=**설정 아이콘 1개**(톱니).
- **Content(`.content`):**
  1. **인사 블록** + 상태 적응형 서브카피 1줄(곡 있음=`이어서 만들어볼까요?` / 0개=`첫 트랙을 녹음해볼까요?`).
  2. **주 진입 카드 2장(세로 스택, `.card`)**: 스튜디오(`새 곡 만들기/트랙 녹음`) · 커뮤니티(`다른 사람 곡에 얹기/둘러보기`). 카드 전체 탭, chevron, `--spring` 눌림만.
  3. **이어하기 섹션(`.card` 리스트):** 최근 곡 1~3, 곡명+악기/스타일 `.chip`+상대시간, 탭 시 `songId`만 들고 스튜디오. **곡 0개면 '아직 녹음한 곡이 없어요' 빈 상태 카드를 명시 표시(숨기지 않음 · 조장 결정).**

### 3.3 컴포넌트 ↔ theme.css 매핑
`.screen`(--bg) · `.appbar`(--surface/--text) · `.content` · 주 카드 ×2 `.card`(--e1) · 빈상태 스튜디오 강조 `.card`+`--blue` · 최근곡 `.card` · 태그 `.chip` · 설정 `.sheet`(--e2) · 모션 `--spring`(눌림만). **주 카드 상시 elevation 차등 금지.**

### 3.4 상태·엣지케이스
| 상태 | 처리 |
|---|---|
| 닉 없음 | Onboarding 강제, Home 비노출 |
| 닉 있고 곡 0 | 이어하기 자리에 빈 상태 카드('아직 녹음한 곡이 없어요') 명시 + 서브카피 + **스튜디오 카드 `--blue` 1순위**. 죄책감 카피 금지 |
| 재방문(곡 1~3) | 이어하기 노출, 최근 우선 |
| 곡 4+ | 최근 3개만. **'더 보기'/목록/관리 안 만듦** → 커뮤니티 내음원(SCR-C04)에 위임 |
| 닉 로드 지연 | `안녕하세요` 먼저 렌더, 닉은 레이아웃 점프 없이 채움 |
| 최근곡 로드 중/실패 | 스켈레톤 / 섹션만 조용히 접음. **주 카드 2장은 정적이라 항상 렌더(허브가 안 죽음), 풀스크린 에러 금지** |
| 오프라인 | 주 카드 렌더, 스튜디오(로컬) 활성. 커뮤니티는 라우팅만(빈상태는 해당 화면 책임) |
| 콜드스타트 | 마지막 route 미복원, 항상 Home 시작. 스플래시 신설 없이 스켈레톤 |

### 3.5 내비게이션 (평면 5상태)
라우트 `onboarding / home / studio / community / settings` (중첩 라우터·딥링크 신설 없음, DL-019).
스튜디오 카드→`studio`(곽소정) · 이어하기→`studio`+songId · 커뮤니티 카드→`community`(이상혁) · 설정→`settings` `.sheet`.

## 4. 비중복 경계표 (핵심)

초기화면은 **'문패와 복도'**일 뿐 방 안 가구를 두지 않는다.

| 기능 | 초기화면 | 스튜디오 SCR-ST(곽소정) | 커뮤니티 SCR-C(이상혁) | audio/api(김민혁) |
|---|:---:|:---:|:---:|:---:|
| 공통 셸·악기/스타일 콤보 | - | PASS | - | - |
| 28코드·멜로디건반·계이름패드·드럼 | - | PASS | - | - |
| 트랜스포트·공유진입 | - | PASS | - | - |
| 피드·상세·공개하기·내음원 | - | - | PASS | - |
| 곡 목록/관리/더보기 | FAIL 위임 | - | PASS(SCR-C04) | - |
| 곡 재생·편집 | FAIL | PASS | PASS | - |
| 익명키 발급·닉 저장 | PASS 부트스트랩 | - | - | (계약 제공) |
| 최근 곡 메타 조회 | PASS **읽기 전용 3필드** | - | - | (계약 제공) |
| 두 영역으로 라우팅 | PASS **유일 책임** | - | - | - |

**최근 곡 카드 한계:** `songId`·`title`·`updatedAt` 3필드만 읽는 **읽기 전용 진입 트리거**(재생/편집/관리 없음), 출처는 **내 스튜디오 곡 한 곳만**(커뮤니티 곡 혼입 금지).

## 7. 소유/경로 + Open Questions

### 7.1 소유/경로 제안
- 초기화면(Home Hub + Onboarding 게이트 + Settings 시트) = **별도 1인 소유 권장**(SCR-ST/SCR-C와 컴포넌트·라우트 비중복). 배정 미정 → 조장 결정.
- 변경 면적 최소: `App.tsx` 라우트 상수 1곳(studio→home) + `Home.tsx`에 커뮤니티 카드 1개 + 이어하기 songId 진입. 새 스택/딥링크/중첩 라우터 금지.

### 7.2 Open Questions (조장 결정)
- **OQ-1 (route 변경 호환) · 머지 전제:** `studio→home` 복원이 곽소정의 '스튜디오=항상 진입점' 가정·공유 딥링크 착지·테스트 기대값과 충돌 가능. **`songId` 전달 계약 + 공유 복귀 착지 지점을 곽소정과 서면 합의** 후 변경.
- **OQ-2 (백스택) · 미합의:** 백버튼/전환 애니 규칙. **추천:** 초기화면은 '백스택 루트=Home' 원칙만, 실제 핸들러/애니는 각 셸 소유로 위임. 3자 합의.
- **OQ-3 (전환 위계), 미합의:** **추천:** 곡 0개일 때만 스튜디오 강조, 재방문은 동등 위계 + 이어하기 우선. 상시 차등 없음.
- **OQ-4 (정책 동선) · 미합의:** 약관·개인정보 링크 = 초기화면 설정 `.sheet`, **콘텐츠 신고/차단 모더레이션 = 커뮤니티(이상혁)**. 무주공산 방지 위해 조장 명시.
- **OQ-5 (스플래시):** **추천:** 신설 없이 스켈레톤 흡수(브랜드는 Onboarding이 수행).

### 7.3 기각된 제안
- Home에 '내음원' chip 별도 진입 → 기각(2분기 흐림·커뮤니티 IA 결합). · 감정 후크 별도 카드 → 기각(서브카피 1줄 흡수). · 곡 개수 3분기 상태머신 → 최소화(이어하기 노출/숨김 + 빈상태 강조만).
