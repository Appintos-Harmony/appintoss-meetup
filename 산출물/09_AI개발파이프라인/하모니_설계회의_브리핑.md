# 하모니 설계 회의 브리핑 (GPT Pro·Gemini용 — 저장소 접근 불가 가정)

> 이 문서는 저장소를 못 읽는 AI(ChatGPT Pro·Gemini)에게 **상황을 자체 포함해 설명**하는 회의 입력본이다. 그대로 붙여넣어 설계 비평을 받는다. (Codex는 저장소를 직접 읽고 검토)

## 1. 프로젝트 한눈에
- 앱인토스(토스 미니앱) **비게임 해커톤**, 6/26 발표. 평가: 발표/시연 50 · 산출물 25 · AI 파이프라인 25 · 배포 가산 10.
- 운영: 멀티에이전트 하네스 — ChatGPT Pro(통제·품질), Claude Code·Codex(실행), 사람(승인).
- **피벗:** 기존 "소모임 밋업" → **「하모니」**(악기 합주 미니앱). 사업자 없음, **비게임**, 사용자 식별=getAnonymousKey(토스 로그인 미사용).

## 2. 제품 「하모니」
토스 안에서 악기를 연주하고, **친구가 만든 트랙 위에 내 악기를 얹어** 합주하는 앱.
- 악기: 피아노·드럼·기타·베이스
- 코드 4~6개 선택(C~B × ／m／7／m7)
- 연주: **코드 연주(카메라 손 제스처)** / **멜로디 연주(터치)**
- 녹음(이벤트 기반·마이크 불필요) → **합주=비동기 "얹기"**(녹음→공유→레이어, 실시간 오디오 스트리밍 없음)
- 메트로놈(박자 4/4·3/4·6/8, BPM 기본 100)

## 3. 이미 검증된 사실 (중요·확정)
- **코드 연주 카메라 제스처**(MediaPipe Hands + Tone.js)가 **실제 토스 WebView(갤럭시 S23 Ultra 샌드박스)에서 작동 확인됨.** 라이브 카메라(getUserMedia)·핸드트래킹·녹음 OK(연주 시 ~30fps).
- 정책: 음악앱 출시 금지 아님 / 비게임 / 표준 Web API(Web Audio·getUserMedia) 허용 / 핀치줌 금지 / 자체 뒤로가기 금지 / TDS 필수.
- 제약: granite dev는 ASCII 경로에서 실행(한글 경로 헤더 버그).

## 4. 설계 원안 (곽소정)
- 화면 흐름: ① 악기 선택 → ② 코드 4~6개 선택 → ③ 연주법 선택 → ④ 코드 연주(4분할 존+제스처)/⑤ 멜로디 연주(건반·지판, 터치) → ⑥ 녹음·트레이(메트로놈·악기추가·음원추가·저장공유) → ⑦ 공유 목록(제목·제작자·길이·들어보기) → ⑧ 메트로놈.
- 핵심 판단: **코드=제스처**(존이 넓어 오발 적음), **멜로디=터치**(모션 시 손이 지나가며 인접음 오발 → 터치 채택).
- 디자인 방향(초안): 메뉴=라이트·깔끔(토스 기본), 연주 화면=다크 무대 + 강조색 글로우. 토스 블루 #3182f6, Pretendard, 큰 터치 타깃.

## 5. 이번 회의에 요청 (GPT Pro·Gemini)
1. **토스 감성의 시니어 디자이너급 화면 구성/무드 제안** — 정보 위계, 컬러/타이포/여백/모션, "토스답다"는 느낌을 어떻게 줄지.
2. **화면명세서 비평** — 흐름의 빈틈, 각 화면의 상태(빈/로딩/권한/오류) 누락, 5분 시연 동선, 접근성.
3. **위험·결정 필요** — 드럼 연주 방식, 멜로디 음역, 합주 UX(트랙 얹기 흐름), 데모 메인 화면.
4. 각자 **구체 제안 + 근거**로 답해 주세요(다수결 아님, 근거 비교). 결과는 4-AI 토론기록(DEBATE)으로 남깁니다.

## 6. 고정 제약 (벗어나면 안 됨)
- 비게임 + TDS + 자체 뒤로가기 금지 + 핀치줌 금지.
- 코드 연주만 카메라 제스처(검증됨). 멜로디는 터치.
- 5일 일정 — MVP는 검증된 코드연주+메트로놈+녹음부터.
