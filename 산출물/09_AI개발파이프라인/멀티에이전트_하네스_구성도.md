# 멀티에이전트 하네스 구성도

이 문서는 3에이전트 운영의 **저장소 구조와 자동화(Git = 메시지 버스)**를 다룬다. 3층 구조·역할·작업 유형별 배정·상호검증 규칙은 [에이전트 역할 매트릭스](에이전트_역할매트릭스.md)를, 에이전트 정의 스냅샷은 [에이전트 목록 및 역할](에이전트_목록및역할.md)을, 작업·결과 계약은 [공통 작업계약](공통_작업계약.md)을 따른다.

## 작업 흐름 (Git 문서 = 메시지 버스, CLAUDE.md §7)

```text
작업지시서(TASK-…, Ready)
  → 주 구현 에이전트(Claude 또는 Codex) 구현 + 검증 명령
  → 다른 계열 에이전트가 독립검토서(REVIEW-…)
  → 불일치 시 결정요청서(DECISION-…)  (근거: 공식문서>요구사항>로그>테스트)
  → 사람 승인(HUMAN_APPROVAL)
  → Done(추적표·문서·증거 갱신)
```

상태: `Proposed → Ready → In Progress → AI Review → Human Approval → Done`(↘ Rework/Rejected)

세 AI는 직접 대화하지 않는다. 저장소의 승인된 문서·작업지시서·diff·테스트 로그를 공용 상태 저장소(메시지 버스)로 사용한다. 상세 배정·검증 규칙은 [에이전트 역할 매트릭스](에이전트_역할매트릭스.md) 참조.

## 주의 · settings.json 권한

2026-06-20 시점에는 `.claude/settings.json`(권한 allow 규칙)이 **AI가 자기 권한을 넓히는 자기수정**이라 자동 분류기가 AI의 자기권한 확대를 차단했다(과거 사실). 이후 **사람이 직접 검토해 settings.json을 적용**(커밋 de049d7)했고, 현재는 `.claude/settings.json`이 **실재**하며 권한 분리가 가동 중이다: `permissions.allow`=git add/commit·`node tooling/scripts`, `ask`=git push/merge/tag, `deny`=`git push --force`/`git push -f`/`rm -rf`. 즉 커밋은 allow(자동), push·merge·tag는 ask(사람 게이트)다. 권장 내용은 [재사용 운영지침](재사용_운영지침.md) 참조. 추가 강제는 git-hook·CI로 보강했다.
