# AI 개발 라이프사이클 흐름

> 작업 1건이 어떻게 흐르는지 + 실제 사례로 1회 관통. 평가의 "구현-검증 라이프사이클 파이프라인" 증거.

## 흐름도
```
작업지시서(TASK, Ready)
   │   사람이 범위·수락기준·검증명령·승인자 지정
   ▼
구현 (Claude 또는 Codex, 작업 브랜치)
   ▼
자동 검증 (검증_전체: 문서·산출물·링크·작업지시서·비밀값) ── 실패 시 되돌림
   ▼
독립 검토 (다른 계열 AI → REVIEW-…)
   ▼
토론·합의 (일치→합의기록 / 불일치→결정요청서)
   ▼
사람 승인 (이상혁·역할 담당)
   ▼
커밋/머지 (커밋 헬퍼 --path · main 보호 · 비밀값 훅 · feature→develop)
   ▼
재사용 (템플릿·스크립트·지침)
```

## 단계별 산출물·증거
| 단계 | 산출물 | 증거 위치 |
|---|---|---|
| 작업지시서 | TASK-… | `작업지시서/` · 목록 |
| 구현 | diff/파일 | git 커밋 |
| 자동 검증 | PASS 로그 | `평가증빙/테스트증빙_목록.md`(EV-) |
| 독립 검토 | REVIEW-… | `독립검토서/` · 목록 |
| 합의 | 합의-… | `합의기록/합의_기록_목록.md` |
| 사람 승인 | 승인 기록 | `평가증빙/사람검수_기록.md` |
| 커밋/머지 | 커밋·머지 | `git log` |

## 현재 범위
이 흐름은 하네스(문서·운영)뿐 아니라 **제품 라이프사이클도 1회 관통했다**. 초기화면·오디오 작업 묶음([TASK-029](작업지시서/TASK-20260622-029_음정버그수정_김민혁.md)·[TASK-030](작업지시서/TASK-20260622-030_풀스튜디오UI_곽소정.md)·[TASK-031](작업지시서/TASK-20260622-031_초기화면홈허브_김민혁.md))을 구현하고, 두 PR을 다른 계열 페르소나가 독립검토([REVIEW-032](독립검토서/REVIEW-20260622-032_초기화면오디오PR.md))해 **PR#1=Rework / PR#2=GO**로 갈랐다. PR#1은 코드 품질은 GO 수준이었지만 소유권 문서 모순(거버넌스)으로 머지 보류 판정이 났고, 조장이 소유권을 확정하고 테스트 증빙을 연결한 뒤 GO 조건을 채웠다. 검토 시점 실측은 `vitest run` 24 passed, `tsc --noEmit` exit 0이며, 제품은 AWS EC2(nginx + systemd harmony-api, https://3.39.167.74.nip.io)에 배포돼 운영 중이다.

이 사례가 TASK-010보다 강한 증거다. AI 생성 코드의 결함을 다른 AI가 잡아 Rework→GO로 되돌리는 흐름이 제품 코드에서 실제로 작동했고, 그 끝에 배포까지 닿았기 때문이다.

남은 부분만 정직하게 고지한다. REVIEW-032 독립검토는 실제 Codex가 아니라 조장 승인 하 Codex 페르소나가 대행했으므로 완전한 교차계열 독립성은 미충족이며, 추후 실제 Codex 검토로 보강이 필요하다. 통합테스트는 12/12 통과지만 과거 스냅샷 기준이고, 토스 WebView 등록(ait deploy)은 아직 진행 전이다.
