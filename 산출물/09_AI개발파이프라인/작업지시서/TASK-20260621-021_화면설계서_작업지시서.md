# TASK-20260621-021 — 화면설계서 작성 + 추적표 SCR 연결

## 1. 배경과 문제
프로토타입(TASK-019)이 흐름·규칙은 증명했으나 화면 정의가 없어 디자인이 약하다. 화면설계서(필수 산출물 §9)를 작성해 UI 재구현·Figma·추적성의 단일 기준을 만든다.

## 2. 목표와 비목표
- 목표: ① SCR-### 화면 정의(목적·FR·진입·구성·상태별·CTA·예외) ② 네비게이션 맵·상태 매트릭스 ③ 요구사항_추적표 `화면` 칸을 `예정`→SCR ID로 갱신(R18-002/R19-002 해소).
- 비목표: UI 코드 재구현(별도 TASK), Figma 실제 작성(곽소정), TDS 세부 매핑(인계서).

## 3. 입력 근거
- PRD(`5888cbf`), 서비스_기능정의서, 요구사항_추적표, CLAUDE.md §12(화면·상태·SCR)·NFR-004(접근성)
- 현 프로토타입 apps/miniapp(흐름 참고)

## 4. 수락 기준
1. MVP 화면(SCR-001~005) 각각 목적·관련 FR·진입·구성·**상태별 화면(§12 해당)**·CTA·예외/검증 포함.
2. 후속 화면(SCR-006~009: 공지·신고·운영자·내정보/탈퇴) 범위·FR 명시(미구현 표기).
3. 네비게이션 맵 + 화면×상태 매트릭스 존재.
4. 요구사항_추적표 `화면` 칸이 SCR ID로 채워지고 SCR↔FR 일치.
5. 정밀 위치 미표시(POL-003)·토스 네비 중복 금지(§12)·접근성(NFR-004) 반영.
6. 검증_전체·링크_검증 PASS. 가짜 수치·미구현을 구현처럼 쓰지 않음.
