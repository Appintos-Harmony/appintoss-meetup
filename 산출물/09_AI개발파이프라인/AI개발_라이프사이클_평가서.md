## 발견된 AI 오류·사람/가드 개입 (실제)

AI 결과를 그대로 신뢰하지 않고 다른 계열 AI·자동 가드·사람이 실제로 잡아낸 사례를 1차로 기록한다. 새 사례가 생기면 여기 추가하고 [대응표 §3](평가_25점_대응표.md)을 갱신한다. 실제 기록만 적는다(추정·과장 금지).

사례는 발생 단계로 나눈다. 하네스(문서·운영) 단계 1~4, 제품 구현 단계 5~7.

### 하네스 단계

1. **Codex가 Claude 자가진단 확인 + 판정 차이 제기**: "불가" vs "조건부" → 합의 절차로 수렴(DL-008, 합의-001). 근거 = "감사 루프 실제 작동" vs "강제 레이어 부재". 양측 수정 목록이 같아 라벨만 조정, 결정요청서는 불요([공통 작업계약](공통_작업계약.md) 회의·합의 절차). (§19 사례 3·4)
2. **Codex가 Claude 구현의 보안 결함 차단(pathspec magic 우회)**: TASK-010 커밋 헬퍼에서 pathspec magic으로 경로 보호가 우회될 수 있음을 [REVIEW-011](독립검토서/REVIEW-20260620-011_TASK010구현검토.md)이 **NO-GO** 판정 → `GIT_LITERAL_PATHSPECS`+`:` 차단으로 수정 → [REVIEW-012](독립검토서/REVIEW-20260620-012_pathspec재검토.md) **GO** → 사람 승인 → 커밋 5cfa779·머지 60091ba(합의-005). (§19 사례 3·5)
3. **자동 분류기가 Claude의 자기권한 확대(settings.json) 차단**: AI가 자기 권한을 넓히려 한 시도를 가드가 거부 → git-hook·CI로 대체. (§19 사례 5)
4. **검증 스크립트가 정직성 강제**: 초기 감사 당시 산출물 19/49만 존재, 미커밋, MCP 미연결을 "완료"로 못 적게 했다. 이후 보강·제품 구현 단계에서도 누락 산출물과 미검증 실기기를 계속 분리 표기한다. (§19 사례 5)

### 제품 구현 단계

5. **독립검토가 PR#1을 Rework로 차단(거버넌스 모순)**: 초기화면/오디오 작업 묶음 검토에서 PR#1(오디오, `feat/...-029-audio`)은 코드 품질(평균율·보이싱·폴리포니·음색 2종·테스트)이 GO 수준이었지만, [REVIEW-032](독립검토서/REVIEW-20260622-032_초기화면오디오PR.md)가 소유권 문서 불일치를 차단 사유로 **Rework** 판정했다. carve-out 계약은 Studio·오디오를 곽소정 소유로, TASK-029는 `human_owner: 이상혁`으로 상반 규정 → 단일 진실원 부재. 조장이 소유권을 확정([DL-20260622](DL-20260622_초기화면_오디오_정합.md) 결정 1·2)하고 테스트 증빙 24/24를 연결한 뒤 GO 조건을 채웠다. PR#2(홈허브)는 같은 검토에서 GO. (§19 사례 3·4)
6. **거버넌스 감사가 TASK-029 범위 초과 적발 → DL 소급 정합**: 공식 [TASK-029](작업지시서/TASK-20260622-029_음정버그수정_김민혁.md)는 `allowed_paths: audio/**`, `forbidden: routes/**`, 비목표 "새 음색 추가는 별건"이었다. 실제 구현(PR#1)은 `routes/Studio.tsx`(멜로디 폴리포니·멀티옥타브 키보드, +268)와 피아노 음색 2종(어쿠스틱/전자)을 포함해 path-lock과 비목표를 넘었다. 근거는 조장 구두 지시(DL-023 슈퍼권한)였고, 절차 누락을 [DL-20260622](DL-20260622_초기화면_오디오_정합.md) 결정 1로 소급 정합했다. 같은 ID로 만들었던 중복 작업지시서(`음정정확도`)·중복 회의록은 정리(커밋 3baa959). (§19 사례 4)
7. **선행 검토의 폴리포니 HIGH 주장 3건을 실파일 직독으로 강등**: REVIEW-032는 Codex 독립검토에서 선행 검토 주장을 실제 커밋 코드와 교차검증했고, 차단급(HIGH)으로 제기된 events.ts/NoteEvent 폴리포니 런타임 충돌 3건이 실파일과 어긋남을 확인했다. TASK-030·events.ts는 두 PR 브랜치에 미존재(미래 스트림)였으므로 차단 사유에서 제외하고 잔여 위험(⑤)으로 이관했다. AI 검토 의견도 실증거로 검증하지 않으면 채택하지 않는다는 원칙이 적용된 사례다. (§19 사례 3·4)

8. **후반 동일계열 자기검증 한계를 교차계열로 폐쇄**: 후반 전체 감사([REVIEW-053](독립검토서/REVIEW-20260625-053_발표D1_전체품질감사.md)·[REVIEW-054](독립검토서/REVIEW-20260627-054_출시후_코드파이프라인_전체감사.md))가 같은 계열(Claude) 자기검증임을 REVIEW-054가 정직하게 고지했고, 권고대로 Codex가 최종 상태를 교차계열 독립검토했다([REVIEW-055](독립검토서/REVIEW-20260629-055_Codex_최종_교차계열_감사.md), 2026-06-29, Conditional GO). Codex가 단위 58/58·타입 0 errors·웹 빌드·보안 블랙박스 7/7·`/healthz` 200을 직접 실행(exit 0)하고 종료보고서 문서·코드 불일치 2건(빌드 수치·신고 숨김 표현)을 지적 → Claude Code가 수정 반영. 파이프라인이 자기 약점을 발견하고 다른 계열로 닫은 사례다. (§19 사례)
