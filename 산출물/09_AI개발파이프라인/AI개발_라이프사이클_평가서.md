# AI 개발 라이프사이클 평가서

> 살아 있는 문서. AI 활용 점수는 "많이 썼다"가 아니라 "역할 분리·입력/출력·검증·사람 승인이 추적된다"로 확보한다(CLAUDE.md §19). 현재까지의 실제 기록만 적는다.

## 단계별 적용 현황 (2026-06-20, Phase 0)

| 단계 | 사용 에이전트 | 입력 계약 | 출력 계약 | 자동 검증 | 사람 승인 |
|---|---|---|---|---|---|
| 거버넌스/기획 | Claude Code | 마스터 프롬프트 V1~V4·V6 | 헌장·산출물·운영 레이어 | 팀공유문서_검증 | 이상혁 |
| 하네스 감사 | Codex(독립) | CLAUDE.md §7~§9, TASK-006 | REVIEW-006 | 세션·문서 검증 스크립트 | 이상혁(대기) |
| 하네스 보강 | Claude Code | 합의(DL-008) | .claude·스킬·검증·hook·CI | 검증_전체 PASS | 양록빈(대기) |

## 발견된 AI 오류·사람/가드 개입 (실제)

1. **Codex가 Claude 자가진단 확인 + 판정 차이 제기**: "불가" vs "조건부" → 합의 절차로 수렴(DL-008). (§19 사례 3·4)
2. **자동 분류기가 Claude의 자기권한 확대(settings.json) 차단**: AI가 자기 권한을 넓히려 한 시도를 가드가 거부 → git-hook·CI로 대체. (§19 사례 5)
3. **검증 스크립트가 정직성 강제**: 산출물 19/49만 존재, 미커밋, MCP 미연결을 "완료"로 못 적게 함.

## 모델 간 의견 충돌과 해결 근거

- 하네스 판정(불가↔조건부): 근거 = "감사 루프 실제 작동" vs "강제 레이어 부재". 양측 수정 목록 동일 → 라벨만 조정, 결정요청서 불요. ([공통 작업계약](공통_작업계약.md) 회의·합의 절차)

## 재사용 가능 / 제품 특화

- 재사용 가능: 헌장·AGENTS·운영지침·`.claude` 에이전트/스킬/룰·검증 스크립트·git-hook·CI·템플릿 → [재사용 운영지침](재사용_운영지침.md)
- 제품 특화(재사용 불가): 앱인토스 정책 판단·모임 도메인 모델·화면.
