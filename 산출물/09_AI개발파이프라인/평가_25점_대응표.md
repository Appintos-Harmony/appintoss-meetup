# 25점 평가 대응표

> 평가 항목 **"AI 도구 활용과 재사용 가능한 라이프사이클 파이프라인 25%"**의 **단일 기준본**.
> AI 활용 점수는 "많이 썼다"가 아니라 "역할 분리·입력/출력·자동 검증·사람 승인이 추적된다"로 확보한다(CLAUDE.md §19).
> **증거 2층 분리:** ⓐ 하네스·문서 파이프라인 = 확보 · ⓑ 제품 구현·배포·테스트 = 진행 증거 확보, 앱인토스 실기기 9건 완료·2026-06-26 테스트 트랙 출시(버전 20260626-1, SDK 2.9.2) → 2026-06-26 정식 전체공개(프로덕션) 출시 완료.
> 흐름 1회 관통과 실제 관통 사례는 [라이프사이클 흐름](라이프사이클_흐름.md), 증거 파일 위치 색인은 [평가 증빙 맵](../../평가증빙/평가_증빙_맵.md)에 둔다(중복 작성 금지).

## 2. 단계별 적용 현황 (에이전트 역할·입출력·자동 검증·사람 승인)

라이프사이클 각 단계에서 누가(에이전트), 무엇을 입력받아(입력 계약), 무엇을 내고(출력 계약), 어떻게 자동 검증되고, 누가 승인하는지를 한 표로 정리한다.

위 세 행(거버넌스/기획·하네스 감사·하네스 보강)은 6/20 Phase 0 기록이다. 아래 세 행(구현·테스트·배포)은 6/22 이후 제품 작업패킷에서 같은 계약(작업지시서→구현→자동 검증→독립검토→사람 승인)으로 실제 관통한 기록이다.

## 3. 발견된 AI 오류·사람/가드 개입 (실제 사례)

AI 결과를 그대로 신뢰하지 않고, 다른 계열 AI·자동 가드·사람이 실제로 잡아낸 사례다(추정·과장 없음). 사례별 근거는 REVIEW-/DL-/git으로 연결된다. 하네스 단계 1~4, 제품 구현 단계 5~7.

1. **Codex가 Claude 자가진단 확인 + 판정 차이 제기**: "불가" vs "조건부" → 합의 절차로 수렴(DL-008, 합의-001). 근거 = "감사 루프 실제 작동" vs "강제 레이어 부재". 양측 수정 목록이 동일했으므로 라벨만 조정, 결정요청서는 불요. (§19 사례 3·4)
2. **Codex가 Claude 구현의 보안 결함 차단(pathspec magic 우회)**: TASK-010 커밋 헬퍼에서 pathspec magic으로 경로 보호가 우회될 수 있음을 [REVIEW-011](독립검토서/REVIEW-20260620-011_TASK010구현검토.md)이 **NO-GO** 판정 → `GIT_LITERAL_PATHSPECS`+`:` 차단으로 수정 → [REVIEW-012](독립검토서/REVIEW-20260620-012_pathspec재검토.md) **GO** → 사람 승인 → 커밋 5cfa779·머지 60091ba(합의-005). "AI가 만든 코드의 보안 결함을 다른 AI가 잡고, 사람이 승인해 고쳤다"가 git·REVIEW로 증명됨. (§19 사례 3·5)
3. **자동 분류기가 Claude의 자기권한 확대(settings.json) 차단**: AI가 자기 권한을 스스로 넓히려 한 시도를 가드가 거부 → git-hook·CI로 대체. (§19 사례 5)
4. **검증 스크립트가 정직성 강제**: 초기 감사 당시 산출물 19/49만 존재, 미커밋, MCP 미연결을 "완료"로 적지 못하게 함. 현재도 실기기 미검증과 누락 산출물을 완료로 포장하지 않게 한다. (§19 사례 5)
5. **독립검토가 PR#1을 Rework로 차단(거버넌스 모순)**: 오디오 PR#1은 코드 품질(평균율·보이싱·폴리포니·음색 2종)이 GO 수준이었으나 [REVIEW-032](독립검토서/REVIEW-20260622-032_초기화면오디오PR.md)가 소유권 문서 불일치(carve-out=곽소정 vs TASK-029=이상혁)를 차단 사유로 **Rework** 판정 → 조장이 소유권 확정([DL-20260622](DL-20260622_초기화면_오디오_정합.md))·테스트 증빙 24/24 연결로 GO 조건 충족. PR#2(홈허브)는 GO. (§19 사례 3·4)
6. **거버넌스 감사가 TASK-029 범위 초과 적발 → DL 소급 정합**: 공식 029는 `audio/**`·`forbidden: routes/**`였으나 PR#1이 `routes/Studio.tsx`(폴리포니·멀티옥타브 키보드)와 음색 2종을 포함해 path-lock·비목표를 초과 → [DL-20260622](DL-20260622_초기화면_오디오_정합.md) 결정 1로 소급 정합, 중복 작업지시서·회의록 정리(커밋 3baa959). (§19 사례 4)
7. **선행 검토의 폴리포니 HIGH 주장 3건을 실파일 직독으로 강등**: REVIEW-032가 선행 검토(선행 Claude 워크플로)의 events.ts/NoteEvent 폴리포니 런타임 충돌 HIGH 3건을 실제 커밋과 교차검증 → TASK-030·events.ts가 PR 브랜치에 미존재(미래 스트림)임을 확인해 차단 사유에서 제외, 잔여 위험으로 이관. AI 검토 의견도 실증거 없이는 채택하지 않는다. (§19 사례 3·4)

## 5. 미충족 / 충족 (후속 축적)

§19 필수 사례 8개 중 제품 작업패킷에서 다음이 충족됐다.

- **사례 2(Codex가 Claude 구현의 결함·테스트 누락 발견)**: [REVIEW-011](독립검토서/REVIEW-20260620-011_TASK010구현검토.md) NO-GO → 수정 → [REVIEW-012](독립검토서/REVIEW-20260620-012_pathspec재검토.md) GO(§3 사례 2와 동일 건).
- **사례 6(사람이 AI 제안을 거절·수정하고 이유를 남김)**: 초기화면·오디오 PR 독립검토 [REVIEW-032](독립검토서/REVIEW-20260622-032_초기화면오디오PR.md)에서 PR#1은 코드 품질은 GO 수준이었으나 소유권 문서 모순으로 **Rework** 판정 → 조장이 소유권을 확정하고 테스트 증빙을 연결한 뒤 GO 조건 충족.
- **사례 7(동일 작업지시서·검토 계약으로 새 기능을 다시 처리)**: TASK-029/030/031([음정 수정](작업지시서/TASK-20260622-029_음정버그수정_김민혁.md)·[풀스튜디오 UI](작업지시서/TASK-20260622-030_풀스튜디오UI_곽소정.md)·[홈 허브](작업지시서/TASK-20260622-031_초기화면홈허브_김민혁.md))를 §2 거버넌스 단계와 같은 계약으로 구현→독립검토→승인까지 관통.

남은 사례는 1(요구사항 누락 발견)과 8(새 앱 재사용)이다. 사례 6의 REVIEW-032는 Codex 독립검토 정본으로 보강 완료했다.
