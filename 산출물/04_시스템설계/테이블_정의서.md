# 테이블 정의서 (하모니)

> 백엔드 `apps/api/server.mjs`의 실제 SQLite 스키마. 합주 공유만 서버에 저장하고, 솔로 곡은 클라 localStorage에 둔다. 외부 의존 없이 `node:sqlite`만 쓴다.

## sessions — 합주 세션
| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| code | TEXT | PK | 6자리 공유 코드(혼동문자 0/1/I/O 제외) |
| name | TEXT | | 세션 이름(기본 "하모니 세션") |
| bpm | INTEGER | | 박자(기본 100) |
| created_at | INTEGER | | 생성 epoch(ms) |

## tracks — 트랙(레이어)
| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | 트랙 ID |
| code | TEXT | (sessions.code 참조) | 소속 세션 |
| owner | TEXT | | 작성자 닉네임(기본 "익명") |
| events | TEXT | | 노트 이벤트 JSON 배열(아래) |
| instrument | TEXT | | 재생 악기 `piano`/`guitar`/`bass`/`drum`. 옛 행은 NULL → 클라가 추론 |
| style | TEXT | | 음색 프리셋(소리만, 음정에는 영향 없음). 옛 행은 NULL |
| created_at | INTEGER | | 생성 epoch(ms) |

> `instrument`/`style`은 기존 DB 호환을 위해 `ALTER TABLE … ADD COLUMN`으로 추가한다(없으면 추가, 있으면 무시). 옛 행의 NULL은 조회 시 `undefined`로 내려가고 클라가 채운다.
>
> 외래키 제약은 두지 않았다. insert 전에 앱 레벨에서 세션 존재를 확인한다(`POST /sessions/:code/tracks`는 세션 없으면 404). 한 세션에 N개 트랙 = 비동기 합주 레이어("얹기").

## events JSON 요소 (`NoteEvent`)
타입 계약은 `apps/miniapp/src/audio/events.ts`. 와이어/저장 형식은 하위호환을 위해 레거시 `ChordEvent`({tick, phase, chord, source}) 모양을 그대로 쓰고, `NoteEvent`는 그 위에 `kind`를 입힌 타입 뷰다. `normalizeEvents`가 저장된 배열을 `kind`별로 복원한다.

| kind | 추가 필드 | 설명 |
|---|---|---|
| chord | chord | 28개 코드 중 하나. 7루트(C·D·E·F·G·A·B) × 4성질(없음·m·7·m7), 예 `C`/`Am`/`G7`/`Dm7` |
| melody | note | 개별 음명(예 `C4`). 코드 이름이 아닌 값은 멜로디 단음으로 본다 |
| drum | piece | 드럼 8피스 `kick`/`snare`/`hihat`/`ride`/`crash`/`hitom`/`midtom`/`floortom` |

공통 필드:

| 필드 | 타입 | 설명 |
|---|---|---|
| tick | number | 세션 공통 tick(4/4·BPM100, 1박=4tick) — 기기 간 정렬. 벽시계 ms 금지 |
| phase | 'on' \| 'off' \| 'hit' | chord/melody는 noteOn/noteOff, drum은 원샷 `hit`(off 없음) |
| source | 'gesture' \| 'touch' | 입력 방식(기록용) |

> 저장은 항상 `{tick, phase, chord, source}` 한 모양이다. 드럼은 `chord='drum:piece'`(events.ts `drumKey`)로, 멜로디 단음은 `chord='C4'`처럼 흘러 백엔드 스키마를 안 건드린다. `instrument`/`style`은 이벤트가 아니라 트랙에 싣는다("스타일=소리만" 원칙, `TrackMeta`).

## 인덱스·정합성
- `sessions.code` PK(고유). 코드 생성 시 중복 검사 후 재생성.
- `tracks` 조회는 `WHERE code=? ORDER BY id`(생성 순).
- 무결성: `events`는 서버에서 `Array.isArray` 검증 후 저장(아니면 400). 손상 JSON은 조회 시 클라가 방어.
