# 테이블 정의서 (하모니)

> 백엔드 `apps/api/server.mjs`의 실제 SQLite 스키마(`node:sqlite`, 외부 의존 없음). 서버에는 **합주 공유 + 커뮤니티 보드(공개곡·댓글·좋아요·신고)** 만 저장하고, 솔로 곡은 클라 localStorage에 둔다. 모든 컬럼은 `CREATE TABLE`/`ALTER TABLE ADD COLUMN`·실제 쿼리(`server.mjs`) 근거.

## sessions — 세션(합주 + 커뮤니티 공개곡)
| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| code | TEXT | PK | 6자리 공유 코드(혼동문자 0/1/I/O 제외) |
| name | TEXT | | 세션/곡 이름(기본 "하모니 세션") |
| bpm | INTEGER | | 템포(기본 100) |
| created_at | INTEGER | | 생성 epoch(ms) |
| published | INTEGER | DEFAULT 0 | 1=커뮤니티 보드 공개. `/community`는 `published=1 AND hidden=0`만 노출. 비공개(친구 코드 공유)는 0으로 두고 code로만 접근 |
| author | TEXT | | 공개곡 작성자 닉네임(기본 "익명") |
| author_key | TEXT | | 작성자 익명키(소유 검증·중복방지용, 외부 미노출) |
| origin_code | TEXT | | 파생곡의 원곡 `code`(출처 크레딧). NULL이면 원곡 |
| play_count | INTEGER | DEFAULT 0 | 재생 수 |
| hidden | INTEGER | DEFAULT 0 | 1=숨김(운영) |
| content_hash | TEXT | | 첫 트랙 콘텐츠 해시 — 원곡 publish 중복방지 |
| track_count | INTEGER | | 트랙 수 — 중복방지 키 보강(트랙 수 다르면 다른 곡, 멀티트랙 collapse 방지) |

> `published`~`track_count`(8개)는 기존 DB 호환을 위해 `ALTER TABLE sessions ADD COLUMN`으로 추가한다(없으면 추가, 있으면 무시).

## events JSON 요소 (`NoteEvent`)
타입 계약은 `apps/miniapp/src/audio/events.ts`. 와이어/저장 형식은 하위호환을 위해 레거시 `ChordEvent`({tick, phase, chord, source}) 모양을 그대로 쓰고, `NoteEvent`는 그 위에 `kind`를 입힌 타입 뷰다. `normalizeEvents`가 저장된 배열을 `kind`별로 복원한다.

| kind | 추가 필드 | 설명 |
|---|---|---|
| chord | chord | 28개 코드 중 하나. 7루트(C·D·E·F·G·A·B) × 4성질(없음·m·7·m7), 예 `C`/`Am`/`G7`/`Dm7` |
| melody | note | 개별 음명(예 `C4`). 코드 이름이 아닌 값은 멜로디 단음으로 본다 |
| drum | piece | 드럼 8피스 `kick`/`snare`/`hihat`/`ride`/`crash`/`hitom`/`midtom`/`floortom` |

공통 필드:

| 필드 | 타입 | 설명 |
|---|---|---|
| tick | number | 세션 공통 tick(1박=4tick) — 기기 간 정렬. 벽시계 ms 금지. 박자·템포는 클라 설정(메트로놈) |
| phase | 'on' \| 'off' \| 'hit' | chord/melody는 noteOn/noteOff, drum은 원샷 `hit`(off 없음) |
| source | 'gesture' \| 'touch' | 입력 방식(기록용) |

> 저장은 항상 `{tick, phase, chord, source}` 한 모양이다. 드럼은 `chord='drum:piece'`(events.ts `drumKey`)로, 멜로디 단음은 `chord='C4'`처럼 흘러 백엔드 스키마를 안 건드린다. `instrument`/`style`은 이벤트가 아니라 트랙에 싣는다("스타일=소리만" 원칙, `TrackMeta`).

## 인덱스·정합성
- `sessions.code` PK(고유). 코드 생성 시 중복 검사 후 재생성.
- `idx_sessions_board` ON `sessions(published, created_at)` — 보드 목록(공개곡 최신순) 조회.
- `idx_sessions_dedup` ON `sessions(author_key, content_hash, published, hidden)` — 원곡 publish 중복방지 조회.
- `tracks` 조회는 `WHERE code=? ORDER BY id`(생성 순). `comments`는 `WHERE code=? AND hidden=0 ORDER BY created_at DESC`.
- 외래키 제약은 두지 않는다 — insert 전 앱 레벨에서 세션/댓글 존재를 확인한다.
- 무결성: `events`는 서버에서 `Array.isArray` 검증 후 저장(아니면 400). 손상 JSON은 조회 시 클라가 방어. 신고·좋아요·댓글은 익명키(`x-anon-key` 헤더)로 식별하며 URL/프록시 로그 노출을 피한다.
