# 테이블 정의서 (Oracle)

> [ADR-001](아키텍처_의사결정기록/ADR-001_데이터베이스_Oracle.md) 기준 **Oracle**. 사용자 식별 = `user_key`(opaque — 현재 익명키 hash, 추후 토스 로그인 userId로 교체 가능). 날짜는 `TIMESTAMP`(UTC 저장). **정원·중복·상태 전이는 서버 트랜잭션에서 강제**(NFR-002). 도메인 로직은 `apps/miniapp/src/domains/meetup`(순수 함수)을 서버로 이식해 재사용.

## 무결성(서버 강제, NFR-002)
- **정원**: 승인 시 트랜잭션 내 `approved 수 < capacity` 확인(예: 모임 행 `SELECT ... FOR UPDATE`).
- **중복**: 신청 시 활성 신청 존재 확인.
- **상태 전이**: open→closed/cancelled, pending→approved/rejected/cancelled만 허용.
- **개인정보**(NFR-003): 실명·정밀 위치 미저장. 탈퇴 시 user_key 기준 삭제/익명화.

## DDL 예시 (Oracle)
```sql
CREATE TABLE MEETUPS (
  id VARCHAR2(36) PRIMARY KEY,
  host_key VARCHAR2(128) NOT NULL,
  title VARCHAR2(200) NOT NULL,
  start_at TIMESTAMP NOT NULL,
  area VARCHAR2(200),
  capacity NUMBER(5) NOT NULL,
  supplies VARCHAR2(500),
  intensity VARCHAR2(100),
  cancel_policy VARCHAR2(500),
  invite_code VARCHAR2(12) NOT NULL,
  status VARCHAR2(16) NOT NULL,
  created_at TIMESTAMP NOT NULL,
  CONSTRAINT chk_capacity CHECK (capacity > 0),
  CONSTRAINT uq_invite UNIQUE (invite_code)
);
CREATE INDEX idx_meetups_host ON MEETUPS(host_key);

CREATE TABLE PARTICIPATIONS (
  id VARCHAR2(36) PRIMARY KEY,
  meetup_id VARCHAR2(36) NOT NULL REFERENCES MEETUPS(id),
  applicant_key VARCHAR2(128) NOT NULL,
  nickname VARCHAR2(60) NOT NULL,
  status VARCHAR2(16) NOT NULL,
  applied_at TIMESTAMP NOT NULL
);
CREATE INDEX idx_part_meetup ON PARTICIPATIONS(meetup_id);
```
- 미결정: 스키마명/계정, CLOB vs 정규화(안전규칙), 함수기반 UNIQUE 적용 — 김민혁 확정.
