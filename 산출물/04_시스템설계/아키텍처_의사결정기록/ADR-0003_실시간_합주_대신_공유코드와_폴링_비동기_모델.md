# ADR-0003 · 실시간 합주 대신 공유코드 + 폴링 비동기 모델

## 상태

Accepted. 근거: [DL-019](../../00_프로젝트관리/의사결정_기록.md#dl-019--하모니-mvp-최종-스펙-4-ai-회의-라운드3)(MVP 백엔드 스펙), [DL-022](../../00_프로젝트관리/의사결정_기록.md#dl-022--풀버전-복귀축소-mvp--곽소정-원안-전체--앱-도메인-서빙)(풀버전 공유·음원추가).

## 맥락

"합주"의 가장 단순한 해석은 여러 사람이 동시에 실시간 연주하는 것이지만, 모바일 WebView·네트워크 환경에서
실시간 오디오 스트리밍은 레이턴시 때문에 합주가 어긋난다(DL-018). 또한 실시간 동기화는 WebSocket·세션 서버·
지터 버퍼 등 일정 내 감당하기 어려운 복잡도를 만든다.

## 결정

합주를 **비동기 "얹기"(레이어) 모델**로 구현한다.

- 각자 메트로놈(공유 BPM)에 맞춰 자기 트랙을 **이벤트 기반으로 녹음**한다(오디오 파일이 아니라 음/코드·시각 이벤트).
- 한 사람이 세션을 만들면 6자리 **공유 코드**가 발급된다(`apps/api/server.mjs` `genCode`, 혼동 문자 0/O/1/I 제외).
- 다른 사람은 코드로 세션을 조회하고 자기 트랙을 추가(`POST /sessions/:code/tracks`)한다.
- 상대 트랙 갱신은 **실시간이 아니라 폴링**으로 받는다.

엔드포인트(server.mjs 3행): `POST /sessions` · `GET /sessions/:code` · `POST /sessions/:code/tracks`
(이후 커뮤니티 보드 `GET /community`, 댓글·신고·숨김 추가).

## 결과

- 트랙은 이벤트 배열(`{tick, phase, chord}`)로 저장된다(server.mjs `badEvents` 검증, 트랙당 events ≤ 5000).
  마이크가 필요 없다(이벤트 녹음 · DL-018 스파이크와 동일 방식).
- 클라이언트는 백엔드 호출 실패 시 프리로드 세션(`PRELOAD`, `apps/miniapp/src/lib/share.ts` 27행)으로 폴백해
  데모가 끊기지 않는다(DL-020 T+10h 공유 실패 시 프리로드 강제).
- "실시간 합주 아님"은 명시 제약이다. server.mjs 5행 주석 및 DL-019 금지 문구: "실시간 합주를 MVP 완료로 표기하지 않는다."

### 폴링 주기

- server.mjs 헤더 주석(5행)은 **1.5s polling**으로 명시한다.
- DL-019는 "2장비 1~2초 polling"으로 기록한다.

두 기록은 같은 비동기 모델 범위 안의 값이며, 코드 주석(1.5s)이 현재 구현 기준이다.

### 미해결 / Open Question

- 실시간(WebSocket) 합주는 명시적으로 범위 밖이다(DL-019 제외 목록). 향후 확장 시 별도 ADR 필요.

## 대안

- **(a) WebSocket 실시간 합주:** 레이턴시·서버 복잡도로 일정 내 불가, MVP 제외(DL-019).
- **(b) 오디오 파일 업로드 합주:** 용량·저장·재생 동기화 부담 + 업로드는 범위 밖(DL-019 제외). 이벤트 녹음이 더 가볍다.
- **(c) 폴링 대신 클라이언트 수동 새로고침:** 구현은 더 단순하나 "트랙이 쌓이는" 합주 체감이 약해 1~1.5s 폴링 채택.
