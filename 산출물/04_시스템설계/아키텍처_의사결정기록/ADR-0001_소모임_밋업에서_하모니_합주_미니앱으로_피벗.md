# ADR-0001 — 소모임 밋업에서 하모니 합주 미니앱으로 피벗

## 상태

Accepted. 근거: [DL-018](../../00_프로젝트관리/의사결정_기록.md#dl-018--주제-전환-제안-소모임-밋업--악기-합주-미니앱-팀-합의-대기)(주제 전환 제안), [DL-019](../../00_프로젝트관리/의사결정_기록.md#dl-019--하모니-mvp-최종-스펙-4-ai-회의-라운드3)(MVP 스펙 확정), [DL-022](../../00_프로젝트관리/의사결정_기록.md#dl-022--풀버전-복귀축소-mvp--곽소정-원안-전체--앱-도메인-서빙)(풀버전 스코프 확대).

DL-018 자체는 "주제 자유, 팀 비즈니스 검토 후 확정"이라 `Proposed`로 남아 있으나, 후속 DL-019·DL-022가
이상혁(조장) 승인으로 하모니 스펙·스코프를 확정했고, 저장소의 실제 코드(`apps/miniapp` 악기/합주, `apps/api` 합주 백엔드)가
하모니로 구현되어 있어 아키텍처 결정으로는 Accepted로 본다.

## 맥락

초기 제품은 오프라인 놀이 모임을 개설·관리하는 소모임 밋업(초대 코드형, [DL-002](../../00_프로젝트관리/의사결정_기록.md#dl-002--기본-트랙-초대-코드형-우선-p0))이었고,
Gate 0([DL-017](../../00_프로젝트관리/의사결정_기록.md#dl-017--gate-0-통과))까지 통과했다. 조장이 주제를 재검토하면서 악기 합주(밴드) 미니앱
"하모니"로 전환을 제안했다(DL-018). 전환 근거:

- 주제는 과제상 자유이고(CLAUDE.md §2), 앱인토스 등재 가능하면 된다.
- 카메라 손 제스처 + Tone.js 연주 스파이크(`apps/miniapp/public/gesture-spike.html`, 커밋 923e545)가
  모바일 브라우저 및 토스 WebView 실기기(아이폰 13·갤럭시 S23 Ultra 샌드박스)에서 작동 확인되어 기술 리스크가 해소됐다
  (DL-018 미해결 ⓑ 해결, [공식문서 근거 #9](../../02_정책준수/공식문서_근거목록.md)).
- 음악앱은 출시 금지 카테고리가 아니고, 표준 Web Audio가 허용된다([공식문서 근거 #8](../../02_정책준수/공식문서_근거목록.md)).

## 결정

제품 주제를 **악기 합주 미니앱 「하모니」**로 전환한다.

- 솔로 연주(피아노·기타·베이스·드럼, 코드/멜로디)는 클라이언트에서 완결한다.
- 합주는 비동기 "얹기"(다른 사람 트랙에 자기 트랙을 레이어)로 구현한다(상세 ADR-0003).
- 사용자 식별은 토스 로그인 없이 익명 식별키를 유지한다(ADR-0002).
- 합주/공유/저장만 백엔드를 둔다(ADR-0004).

DL-019에서 축소 MVP로 확정했다가 DL-022에서 곽소정 원안 풀버전(악기 4종·코드/멜로디·공유·메트로놈)으로 스코프를 다시 넓혔다.

## 결과

- `apps/miniapp`는 React+TS+Vite+Granite 기반으로 악기·합주·메트로놈 화면을 구현한다. 실측: 단위 58/58 PASS·tsc 0·vite build PASS(JS 646KB).
- `apps/api`는 합주/커뮤니티 공유 백엔드로 구현되어 라이브 https://3.39.167.74.nip.io healthz 200(ADR-0004·ADR-0005).
- 소모임 제품 코드는 피벗 리셋으로 제거(커밋 9ac9af2), 별도 브랜치·GitHub에 백업(DL-018 영향 ⑥).
- 재사용: 디자인 시스템·익명 식별·스캐폴드·하네스·파이프라인·정책검증은 그대로 유지(DL-018 영향 ⑥).
- 제품 문서(PRD·기능정의서·화면·테이블·API)는 하모니 기준으로 재작성됐다.

### 미해결 / Open Question

- granite.config `appName`이 `meetup-lite`(소모임 시절 등록 앱 ID)로 남아 있고, 하모니(`harmony`)는 콘솔 미등재다
  (`apps/miniapp/granite.config.ts` 주석, DL-021 남은 일). 실기기 테스트는 등록된 `meetup-lite`를 재사용 중이다.
  제품 출시 시 `harmony` 등록 후 교체가 필요하다(Open Question — 사람 승인/콘솔 작업).
- Gate 0은 소모임 분류로 통과했으므로, 음악(엔터>음악) 카테고리로 앱 등록 교체 + Gate 0 재실행이 필요하다(DL-018 영향 ①, Open Question).

## 대안

- **(a) 소모임 밋업 유지:** Gate 0 통과 자산을 보존하나, 조장이 주제 가치를 재평가해 기각.
- **(b) 실시간 멀티플레이 합주:** 레이턴시·서버 복잡도로 일정 내 불가 → ADR-0003에서 비동기 모델로 대체.
- **(c) 카메라 제스처 없는 터치 전용 악기앱:** 차별성 약화. 제스처는 폴백(터치)과 함께 채택(DL-019).
