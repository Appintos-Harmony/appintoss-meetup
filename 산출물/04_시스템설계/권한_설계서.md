# 권한 설계서

하모니(앱인토스 비게임 악기 합주 미니앱)의 식별·인가·접근 통제·남용 방어를 정리한다(CLAUDE.md §14). 추상적 보안 일반론이 아니라, 실제 배포된 `apps/api/server.mjs`와 `apps/api/deploy/nginx-harmony-api.conf`, `apps/miniapp/src/lib/identity.ts`의 검증 지점을 file:line으로 인용한다.

> **무인증 데모 전제(정직 고지).** 이 앱은 토스 로그인·자체 회원가입·서버 세션을 쓰지 않는다(DL-016). 식별은 클라이언트 익명키, 접근권한은 6자리 세션 `code`다. 따라서 여기서 말하는 "인가"는 *완전한 인증 기반 권한*이 아니라 **데모 한정 약한 소유권 + 서버측 남용 차단**이다. production 강화 항목은 각 절의 `Open Question`/`Assumption`으로 분리한다.

## 1. 식별(Identity)

- **익명키(`author_key`/`anon_key`).** 클라이언트가 생성·보관한다. `apps/miniapp/src/lib/identity.ts:18` `getUserKey()`가 `localStorage`에 없으면 `anon_<128bit hex>`를 만든다(`identity.ts:25` `randomHex(16)` = 16바이트, `identity.ts:39-43`는 `crypto.getRandomValues` 기반 암호학적 난수).
- **식별 2트랙(코드 반영 완료).** `identity.ts`의 `getUserKey()`는 `isToss()` 분기로 토스(WebView/샌드박스)에서는 `@apps-in-toss/web-framework`의 `getAnonymousKey`를 실호출하고, 일반 브라우저에서는 암호학적 난수 익명키(crypto 128bit)로 폴백한다(머지 f506717). 정식 per-user 식별은 정식 출시·실기기 QR 진입에서 최종 검증한다.
- **엔트로피의 한계(정직 고지).** `identity.ts:21-22` 주석과 같이 128bit 엔트로피는 *키 추측에 의한 사칭*(타인 키로 hide/dedup 위조)만 줄인다. 서버가 `author_key`를 인증·검증하지 않으므로 레이트리밋·스팸 방어는 익명키 엔트로피와 무관하며 **서버측 IP 기준**에 의존한다(§5 참조). 따라서 익명키는 "민감 권한의 신뢰 근거"가 아니다.

## 2. 객체 단위 인가(Object-level Authorization, IDOR 방어)

서버는 `code`로 리소스에 접근하더라도, **변경(mutation)에는 호출자가 그 객체의 소유자(`author_key` 일치)인지 검증**한다. 인용 지점:

| 검증 지점 | file:line | 규칙 |
|---|---|---|
| 공개 세션 트랙 추가 | `apps/api/server.mjs:357-359` | `sess.published`이면 `sess.author_key === key`가 아닌 한 **403**. 시드(`'seed'`)·빈 키도 거부. 타인이 공개 code로 남의 곡을 오염시키지 못한다(Codex P0). 파생은 새 `POST /sessions` + `origin_code`로 유도. |
| 세션 숨김(`POST /sessions/:code/hide`) | `apps/api/server.mjs:397-401` | 저장된 `s.author_key`와 요청 `author_key`가 같을 때만 `hidden=1`. 불일치 시 **403 `not owner`**. 시드 세션은 `:396`에서 **403 `cannot hide seed`**. |
| 신고 대상 식별 | `apps/api/server.mjs:312` | 댓글 신고는 `(id AND code)` 동시 일치(`WHERE id = ? AND code = ?`)를 요구해 다른 세션의 댓글 ID를 교차 조작하지 못한다. |

**한계(정직 고지, §5 명세서 §5와 정합):** `author_key`는 클라이언트 자기신고 값이라 서버가 진위를 검증하지 못한다. 즉 hide/소유권 검증은 *키를 아는 사람만 통과*하는 약한 소유권이다. 비공개(친구공유) 세션은 의도적으로 "code를 아는 누구나 트랙 얹기"가 가능하다(`:357`의 가드는 `sess.published`에만 적용). 이는 협업 기능이며 데모 전제다. **`Open Question`**: production은 서명 바인딩(capability 토큰)으로 소유권을 검증해야 한다(커뮤니티 명세서 §5).

## 3. 공개/숨김 접근 규칙(published · hidden)

세션은 `published`(보드 노출)·`hidden`(작성자/모더레이션 내림) 두 플래그로 가시성을 통제한다(스키마 `server.mjs:24,29`).

- **보드 목록(`GET /community`):** `server.mjs:210,216` `WHERE published = 1 AND hidden = 0`. 비공개·숨김 세션은 목록에 절대 노출되지 않는다.
- **세션 상세(`GET /sessions/:code`):** `server.mjs:408` `if (!sess || sess.hidden) return 404`. 숨김 세션은 code를 알아도 공개 GET이 차단된다(Codex MED).
- **댓글(`/sessions/:code/comments`):** `server.mjs:325-326` 세션이 없거나 `hidden`이면 **404**(숨김 세션엔 댓글 비공개). 목록 쿼리도 `:328` `hidden = 0` 댓글만.
- **좋아요(`POST /sessions/:code/like`):** `server.mjs:374-375` 숨김 세션엔 좋아요 불가(404).
- **트랙 추가:** `server.mjs:349-350` 숨김 세션 트랙 추가 404.

즉 `hidden`은 목록·상세·댓글·좋아요·트랙 모든 표면에서 일관되게 비공개를 강제한다.

> **`Assumption` — 심사 제출 기본값.** 커뮤니티 명세서 §8(POL-03)은 심사 제출본 기본값을 **`published` 기본 0(비공개 code 모드)**으로 둬 공개 UGC 소셜 분류 리스크를 구조적으로 회피한다고 본다. 이는 조장 선결(OQ-B) 대상이며 본 설계서는 코드의 현 동작만 기술한다.

## 4. 신고 누적 자동 숨김(Moderation)

댓글 신고(`POST /sessions/:code/comments/:id/report`, `server.mjs:305-320`):

- **신고자 식별 = 서버 도출 IP**(`server.mjs:311` `const reporter = ip`). 클라이언트 `author_key`는 신고자 식별에 **쓰지 않는다**(`:309` 주석). 키 회전으로 1인이 distinct N명을 위조해 자동숨김을 트리거하지 못한다(Codex P0).
- **신고자당 1회.** `comment_reports`의 `UNIQUE(comment_id, reporter_key)`(`server.mjs:16`) + `INSERT OR IGNORE`(`:314`)로 중복 신고를 흡수한다.
- **임계 자동 숨김.** 서로 다른 신고자 누적이 `REPORT_HIDE_THRESHOLD = 3`(`server.mjs:53`) 이상이면 `hidden = 1`(`:317`).
- **한계(`Open Question`).** `server.mjs:52` 주석대로 프록시 뒤 공유 IP에선 다른 사용자가 한 버킷으로 묶일 수 있다(OQ-B). 가역 복원(unhide)은 **미구현 = 비가역**이며, 복원은 조장 수동(DB) 또는 후속 라우트가 필요하다(커뮤니티 명세서 §4 F6, §13 OQ-C).

## 5. Rate limit(IP 버킷)

남용 방어의 핵심은 **익명키가 아니라 IP 버킷**이다(`server.mjs:104` 주석: "자기신고 author_key가 아니라 IP로 버킷팅해 키 회전 우회를 막는다").

- **버킷 구조.** `RATE` Map(`server.mjs:105`), `rateOk(key, limit)`(`:106-113`)는 60초 슬라이딩 윈도. 키 접두사로 엔드포인트를 분리한다.

| 엔드포인트 | 버킷 키 | 분당 한도 | file:line |
|---|---|---|---|
| `POST /sessions` (publish) | `pub:<ip>` | 12 | `server.mjs:248` |
| `POST …/comments/:id/report` | `rpt:<ip>` | 30 | `server.mjs:308` |
| `POST …/comments` | `cmt:<ip>` | 20 | `server.mjs:334` |
| `POST …/tracks` | `trk:<ip>` | 30 | `server.mjs:354` |
| `POST …/like` | `like:<ip>` | 60 | `server.mjs:371` |

- **메모리 바운드.** `server.mjs:117-126` 5분 주기 sweep으로 만료 레이트버킷(60s)·멱등토큰(10분)을 정리한다(`.unref()`로 프로세스 종료 비차단). 데모 한정 인메모리 구현.
- **페이로드 상한.** `server.mjs:141,145` 본문 1MB 초과 시 즉시 연결 종료. 이벤트 배열은 `badEvents`(`:54-63`)에서 5000개·tick 범위·필수 필드를 검증.
- **`Assumption`.** 재기동 시 버킷·멱등 토큰이 초기화된다(인메모리). production은 영속 저장소(Redis 등) 또는 외부 레이트리밋이 필요하다.

## 6. 신뢰 프록시(XFF / X-Real-IP)

IP 버킷의 무결성은 **위조 불가한 IP 도출**에 달려 있다. 두 계층으로 강제한다.

- **앱 계층.** `clientIp(req)`(`server.mjs:95-103`)는 기본적으로 소켓 피어(`req.socket.remoteAddress`, `:102`)만 신뢰한다. `TRUST_PROXY=1`(`:94`)일 때만 `x-real-ip`(`:97-98`) 또는 단일 `x-forwarded-for`의 마지막 값(`:99-100`)을 신뢰한다. 클라이언트가 XFF를 위조해도 기본 경로에선 레이트리밋을 우회하지 못한다(Codex P0).
- **nginx 계층.** `nginx-harmony-api.conf:15-17`은 클라이언트가 보낸 XFF를 **이어붙이지 않고** 실제 TCP 피어(`$remote_addr`)로 `X-Real-IP`·`X-Forwarded-For`를 **덮어쓴다**. 따라서 `TRUST_PROXY=1` 앱은 위조 불가한 IP만 받는다.
- **바인드 하드닝.** `server.mjs:432` 기본 바인드는 `127.0.0.1`이라 8080 포트가 외부에 직접 노출되지 않는다(같은 호스트 nginx만 접근). X-Real-IP spoof 차단(Codex R039 조건). production은 `127.0.0.1` 유지 권장(`:430-431` 주석).

## 7. CORS

- `send()`(`server.mjs:128-135`)는 모든 응답에 `access-control-allow-origin: *`를 보낸다. **데모 한정**이며, `:131` 주석대로 production은 오리진 allowlist로 좁혀야 한다(**사람 게이트**, 커뮤니티 명세서 §5).
- 허용 메서드 `GET,POST,OPTIONS`(`:132`), 허용 헤더 `content-type, x-anon-key`(`:133`). `OPTIONS`는 `:190`에서 204로 선응답.
- **`Open Question`**: CORS `*`는 무인증 데모라 현실적 위험이 낮지만(쿠키·자격증명 미사용), 공개 보드 전환 시 오리진 제한은 선결 항목이다.

## 8. 개인정보 최소 수집·삭제

- **수집 최소화.** 서버 저장 데이터는 세션 메타(이름·BPM·작성자 표시명)·트랙 이벤트 JSON·댓글 텍스트·익명키뿐이다(스키마 `server.mjs:13-17`). 실명·연락처·계정·위치를 수집하지 않는다(DL-016).
- **PII 입력 차단.** UGC 텍스트는 `cleanText`(`server.mjs:83-89`)에서 제어문자 제거·길이 제한 후 URL/이메일/전화 패턴(`:80-82`)을 거부한다(`:87`). 이는 PII·스팸 최소 방어이며 **유해 텍스트(욕설·혐오) 차단은 비보장**(정직 고지, 커뮤니티 명세서 §8 OQ-F).
- **삭제.** 작성자 자기 세션은 `POST /sessions/:code/hide`(`server.mjs:391-402`)로 소유자만 숨길 수 있다. **물리 삭제 배치는 데모에 없다**(커뮤니티 명세서 §6: prod 전제 = 물리삭제 배치·세션 바이트 상한·DB 총량 경보).
- **`Open Question` — POL-04.** 성인·연령 확인 방식은 미정([요구사항_추적표](../01_서비스기획/요구사항_추적표.md) POL-04, 의사결정 §미결정).
