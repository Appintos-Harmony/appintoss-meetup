# 제품 요구사항 정의서 (PRD)

> Phase 1. 도메인 중심. 앱인토스 정책·SDK는 2026-06-21 `ax`로 확인([공식문서_근거목록](../02_정책준수/공식문서_근거목록.md)). 인증: **토스 로그인 제외 · getAnonymousKey 익명키**(DL-016). 트랙: **초대 코드형**(DL-002). 잔여 미검증(POL-002 등)만 별도 표기.

## 1. 문제 / 대상 / 비목표
- 문제: 오프라인 놀이·액티비티 모임의 모집·참가·승인 관리를 흩어진 채팅/메모로 하기 번거롭다.
- 대상: 친구·동아리·지역 활동의 성인 참가자.
- 비목표(MVP): 공개 추천·랜덤 매칭·실시간 위치·1:1 채팅·사진 업로드·결제·평점.

## 2. 핵심 사용자 흐름 (§3.3)
진입 → 안전 규칙 확인 → 초대 코드로 모임 상세 → 일시·넓은 지역·정원·준비물·안전 규칙 확인 → 참가 신청 → 주최자 승인 → 승인 상태·공지 확인 → 모집 마감/모임 취소 → 참가자 상태 일관 갱신.

## 3. 기능 요구사항 (FR)
| ID | 요구사항 | 수락 기준(요약) |
|---|---|---|
| FR-001 | 익명키 진입(getAnonymousKey) + 인앱 약관·안전규칙 동의 | 진입 시 익명 hash 자동 발급(로그인 화면 없음), 약관 미동의 시 진입 차단 |
| FR-002 | 닉네임 온보딩(hash 기반 프로필, 최초 1회) | 가입/로그인 없이 hash로 프로필 저장, 불필요 개인정보 미수집 |
| FR-003 | 모임 생성(제목·일시·대략 장소·정원·준비물·강도·취소 기준·안전 규칙) | 필수값 누락 시 생성 불가 |
| FR-004 | 초대 코드/링크로 모임 상세 진입 | 유효 코드만 상세 접근 |
| FR-005 | 참가 신청 | 중복 신청 서버 차단 |
| FR-006 | 주최자 승인·거절·대기 | 권한자만, 정원 초과 승인 차단 |
| FR-007 | 참가 취소 | 취소 시 정원 복구 |
| FR-008 | 주최자 공지 | 참가자에게 노출 |
| FR-009 | 모집 마감·모임 취소 + 통지 | 상태 일관 갱신 |
| FR-010 | 참가 코드/QR 체크인(상시 위치 없음) | 출석 확인, 위치 미추적 |
| FR-011 | 신고 접수 | 사용자·모임·콘텐츠 신고 |
| FR-012 | 최소 운영자 화면(신고 큐·비노출·처리 기록) | 권한 분리 |
| FR-013 | 계정 탈퇴·데이터 삭제 요청 | 접근 불가 처리 |
| FR-014 | 모임 목록 — 내가 만든 모임·신청한 모임·초대 코드로 접근한 모임만 표시(공개 추천·탐색 없음) | 타인 모임 비노출, 신규 접근은 초대 코드로만 |

## 4. 비기능 요구사항 (NFR)
- NFR-001 보안: 인증(익명키 식별; 민감 권한은 서버 capability 토큰으로 보강 — 익명키는 클라이언트 식별용, DL-016)·객체 단위 권한·입력 검증·XSS/IDOR 방지·rate limit·감사 로그.
- NFR-002 데이터 무결성: 정원·중복·상태 전이 서버 강제, mutation idempotency.
- NFR-003 개인정보: 최소 수집, 탈퇴·삭제 경로, 신고 데이터 접근 제한.
- NFR-004 접근성: 터치 영역·대비·스크린리더 기초.
- NFR-005 성능/안정: 핵심 흐름 응답 지연·오류율 목표(수치 미정).

## 5. 정책 요구사항 (POL) — 앱인토스 공식 확인(2026-06-21, [근거목록](../02_정책준수/공식문서_근거목록.md))
- POL-001 서비스 분류 — **확정**: 출시 금지 카테고리 아님(소셜/만남 명시 금지 없음), 초대 코드형 운영. (#1)
- POL-002 성인 전용·연령/본인 확인 — **미검증**(추가 확인). 익명키 기반이라 실명/연령 미수집.
- POL-003 위치정보 비수집(넓은 지역만)·정밀 위치 미사용 — 설계 결정.
- POL-004 비게임 출시 체크리스트·심사 제출물 — **부분 확인**(상위 가이드 확인, 기능별·제출물 추후). (#1·#6)
- POL-005 인증·플랫폼 — **확정**: 미니앱 로그인은 토스 로그인만 가능하나 비사업자 불가(#2·#3) → **토스 로그인 제외 + getAnonymousKey 익명키, 사업자 미등록**(DL-016, #4). 결제/광고 MVP 미사용, iframe 미사용(#6).

## 6. 안전·악용 시나리오
- 안전 규칙을 모임 생성·참가 흐름의 **기능**으로 구현(§14): 금지구역·무기류·**실제 경찰 제복·표식과 혼동되는 표현 금지**·접촉 기준·음주 금지·악천후 취소·시작/종료 인원·**즉시 중단 신호**·**정확한 집결 위치의 공개 노출 최소화**·이탈/부상/분쟁 대응.
- 악용: 허위 모임·노쇼·괴롭힘·미성년 진입 → 신고·차단·제재·연령 확인으로 대응.

## 7. 성공 지표 (측정 이벤트만, 수치 미정)
- 모임 생성 수, 신청→승인 전환율, 체크인율, 신고 처리 시간. (실측 전 수치 작성 금지)

## 8. 운영자 시나리오
신고 접수 → 운영자 검토 → 모임 비노출/사용자 제재 → 처리 기록(감사 로그) → 삭제 요청 처리.
