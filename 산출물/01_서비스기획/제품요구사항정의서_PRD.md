# 제품 요구사항 정의서 (PRD)

> Phase 1 초안. 도메인 중심. **앱인토스 SDK·정책 의존 항목은 MCP 미연결로 "미검증"** 표기(R-001). 트랙: **초대 코드형**(DL-002).

## 1. 문제 / 대상 / 비목표
- 문제: 오프라인 놀이·액티비티 모임의 모집·참가·승인 관리를 흩어진 채팅/메모로 하기 번거롭다.
- 대상: 친구·동아리·지역 활동의 성인 참가자.
- 비목표(MVP): 공개 추천·랜덤 매칭·실시간 위치·1:1 채팅·사진 업로드·결제·평점.

## 2. 핵심 사용자 흐름 (§3.3)
진입 → 안전 규칙 확인 → 초대 코드로 모임 상세 → 일시·넓은 지역·정원·준비물·안전 규칙 확인 → 참가 신청 → 주최자 승인 → 승인 상태·공지 확인 → 모집 마감/모임 취소 → 참가자 상태 일관 갱신.

## 3. 기능 요구사항 (FR)
| ID | 요구사항 | 수락 기준(요약) |
|---|---|---|
| FR-001 | 토스 로그인·약관 동의 | 로그인 후 약관 미동의 시 진입 차단 (구현 사양 **미검증**) |
| FR-002 | 최소 프로필(닉네임·넓은 지역·관심사) | 불필요 개인정보 미수집 |
| FR-003 | 모임 생성(제목·일시·대략 장소·정원·준비물·강도·취소 기준·안전 규칙) | 필수값 누락 시 생성 불가 |
| FR-004 | 초대 코드/링크로 모임 상세 진입 | 유효 코드만 상세 접근 |
| FR-005 | 참가 신청 | 중복 신청 서버 차단 |
| FR-006 | 주최자 승인·거절·대기 | 권한자만, 정원 초과 승인 차단 |
| FR-007 | 참가 취소 | 취소 시 정원 복구 |
| FR-008 | 주최자 공지 | 참가자에게 노출 |
| FR-009 | 모집 마감·모임 취소 + 통지 | 상태 일관 갱신 |
| FR-010 | 참가 코드/QR 체크인(상시 위치 없음) | 출석 확인, 위치 미추적 |
| FR-011 | 신고 접수 | 사용자·모임·콘텐츠 신고 |
| FR-012 | 최소 운영자 화면(신고 큐·비노출·처리 기록) | 권한 분리 |
| FR-013 | 계정 탈퇴·데이터 삭제 요청 | 접근 불가 처리 |

## 4. 비기능 요구사항 (NFR)
- NFR-001 보안: 인증·객체 단위 권한·입력 검증·XSS/IDOR 방지·rate limit·감사 로그.
- NFR-002 데이터 무결성: 정원·중복·상태 전이 서버 강제, mutation idempotency.
- NFR-003 개인정보: 최소 수집, 탈퇴·삭제 경로, 신고 데이터 접근 제한.
- NFR-004 접근성: 터치 영역·대비·스크린리더 기초.
- NFR-005 성능/안정: 핵심 흐름 응답 지연·오류율 목표(수치 미정).

## 5. 정책 요구사항 (POL) — 미검증(MCP 필요)
- POL-001 소셜·만남 분류 적용 여부 — **미검증**, 공식 문의 필요.
- POL-002 성인 전용·연령/본인 확인 방식 — 미정.
- POL-003 위치정보 비수집(넓은 지역만), 정밀 위치 미사용.
- POL-004 비게임 출시 체크리스트·심사 제출물 — 미검증.

## 6. 안전·악용 시나리오
- 안전 규칙을 모임 생성·참가 흐름의 **기능**으로 구현(§14): 금지구역·무기류·접촉 기준·음주 금지·악천후 취소·시작/종료 인원·이탈/부상/분쟁 대응.
- 악용: 허위 모임·노쇼·괴롭힘·미성년 진입 → 신고·차단·제재·연령 확인으로 대응.

## 7. 성공 지표 (측정 이벤트만, 수치 미정)
- 모임 생성 수, 신청→승인 전환율, 체크인율, 신고 처리 시간. (실측 전 수치 작성 금지)

## 8. 운영자 시나리오
신고 접수 → 운영자 검토 → 모임 비노출/사용자 제재 → 처리 기록(감사 로그) → 삭제 요청 처리.
