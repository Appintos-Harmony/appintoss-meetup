# 역할 책임 분담표 (RACI)

팀4의 실명 배정이다(CLAUDE.md §5, DL-005). 담당(기획/백엔드/프론트/테스트)에 따라 역할 A~D를 정했고, 운영 기준으로 굳었다.

- 이상혁 — 조장, 역할 A (Product & Policy)
- 곽소정 — 역할 B (Design / 프론트, 보안 검토 겸임)
- 김민혁 — 역할 C (Backend)
- 양록빈 — 역할 D (QA & Release)

## 팀원 및 역할 매핑

| 역할 | 책임 영역 (CLAUDE.md §5) | 담당자 | 근거 |
|---|---|---|---|
| 역할 A — Product & Policy Lead | 범위·우선순위, PRD·서비스 기능 정의서, 앱인토스 정책, 사용자 흐름, 발표 스토리, 최종 승인 | **이상혁 (조장)** | 기획 담당·조장·최종 승인 |
| 역할 B — Miniapp & Design Lead | Figma, 화면설계서, TDS 매핑, 미니앱 프런트엔드, 접근성·UX 문구, 디자인 QA | **곽소정** | 디자인·프론트 담당 |
| 역할 C — Backend & Data Lead | API 서버(node:http+node:sqlite), DB, 익명키 인증, 테이블 정의서, 데이터 삭제, 서버 배포 | **김민혁** | 백엔드 담당 |
| 역할 D — QA & Release Lead | 테스트 계획·자동화(vitest), 통합테스트, 실기기·샌드박스 검수, CI/CD, 사용자 매뉴얼, 릴리즈·롤백, 발표 시연 | **양록빈** | 테스트 담당 |

> 보안: 곽소정이 보안 역량을 보유해, 익명키 인증·공유세션 API의 2인 교차 검토에 참여한다(§5). 조장 이상혁이 작업을 주도해도 구현자와 검토자는 분리한다.

## 운영 규칙 (CLAUDE.md §5·§6·§7.2)

- 구현자와 검토자를 분리한다. 한 모델 산출물을 같은 모델 자기검토만으로 승인하지 않는다.
- 익명키 인증·공유세션 API는 최소 2명(예: 김민혁 + 곽소정/양록빈)이 검토한다.
- 기능 완료는 양록빈(QA & Release)이 검증 결과를 남긴 뒤 승인한다.
- `owner`/`reviewer`/승인자에는 실제 사람만 기록한다. 도구·모델 이름 금지.
- 배포·데이터 삭제·키 로테이션·push·merge·tag는 사람(조장 또는 역할 담당) 승인이 필요하다.

하모니 스코프 기준이다. 악기·연주, 공유세션 API, 익명키, 실기기·발표 항목으로 구성한다.
