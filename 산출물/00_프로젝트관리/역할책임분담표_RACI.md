# 역할 책임 분담표 (RACI)

팀원 실명을 역할 A~D에 매핑한다(CLAUDE.md §5). 아래 **역할-문자 배정은 제공된 담당(기획/백엔드/프론트/테스트)에 근거한 제안**이며, 팀이 확정해 주면 갱신한다. 이름은 실제 팀원이다.

## 팀원 및 역할 매핑 (제안)

| 역할 | 책임 영역 (CLAUDE.md §5) | 담당자 | 근거 |
|---|---|---|---|
| 역할 A — Product & Policy Lead | 범위·우선순위, PRD·서비스 기능 정의서, 앱인토스 정책 매트릭스, 사용자 흐름, 발표 스토리, 최종 승인 | **이상혁 (조장)** | 조장·최종 승인·전반 주도 |
| 역할 B — Miniapp & Design Lead | Figma, 화면설계서, TDS 매핑, 미니앱 프런트엔드, 접근성·UX 문구, 디자인 QA | **곽소정** | 기획·프론트 담당 |
| 역할 C — Backend & Data Lead | API 서버, DB, 인증·인가, 테이블 정의서, 데이터 삭제, 운영자 기능, 서버 배포 | **김민혁** | 백엔드 담당 |
| 역할 D — QA & Release Lead | 테스트 계획·자동화, 통합테스트, 실기기·샌드박스 검수, CI/CD, 사용자 매뉴얼, 릴리즈·롤백, 발표 시연 환경 | **양록빈** | 테스트 담당 |

> 보안: 곽소정이 보안 역량을 보유하여, 인증·권한·개인정보·신고 기능의 **2인 교차 검토**에 곽소정이 참여한다(§5). 조장 이상혁이 대부분의 작업을 주도하더라도, 구현자와 검토자는 분리한다.

## 운영 규칙 (CLAUDE.md §5·§6·§7.2)

- 구현자와 검토자를 분리한다. 한 모델 산출물을 같은 모델 자기검토만으로 승인하지 않는다.
- 인증·권한·개인정보 삭제·신고 기능은 **최소 2명**(예: 김민혁 + 곽소정/양록빈) 검토.
- 기능 완료는 **양록빈(QA & Release)** 이 검증 결과를 남긴 뒤 승인.
- `owner`/`reviewer`/승인자에는 실제 사람만 기록. 도구·모델 이름 금지.
- 배포·데이터 삭제·migration·push·merge·tag는 **사람(조장 또는 역할 담당) 승인** 필요.

## 의사결정 매트릭스 (R=실행, A=승인, C=자문, I=공유)

| 의사결정 | 이상혁(A) | 곽소정(B) | 김민혁(C) | 양록빈(D) |
|---|---|---|---|---|
| 제품 범위·트랙 확정 | A/R | C | C | C |
| 개인정보 수집·삭제 | A | C(보안) | R | C |
| 인증·권한 설계 | C | C(보안) | R | C |
| 신고·운영자 기능 | A | C | R | C |
| 배포·롤백 승인 | A | I | R | R |
| 기능 완료 판정 | C | I | C | A/R |
| UX·콘텐츠·화면 기준 | C | R | I | C |
| 발표 구성·시연 | A/R | C | C | R |
