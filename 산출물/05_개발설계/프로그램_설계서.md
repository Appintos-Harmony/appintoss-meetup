# 프로그램 설계서 (하모니)

> 실제 소스 기준 모듈별 입출력·처리·예외·단위테스트 연결. 함수 시그니처와 불변식은 코드에서 직접 읽어 기술한다.
> 파일 목록·역할 개요는 [프로그램_목록](프로그램_목록.md), 구현 맥락은 [하모니_스튜디오_구현내역](하모니_스튜디오_구현내역.md)(중복 서술 금지 — 링크). 단위테스트 ID는 [단위테스트_결과서](../06_테스트/단위테스트_결과서.md)와 연결.

## 0. 읽는 법

- "관련 단위테스트ID" 열은 [단위테스트_결과서](../06_테스트/단위테스트_결과서.md)의 케이스 ID(UT-RD/PY/TN/EV/LP/NE/NT)를 참조한다. 비어 있으면 단위 미커버(통합/실기기 범위 또는 미작성)다.
- "불변식"은 코드가 강제하는 도메인 규칙이다. 위반 시 예외/거부/no-op로 처리된다.
- API 핸들러는 모두 `apps/api/server.mjs` 단일 파일의 라우트 분기다(무의존 node:http+node:sqlite).

## 1. 미니앱 — 오디오 도메인 (순수/준순수)

### 1.1 `apps/miniapp/src/audio/chordReducer.ts` — 입력 reducer (순수)

| 함수·시그니처 | 입력 | 처리 | 출력 | 예외/거부 | 단위테스트ID |
|---|---|---|---|---|---|
| `chordReducer(state: ChordState, action: ChordAction): ChordState` | 현재 상태 + 액션(`down`/`up`/`hit`) | 액션별 이벤트 적재·활성코드/활성음 갱신 | 새 `ChordState`(불변 갱신) | 변화 없는 분기는 동일 `state` 참조 반환(no-op) | UT-RD-01~15, UT-PY-01~06 |

불변식(코드에서 직접 확인):
- 같은 코드 noteOn 중복 금지: `state.activeChord === action.chord && state.activeSource !== null`이면 `state` 그대로 반환(UT-RD-02).
- 코드 전환 시에만 이전 코드 off 후 새 코드 on(`activeChord !== null` 분기, UT-RD-03).
- 터치 우선: `action.source === 'gesture'`이고 `state.activeSource === 'touch'`면 무시(UT-RD-05).
- 제스처 재개 게이트: 터치 종료 후 `GESTURE_RESUME_MS = 200`ms 동안 제스처 down 무시(`nowMs - touchReleasedAtMs < 200`, UT-RD-06).
- 폴리포니(`poly`): 음별 독립 noteOn — 같은 음 재down은 `action.chord in state.activeNotes`로 무시, up은 보유 음만 off(UT-RD-08~11, UT-PY-01~06).
- 드럼(`hit`): off 없이 단일 `phase:'on'` 이벤트만 적재, `activeChord`/`activeNotes` 불변(UT-RD-13~15).
- `up`은 활성 소스가 해제할 때만 off(다른 소스 up은 `touchReleasedAtMs`만 갱신, UT-RD-07).

불변식·음정 매핑(코드에서 직접 확인):
- 음정 단일 진실원은 `tuning.ts`(평균율 A4=440). 엔진은 `noteToFreq`/`midiToFreq`만 import하고 음정값을 만들지 않는다.
- 코드 통일 옥타브: `voiceFreqs`가 루트 음정클래스(`ROOT_PC`)+인터벌(`QUAL_IV`)로 옥타브3 트라이어드 산출(`CHORD_OCTAVE=3`). 베이스 코드모드는 근음만·옥타브2(`BASS_OCTAVE=2`)·velocity 0.4(과음 방지). `tuning.ts`의 `CHORD_NOTES`가 옥타브 들쭉날쭉한 문제를 엔진에서 통일(구현내역 §3 참조).
- `QUAL_IV`: `''=[0,4,7]`·`m=[0,3,7]`·`7=[0,4,7,10]`·`m7=[0,3,7,10]`.
- 엔진 음정 함수 자체는 Tone.js/WebAudio 의존이라 헤드리스 단위테스트 불가 → 통합/실기기 범위. 음정 정확성은 `tuning.test`(UT-TN-01~12)·`events.test`(UT-EV-01~02)가 순수 레벨에서 보증.

핸들러 불변식(코드에서 직접 확인):
- 정원: `MAX_TRACKS=16`. `trackCount(code) >= 16`이면 트랙 추가 409.
- 중복방지(멱등): `POST /sessions` 멱등토큰은 `key(author_key/IP):token`로 스코프(타인이 같은 토큰으로 내 code 못 받음, Codex MED). 댓글은 같은 `author_key+text` 60초 내 중복 무시.
- 콘텐츠 dedup: origin 없는 원곡 publish + 실제 클라 키일 때 `(author_key, content_hash, track_count)` 동일·published·미숨김이면 새 세션 안 만들고 기존 code 멱등 반환. `track_count`까지 키에 포함해 레이어 더 얹은 재게시는 collapse 안 됨. `node:sqlite` 동기 SELECT~INSERT~COMMIT 사이에 await 없어 원자적(레이스 없음).
- 소유권(published 오염 차단, Codex P0): published 세션 트랙 추가는 `author_key`가 소유자와 일치할 때만(seed/빈키 거부). 파생은 새 `POST /sessions` + `origin_code`.
- 신고자 위조 방지(Codex P0): 신고자 식별 = 서버 도출 IP(`clientIp`, TRUST_PROXY 하드닝 전제). 클라 `author_key` 회전으로 distinct 신고자를 위조해 자동숨김 트리거 불가.
- 출처 강제: `origin_code`가 오면 `sessionExists` 검증, 없으면 400. INSERT-only(여기서만 기록).
- 숨김 전파: `hidden=1` 세션은 GET/comments/like 모두 404(공개 차단, Codex MED).
- 레이트리밋 버킷팅은 `author_key`가 아니라 IP로(키 회전 우회 차단). 기본 바인드 `127.0.0.1`(nginx 리버스프록시만, 8080 외부 직접 노출·X-Real-IP spoof 차단, Codex R039).
