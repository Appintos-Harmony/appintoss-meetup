# 하모니 커뮤니티 기능 명세서 v3 — 음원 공유 + 합 쌓기 공간

> **포지셔닝:** "완전한 커뮤니티"가 아니라 **라이트 음악 컨텐츠 생산 앱의 "녹음 음원을 공유하고, 남이 가져와 그 위에 합을 쌓는 공간"**. 피드 알고리즘·테마·팔로우·랭킹·**좋아요(발표/심사 빌드 미노출)** 는 비범위.
> **상태:** 곽소정 TASK-006과 정합 머지 완료(커밋 119aa75, tsc+vitest 58/58). 서버 `apps/api/server.mjs` + 클라 `Community.tsx`(이모지 카드 + 서버 보드·댓글·출처·3상태·올리기) 일부 구현됨.
> **v3 근거:** 다각 부정피드백(5각도 34건) → 적대적 재검증 → 타당 23건 수렴. 변경 요약 §12, 기각/오정정 §14.

## 1. 스코프 핸드오프 (조장 승인 전제)
커뮤니티 본체는 기존 이상혁(조장) 소유(DL-022 범위 외)였고, 김민혁 스트림이 인수(2026-06-23). **조장 승인 게이트** 전제. 코드 삭제·플래그·머지·푸시·스코프 변경은 조장 권한.

## 2. 진단 (왜)
현 로컬 데모(PRELOAD+listSongs·로컬 가짜 좋아요)엔 진짜 타인의 공유물이 없음. → 서버 공유 보드(listCommunity) + 출처 강제 파생 + 코멘트를 기존 `sessions/tracks`에 얹는다.

## 3. 핵심 루프 & 기능
**루프:** *녹음 → "커뮤니티에 공유"(이름) → 보드 → 남이 들어보고 가져와 그 위에 한 겹 → **합주해서 올리기(출처 박힘)** → 보드에 파생곡 + 원곡 파생수 +1 → 코멘트.*

## 4. 기능 상세 (변경 위주)

### F4·F5 · 출처 파생 루프 — ★P0 (앱 유일 차별점, 현재 죽은 코드)
- **현 상태(확증):** `share.ts` `publishSession.originCode`는 정의됐으나 **호출부가 안 채움** → `origin_code` 항상 null → **forkCount 구조적으로 항상 0**, 출처 크레딧 칩은 시드에만. 다중 담기는 `code:'LOCAL-import'`만 onFork. Studio엔 파생 publish 경로 부재. → §10 데모 클라이맥스 재현 불가.
- **최소 배선(P0, 4일 내 데모 보장):**
  1. `share.ts` `Session` 타입에 `originCode?: string|null` 추가, `getSession` 매핑(서버는 이미 반환).
  2. `App.tsx` forked 상태를 `{session, originCode}`로 확장, `onFork`가 originCode 보존.
  3. `Community.tsx` **단일 가져오기**일 때 원본 `code`를 originCode로 전달(다중 담기는 "재료만(비파생)"으로 §9 후속 분리).
  4. `Studio.tsx`에 기존 비공개 `share()`와 **분리된 신규 "합주해서 올리기"** 액션: `publishSession({events: 원본+내겹, originCode, authorKey, idempotencyToken, published:true})` + 상단 "○○의 △△ 위에 쌓는 중" 출처 칩.

### F6 · 코멘트 — 신고/숨김 정직화
- 신고 3건(`REPORT_HIDE_N` env로 조정) 누적 시 hidden. **현재 가역 복원(unhide) 미구현 → 트리거만 존재(비가역).** 복원은 조장 수동(DB) 또는 후속 `POST …/comments/:id/unhide`(자기 댓글/운영토큰). sybil 완화: reporter dedup을 `author_key|ip` 조합 + report에도 IP 레이트리밋.

### F7 · 보상 — 좋아요 대체
- 재생수(playCount) + 파생수(forkCount). 좋아요는 발표/심사 빌드 **보드 미노출**(아래 §9).

## 5. 신뢰·보안 모델 (정직 고지 — 과장 축소)
- **익명키(author_key) = 약한 소유권(데모 한정).** `identity.ts`의 브라우저 폴백 익명키는 `crypto.getRandomValues` **128bit 암호난수**(`randomHex(16)`)다. **레이트리밋·댓글 dedup은 서버가 author_key를 검증 안 해 엔트로피와 무관하게 우회 가능** → 엔트로피 상향이 스팸 방어를 강화하진 않음(피해자 키 추측→hide 위조 위험만 축소).
- **레이트리밋 = IP 기준(키 회전 우회 방지).** 현 코드는 `author_key||ip` 키라 매 요청 랜덤 키로 무력화됨 → **`ip` 기준으로 변경**(또는 ip+key 동시 버킷), `report` 엔드포인트에도 추가. `RATE`/`IDEMP` Map은 **TTL·sweep**(빈 버킷 delete, IDEMP 10분 만료)로 메모리 바운드.
- **출처(origin_code) = 표기 무결성**(INSERT-only로 사후 제거/변조 방지)일 뿐, **"도용 방지의 실제 근거"라는 일반화는 철회.** 무인증·약한 소유권이라 서버는 origin 실재만 검증하고 호출자가 원본 author인지 미검증 → 협업 크레딧 위조·forkCount 오염은 데모 한정 한계(prod=서명 바인딩 후속). **자기참조/순환 가드** 추가(server.mjs 미구현분).
- CORS `*`·무인증은 데모 한정 → production 오리진 allowlist = 사람(조장) 게이트.

## 6. 데이터·API (실제 server.mjs 기준)
기존 `sessions/tracks`·멱등 ALTER·`badEvents` 재사용. v3 보강:
- **다중트랙 원자성:** `POST /sessions`가 `tracks[]`를 같은 BEGIN/COMMIT 안에서 적재(또는 트랙 적재 완료 전 `published=0`→마지막 `published=1`). 클라 `publish`의 addTrack 루프 제거.
- **무한 생성 차단:** `published` 전역/IP 상한(예 ≤200) 초과 시 429/409. IP 레이트리밋(§5).
- **play_count 쓰기 완화:** 매 GET 동기 UPDATE → IP 디바운스/메모리 카운터 주기 flush(`play:ip` 레이트리밋).
- **보드 쿼리:** 항목별 N+1 서브쿼리 → LEFT JOIN+GROUP BY 단일 쿼리 권고. 커서 `(created_at, code)` 복합·limit 상한 유지.
- **데이터 수명주기(정직 고지):** 데모는 정리 배치 없음. prod 전제 = 물리삭제 배치·세션당 바이트 상한·DB 총량 경보. (선택 `PRAGMA journal_mode=WAL`.)
- **정정:** "1.5s 폴링"은 **보드와 무관**(Studio 잼 동기화 한정) — 보드 갱신 = 진입 1회 GET + pull-to-refresh.
- 시드: `hide` 핸들러에서 `author_key='seed'`(또는 SEED 화이트리스트) 숨김 거부.
- ⚠️ 서버 배포·마이그레이션·production = 사람(조장)만. AI=코드+로컬 테스트.

## 7. 화면
보드 카드(이모지 아바타·이름·작성자·메타(트랙/재생/파생)·출처 크레딧·들어보기/담기/댓글) + 3상태(로딩/빈/실패) + 올리기 시트 + 댓글 패널. **좋아요 하트는 발표/심사 빌드 미노출**(§9). 상세 레이아웃은 이미지 명세서(스케치→와이어→목업) 별도.

## 8. 정책 (POL-03)
- **심사 제출본 기본값 = code 기반 비공개 모드**(`published` 기본 0 유지 + `/community` 비공개/미노출) → 공개 UGC 소셜 분류 리스크 구조적 회피. **OQ-B로 조장이 구현 굳히기 전 선결.** 발표 데모는 시드곡+자기입력만 → 비공개로 충분.
- **자동 필터 = PII 최소 방어(URL/EMAIL/PHONE)뿐, 유해 텍스트(욕설·혐오) 차단 비보장**(정직 고지). 공개 보드 전환 시 선결: 한글 블록리스트→reports 가중→임계 hidden, URL 난독 정규화 (OQ-F).
- 콘텐츠 = events JSON + 음원 이름 + 짧은 댓글(평면). 음원 이름도 UGC 표면(신고/숨김 대상).

## 9. 비범위
피드 추천·테마·팔로우/DM/프로필·랭킹·해시태그/검색·오디오 업로드·실시간·대댓글·"재료만(비파생) 다중 담기"(후속).
- **좋아요:** 발표/심사 빌드 **보드 미노출**(스펙 §11.4 "로컬 가짜 좋아요 제거" 이행). `likes.ts` 파일은 **보존(미참조 dead)** — 곽소정 보존 원칙과 양립. 코드 제거/플래그/머지는 **조장 승인 게이트**(OQ).

## 10. 발표 데모 (실제 밟는 최소 경로, 2장비 ~3분)
1. A: 녹음 → "커뮤니티에 공유"(이름 "여름밤 코드").
2. B: 보드 **pull-to-refresh** → A 곡 등장(서버 공유 증명). *("자동으로 A 폰에 뜸"은 폴링 없음 — 수동 새로고침이 정확.)*
3. B: 들어보기(트랙별 음색) → **가져오기(originCode 보존)** → 한 겹 → **"합주해서 올리기"**.
4. 보드에 B 파생곡 + 카드 "A와 함께 만든 곡" + A 원곡 **파생수 +1**(이게 P0 배선의 증거) → 합주 듣기.
5. B 댓글 → A 새로고침 시 표시. 마무리: *"올리고, 가져와 쌓고, 한마디."*
6. 폴백 리허설: 시드곡(빈 보드 방지), 공유 연타 멱등.

## 11. 구현 단계 (P0=발표 필수)
1. **★출처 파생 루프 배선(§4 F4·F5 최소 배선)** — 데모 §10이 실제 밟는 경로. 최우선.
2. 레이트리밋 IP 기준 전환 + report 레이트리밋 + RATE/IDEMP TTL.
3. 좋아요 보드 미노출(조장 승인 후) + Community.tsx §9 정합.
4. 다중트랙 트랜잭션 원자화 + published 상한 + 시드 hide 거부.
5. (선택) 익명키 crypto 교체, unhide 라우트, N+1→JOIN, play_count 디바운스.
6. 2장비 리허설(originCode·forkCount+1·멱등·시드 폴백) → tsc/vitest → 조장 승인 푸시.
