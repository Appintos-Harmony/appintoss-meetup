# 통합 테스트 계획서 (하모니)

> 이 문서는 **계획만** 담는다. 실제 실행 결과(Pass/Fail·로그·일시)는 [통합테스트_결과서](통합테스트_결과서.md)가 담당한다. 근거: [CLAUDE.md §15.2](../../CLAUDE.md) 통합테스트 전략, [테스트 규칙](../../.claude/rules/tests.md).

## 1. 대상과 목적
모듈 단위테스트를 넘어 **클라이언트↔백엔드↔여러 사용자**가 함께 동작하는 흐름을 검증한다. 핵심 통합 관심사는 ① 세션 공유/받기/얹기 API 계약, ② 클라 라우팅·로컬 저장 복구, ③ 합주 polling(외부 트랙 자동 반영), ④ 카메라 불가 시 터치 폴백, ⑤ CORS·UTF-8(한글) 무결성이다.

오디오 실제 소리·카메라 손 제스처 인식·실배포 2기기 합주 같은 **실기기·하드웨어 영역**은 헤드리스로 검증 불가하며 [앱인토스_실기기검수표](앱인토스_실기기검수표.md)가 담당한다(§5 연계).

## 2. 범위

### 2.1 포함
- 백엔드 엔드포인트: `GET /healthz`, `POST /sessions`, `GET /sessions/:code`, `POST /sessions/:code/tracks` (`apps/api/server.mjs`)
- 클라 흐름: 온보딩→스튜디오 라우팅, 녹음 저장→홈 목록→복구, 공유→받기→얹기, polling, 카메라 폴백 (`apps/miniapp`)
- 데이터 무결성: CORS, UTF-8 한글, 없는 코드 404, 프리로드 폴백

### 2.2 제외 (실기기·배포 → 실기기검수표)
- 실제 오디오 소리(Tone.js), 카메라 손 제스처 인식(MediaPipe), 합주 합쳐듣기 소리(트랙별 음색)
- 토스 샌드박스 2기기 실배포 합주, AWS 프로덕션 HTTPS 전체 시나리오

## 3. 테스트 시나리오

ID 규칙: API 계약은 `IT-API-NN`, 클라↔서버·UI는 `IT-CL-NN`.

### 3.1 IT-API — 백엔드 엔드포인트
| ID | 절차 | 기대 | 관련 요구사항 |
|---|---|---|---|
| IT-API-01 | `GET /healthz` | 200 `{ok:true}` | (인프라) |
| IT-API-02 | `POST /sessions` (base 트랙·events 포함) | 201 `{code}` 발급 | FR-SHARE-01 |
| IT-API-03 | `GET /sessions/:code` | 1 track·bpm 등 메타 반환 | FR-SHARE-02 |
| IT-API-04 | `POST /sessions/:code/tracks` (얹기) | 201 `{ok,trackId}` | FR-SHARE-03 |
| IT-API-05 | 얹기 후 `GET` 재조회 | 2 tracks·owner 정상 | FR-SHARE-03 |
| IT-API-06 | `GET` 없는 코드 | 404 | FR-SHARE-02 |

### 3.2 IT-CL — 클라↔서버·UI
| ID | 절차 | 기대 | 관련 요구사항 |
|---|---|---|---|
| IT-CL-01 | 온보딩(닉네임)→시작→스튜디오 | 라우팅 전환 정상 | FR-ID-01 |
| IT-CL-02 | 녹음 저장→홈 목록→열기→복구 | 저장 곡 목록 노출·복구 | FR-SAVE-01 |
| IT-CL-03 | 제스처 선택→카메라 불가 | 터치 폴백+안내 문구 노출 | FR-PLAY-02 |
| IT-CL-04 | 공유(origin 생성)→얹기→재조회 | 2 tracks·한글 정상 | FR-SHARE-01, FR-SHARE-03 |
| IT-CL-05 | 받기(클립보드 거부)→프리로드 | base 트랙 로드·합주 배너 | FR-SHARE-02 |
| IT-CL-06 | 공유→외부 트랙 추가→polling | 트랙 카운트 자동 증가(폴링 주기 내) | FR-SHARE-04 |

> 합주 합쳐듣기(FR-JAM-01)의 실제 소리는 헤드리스로 검증 불가 → 실기기검수표 RT-11.

## 4. 환경
### 4.1 로컬·헤드리스(통합 기본)
- 클라: `apps/miniapp` Vite dev (`http://localhost:5173`), 프리뷰 브라우저(스냅샷/eval 증거)
- 서버: `apps/api/server.mjs` (node:sqlite, `http://localhost:8080`)
- OS/런타임: Windows 11 · Node.js(결과서가 실측 버전 기록)
- API 호출: PowerShell `Invoke-RestMethod` 또는 브라우저 fetch
- 커밋 SHA·실행 일시는 결과서가 실측 기록

### 4.2 AWS(배포 통합)
- 백엔드 고정 HTTPS(`VITE_API_BASE`, 근거 [DL-021](../00_프로젝트관리/의사결정_기록.md)·[apps/api/README.md](../../apps/api/README.md))
- 미니앱 `ait deploy`는 토스 로그인·앱 등록(appName)·키 로테이션 후 **사람 실행**(AI는 준비만)

## 5. 실기기 검수 연계
헤드리스 통합으로 닿지 못하는 하드웨어·2기기 합주 항목은 [앱인토스_실기기검수표](앱인토스_실기기검수표.md)에서 사람이 검증한다. 통합 시나리오 ↔ 실기기 항목 매핑:

| 통합 시나리오(헤드리스) | 실기기 보강 항목 | 대상 |
|---|---|---|
| IT-CL-03 카메라 폴백 | RT-04·RT-05·RT-06 카메라 권한·제스처 연주·거부 폴백 | FR-PLAY-02 |
| IT-API-02~05 / IT-CL-04 공유·얹기 | RT-10·RT-12 2기기 공유→받기·얹기→polling | FR-SHARE-* |
| (헤드리스 불가) 합주 소리 | RT-11 합주 합쳐듣기 소리 | FR-JAM-01 |
| (헤드리스 불가) 코드 소리 | RT-02·RT-03 터치 코드 소리·AudioContext unlock | FR-PLAY-01 |

P0(데모 필수) 실기기 항목과 실패 시 대안은 실기기검수표 §판정을 따른다.

## 6. 완료 기준 (Exit Criteria)
- IT-API-01~06·IT-CL-01~06 전부 **Pass**(결과서 실측).
- CORS·UTF-8(한글)·없는 코드 404·프리로드 폴백·polling 자동 증가가 모두 확인됨.
- 실기기 P0 항목(실기기검수표)이 Pass 또는 데모 대안 확보.
- 실패 시나리오는 결함 ID 부여 후 [테스트증빙_목록](../../평가증빙/테스트증빙_목록.md)에 연결, 수정·재실행 전까지 완료로 처리하지 않는다.
