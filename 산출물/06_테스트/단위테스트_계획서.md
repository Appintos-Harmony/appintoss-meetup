# 단위 테스트 계획서 (하모니)

> 이 문서는 **계획만** 담는다. 실제 실행 결과(Pass/Fail·로그·일시)는 [단위테스트_결과서](단위테스트_결과서.md)가 담당한다. 근거: [CLAUDE.md §15.1](../../CLAUDE.md) 단위테스트 전략, [테스트 규칙](../../.claude/rules/tests.md).

## 1. 대상과 목적
악기 합주 미니앱 「하모니」의 **순수 로직 모듈**(Web Audio·Tone.js·카메라 비의존)을 헤드리스(vitest)에서 검증한다. 단위테스트의 목적은 음악 도메인 규칙(코드 입력 상태 전이, 음정 정확도, 이벤트 계약, 노트 편집)이 입력에 대해 결정적으로 동작함을 보장하는 것이다.

오디오 소리 출력, 카메라 손 제스처 인식, transport 타이밍 같은 **부수효과·실기기 영역은 단위테스트 범위 밖**이며 [통합테스트_계획서](통합테스트_계획서.md)와 [앱인토스_실기기검수표](앱인토스_실기기검수표.md)가 담당한다.

## 2. 범위

### 2.1 포함 (단위테스트 대상 모듈)
| 모듈 | 파일 | 책임 | 관련 요구사항 |
|---|---|---|---|
| 코드 입력 reducer | `apps/miniapp/src/audio/chordReducer.ts` | 터치/제스처 코드·멜로디·드럼 입력의 tick 기반 상태 전이(순수함수) | FR-PLAY-01, FR-REC-02 |
| 음정/튜닝 | `apps/miniapp/src/audio/tuning.ts` | 음이름→MIDI→주파수(평균율 A4=440), 코드 구성음·보이싱 | FR-PLAY-01 |
| 이벤트 계약 v2 | `apps/miniapp/src/audio/events.ts` | 코드/멜로디/드럼 이벤트 정규화·와이어 직렬화·28코드 인터벌 | FR-PLAY-01, FR-SHARE-01 |
| 노트 편집 | `apps/miniapp/src/lib/noteEdit.ts` | 이벤트↔노트 파싱·직렬화 왕복, 퀀타이즈 | FR-REC-02 |
| 크로매틱 지판 | `apps/miniapp/src/lib/notes.ts` | 반음 단위 transpose·계이름(solfa)·MIDI 음명 왕복 | FR-PLAY-02 |

### 2.2 제외
- 오디오 엔진(`audio/engine.ts`), transport·메트로놈(`audio/transport.ts`), 제스처 인식(`audio/gesture.ts`) — Web Audio/MediaPipe 부수효과로 헤드리스 단위테스트 불가 → 실기기.
- 클라↔서버 통신·UI 라우팅·polling → [통합테스트_계획서](통합테스트_계획서.md).
- 백엔드(`apps/api/server.mjs`) 엔드포인트 → 통합테스트(IT-API-*).

## 3. 테스트 항목

ID 규칙: `UT-<모듈코드>-NN`. 모듈코드 — RD(chordReducer), PY(poly 회귀), TN(tuning), EV(events), NE(noteEdit), NT(notes). [단위테스트_결과서](단위테스트_결과서.md)의 ID와 일치한다.

### 3.1 UT-RD — 코드 입력 reducer (`chordReducer.test.ts`)
| ID | 대상 | 방법 | 기대 |
|---|---|---|---|
| UT-RD-01 | 첫 down | `down(C)` 적용 | noteOn 1개·activeChord='C' |
| UT-RD-02 | 같은 코드 연속 down | `down(C)`×2 | noteOn 1개(중복 무시) |
| UT-RD-03 | 다른 코드로 전환 | `down(C)`→`down(G)` | 이전 off + 새 on, activeChord='G' |
| UT-RD-04 | up | `down(C)`→`up` | noteOff 1개·activeChord=null |
| UT-RD-05 | 터치 중 gesture down | `down(C,touch)`→`down(G,gesture)` | gesture 무시(터치 우선) |
| UT-RD-06 | 터치 종료 후 gesture 차단창 | up 후 +150ms/+250ms gesture | 200ms 이내 무시·이후 허용 |
| UT-RD-07 | 비활성 소스 up | `down(C,touch)`→`up(gesture)` | 활성 코드 유지 |
| UT-RD-08 | 폴리 동시 down | `down(C4,poly)`→`down(E4,poly)` | on 2개·이전 off 없음·activeNotes 2개 |
| UT-RD-09 | 폴리 한 음만 up | C4·E4 down 후 `up(C4)` | C4만 off·E4 유지 |
| UT-RD-10 | 폴리 같은 음 재down | `down(C4,poly)`×2 | noteOn 1개(중복 무시) |
| UT-RD-11 | 폴리 비활성 음 up | `down(C4)`→`up(G4)` | off 없음(무시) |
| UT-RD-12 | 코드 모드 단음 보존 | poly 없이 `down(C)`→`down(G)` | 전환 시 이전 off 1개 |
| UT-RD-13 | 드럼 hit 단발 | `hit(drum:kick)` | on 1개만·activeChord/Notes 불변 |
| UT-RD-14 | 연속 hit 누적 | hit×3 | on 3개·off 없음 |
| UT-RD-15 | 코드 연주 중 hit | `down(C)`→`hit(drum:hat)` | activeChord='C' 유지·hit 적재 |

### 3.2 UT-PY — 폴리포니 회귀 (`chordReducer.poly.test.ts`)
멀티터치 멜로디 경로가 코드 경로(activeChord)와 독립임을 보장하는 회귀 세트(근거 [REVIEW-20260622-032 M-3](../09_AI개발파이프라인/독립검토서/)).
| ID | 대상 | 방법 | 기대 |
|---|---|---|---|
| UT-PY-01 | 여러 음 동시 보유 | C4·E4·G4 down | activeNotes 3개·on 3개 |
| UT-PY-02 | 같은 음 재입력 동일 참조 | C4 down 후 재 C4 down | 동일 참조 반환·on 1개 |
| UT-PY-03 | 한 음만 떼기 | C4·E4 후 up(C4) | E4 유지·off 1개(C4) |
| UT-PY-04 | 누르지 않은 음 up | C4 후 up(G4) | no-op·동일 참조 |
| UT-PY-05 | 코드 상태와 독립 | C4 down | activeChord=null·activeSource=null |
| UT-PY-06 | 전부 떼면 on/off 균형 | C4·E4 후 둘 다 up | activeNotes 비고 on 2·off 2 |

## 4. 환경
- OS/런타임: Windows 11 · Node.js(결과서가 실측 버전 기록)
- 테스트 러너: vitest 4.x (`apps/miniapp/devDependencies`)
- 대상 패키지: `apps/miniapp`
- 외부 의존 없음(Tone.js/Web Audio/MediaPipe import 없는 순수 모듈만 대상)

## 5. 도구·실행 방법
- 도구: **vitest**(설정 `apps/miniapp/vite.config.ts` 공유). 단언은 vitest 내장 `expect`.
- 실행: `npm --prefix apps/miniapp run test` (= `vitest run`)
- 재현(직접 호출): `& apps/miniapp/node_modules/.bin/vitest.cmd run --root apps/miniapp`
- 검증 게이트 연계: `node tooling/scripts/검증_전체.mjs`의 단위테스트 단계.

## 6. 완료 기준 (Exit Criteria)
- 위 6개 파일(UT-RD/PL/TU/EV/NE/NT)의 모든 케이스가 **Pass**.
- 신규/변경 도메인 로직 추가 시 해당 케이스를 본 표에 추가하고 결과서에 실행 기록을 남긴다.
- 실패(Fail) 케이스는 결함 ID를 부여하고 [테스트증빙_목록](../../평가증빙/테스트증빙_목록.md)에 연결, 수정 후 재실행 전까지 완료로 처리하지 않는다.
- 완료율은 추정하지 않고 `Pass 수 / 전체 수`로 결과서에 기록한다.
