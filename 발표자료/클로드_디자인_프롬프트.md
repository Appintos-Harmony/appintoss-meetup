=== 프롬프트 시작 ===

너는 시니어 프레젠테이션 디자이너이자 프런트엔드 엔지니어다. 아래 내용으로 **캡스톤 발표 슬라이드 덱**을 만들어줘. 결과는 **자체 완결 HTML 1파일**(외부 CSS/JS 의존 없이 inline, 16:9 = 1280×720 기준, 좌우 방향키로 슬라이드 넘김, 우하단에 현재/전체 페이지)로 출력해. 디자인 기준은 **Toss Design System · Apple · Stripe · Notion 수준**의 절제되고 전문적인 비주얼.

## 제품 한 줄
하모니(harmony) — 앱인토스(토스 미니앱 마켓) 안에서 도는 음악 합주 미니앱. 코드를 몰라도 악기를 터치·카메라 제스처로 연주하고, 트랙을 쌓아 혼자서도 합주를 만들고, 공유 코드로 친구 연주 위에 내 악기를 얹는다.

## 발표 맥락 (꼭 반영)
- 청중: 캡스톤 심사위원. **교수님이 Loop Engineering·Harness Engineering(AI 개발 자동화)을 가장 강조**했다. 단순 기능 나열이 아니라 "AI를 어떻게 썼더니 어디까지 자동화됐나"의 엔지니어링 서사로.
- 평가 비중: 발표·시연 50% / 산출물 25% / AI 파이프라인·재사용 25% / 앱인토스 배포 +10%.
- 톤: 과장 금지, 정직. "한 것과 안 한 것을 섞지 않는다"가 이 팀의 강점.

## 절대 바뀌면 안 되는 사실 (정확히 이대로만)
- 단위테스트 58/58 Pass, 통합테스트 34/34 Pass(API 12·보안 7·클라 6·실기기 9), 보안 블랙박스 7/7, vite 빌드 645.87kB.
- 실기기 9건은 S23 Ultra 사람 육안 검증 성공(자동 회귀 아님), 증빙 보유.
- 사용자 식별 = 2트랙: 토스 WebView에선 getAnonymousKey 실호출 / 일반 브라우저에선 익명키. 데모 한정 약한 소유권(서버가 author_key 미검증). "mock"도 "완전 실연동"도 아님.
- 토스 앱: 정식 등록·심사 제출 완료, 현재 "검토 중"(영업일 2일 통지). appName=harmony. **"배포 완료/승인"은 아직 아님.** 가산점은 심사 승인 시 확보.
- AI 통제면 = ChatGPT Pro·Gemini Pro 실제 2모델(페르소나 아님). 사람이 Claude가 짠 프롬프트를 각 모델에 입력해 4-AI 토의·독립 판정.
- 라이브 시연은 토스 WebView가 아니라 브라우저 HTTPS(https://3.39.167.74.nip.io). 정직하게 고지.

## 슬라이드 구성 (본문 17 + 부록 3)
1. **표지** — "하모니 / 혼자도 합주, 코드로 합주". 부제 1줄: "코드 몰라도 악기를 쌓아 곡을 만들고, 코드 한 줄로 친구 연주에 얹는 앱". 팀 4인(이상혁·제품/정책/팀장, 곽소정·UX/프론트, 김민혁·백엔드/데이터, 양록빈·QA/릴리즈). 다크 배경 권장.
2. **목차** — 4섹션: ①제품·기능 시연 ②시스템 아키텍처 ③AI 활용 파이프라인 ④프로젝트 후기. 아이콘 포함.
3. **아이디어의 시작** — 팀이 만든 손 제스처 AI(MediaPipe 온디바이스 수어→소리 번역기) 경험이 하모니의 카메라 연주로 이어졌다. 이미지 2장 자리.
4. **문제** — 합주는 사람·장소·악기가 동시에 맞아야 한다. 그래서 실시간을 빼고 비동기 '얹기'로 풀었다.
5. **해결** — 4블록: ①코드 몰라도 눌러서 연주(피아노·기타·베이스·드럼 터치 + MediaPipe 카메라 제스처) ②코드 매트릭스(코드 골라 반주) ③멀티트랙 레이어(혼자 여러 악기 쌓기) ④비동기 합주(공유 코드로 남 트랙 얹기, 1.5초 폴링).
6. **기능 — 스튜디오** — 폰 목업 4장(코드패드 C·Am·F·G / 카메라 제스처 / 더보기 시트 / 멜로디 건반). 캡처: 05_스튜디오·코드_제스처모드·12_더보기시트·13_멜로디모드.
7. **기능 — 커뮤니티** — 남 음원 들어보기·좋아요·댓글·내 트랙에 추가. 캡처: 04_커뮤니티·36_커뮤니티_인기순·26_공유_세션.
8. **라이브 시연** — 5단계 타임라인(연주·녹음 → 트랙 추가 → 공유 코드 6자 → 가져와 얹기 → 합주 재생). LIVE URL + 백업(3분 녹화·캡처). 정직고지: "토스 심사 제출 완료(검토중), 시연은 브라우저 HTTPS".
9. **시스템 아키텍처** — "솔로는 클라이언트에서 완결, 합주만 서버. 외부 의존성 0". 좌(토스 WebView: React18·TS·Vite6·Granite·Tone.js·MediaPipe·localStorage) — HTTPS REST — 우(AWS EC2 Ubuntu: nginx TLS·harmony-api node:http+sqlite·SQLite). 식별=2트랙. 하단 스탯: API 외부의존성 0 / 1.5초 폴링 / 127.0.0.1 바인드.
10. **품질·테스트** — "추정이 아니라 실측". 큰 스탯 4: 58/58 단위 · 34/34 통합(API12·보안7·클라6·실기기9) · 7/7 블랙박스 보안 · 645.87kB 빌드. 헤드리스 검증됨(도메인·API·보안) / 실기기 9건 Pass(S23 Ultra 육안, 증빙 EV-201~209).
11. **AI 파이프라인 ① 역할 분리** — ChatGPT Pro·Gemini Pro(통제) / Claude Code(오케스트레이션) / Codex(구현·검증) / 사람(승인). 핵심: 구현 AI ≠ 검토 AI를 강제 분리, AI끼리 대화하지 않고 git 문서(TASK·REVIEW·diff)를 메시지 버스로.
12. **Loop Engineering** ★교수 1순위 — 제목 "코드가 강제하는 자율 엔지니어링 루프 한 바퀴". 원형/가로 흐름: SELECT(Ready 1건) → PREFLIGHT(가드 게이트 GO/STOP) → IMPLEMENT → VERIFY(tsc·vitest, 실패 시 REPAIR≤2회 후 재검증) → COMMIT(green만) → REVIEW(Codex 독립검토) → STOP(사람 대기). 핵심 3줄: ①안전 게이트는 프롬프트 재량이 아니라 종료코드로 강제(STOP 10·범위위반 11·반복 캡 12) ②푸시·머지·배포는 루프 밖(사람) ③1차 빌드에서 자동 게이트가 사람 눈 전에 구현오류 2건 차단.
13. **Harness Engineering** ★교수 1순위 — 제목 "git을 메시지 버스로 쓰는 자동화 평가 하네스". 3층 스택: [상] 사람 승인(main 병합 3조건 AND: 조장 승인·검증_전체 --strict PASS·독립검토서) [중] 검증_전체.mjs가 검사 6종(비밀값·링크·산출물·작업지시서[구현자≠검토자]·팀문서·코드 tsc+vitest)을 AND 게이트로 묶어 종료코드 1개로 [하] git 훅(pre-commit 비밀값·pre-push main 차단). 우측: 3에이전트 상호검증, "AI는 자기 권한·게이트를 못 넓힌다". 하단: 브랜치 전략(feature/fix→develop→release→main, DL-014).
14. **AI 진정성** — "독립검토가 보안 결함을 잡아 No-Go → 수정 → Go". 빨강(No-Go)→초록(Go) 타임라인. 4단계: 독립검토 결함 3건 → REVIEW-038 No-Go 머지 차단 → commit 수정(인가·키회전·XFF) → REVIEW-040 Go(보안 7/7+사람 승인). REVIEW-038이 잡은 것: 공개 세션 트랙 오염(소유권 누락)·신고 키회전 우회·XFF 위조. 부제: "'AI 티 안 나게'의 답은 사람이 통제하는 검증 게이트".
15. **결과·한계·다음** — 완료(AWS HTTPS 운영·스모크 PASS / 단위 58·보안 7 / tsc 0·vite build / 필수 산출물 15종). 진짜 한계만: 토스 심사 승인 대기 · TDS 부분 적용 · 번들 코드 스플리팅. (※"토스 등재 후속·익명키 mock·실기기 미완" 같은 옛 표현 쓰지 마라 — 이미 해소됨.)
16. **프로젝트 후기** — 3컬럼: 하네스 엔지니어링 활용 팁 / 트렌드 점검 / 배운 역량(앱인토스 플랫폼 이해·AI 통제 파이프라인·정직한 품질 보고·기획~배포 경험). 재사용을 정량으로: "검증 11검사·Loop 커맨드·11스킬 = 다음 앱은 하네스 0에서 시작 안 함".
17. **Q&A**.
- 부록 1~3(Q&A 백업): 데이터 모델 ERD / 배포 인프라 구성도 / 신뢰경계 DFD(보안). 다이어그램 이미지 풀슬라이드 + 제목.

## 디자인 시스템 (TDS)
- 색: 주조 토스 블루 `#3182F6` / 잉크 `#191F28`·본문 `#4E5968`·캡션 `#8B95A1` / 성공·PASS·Go `#15C47E` / 경고·No-Go·결함 `#FF6B6B`. No-Go=빨강·Go=초록 일관, 한 슬라이드 액센트 1색.
- 폰트: 한글 **Pretendard**(없으면 'Malgun Gothic') sans-serif 일관. 표지 60pt / 헤드라인 30pt / 스탯 콜아웃 40~56pt / 본문 14~16pt / 캡션 11~12pt. **명조(serif) 쓰지 마라.**
- 레이아웃: 좌측 마진 일관, 한 슬라이드 핵심 3블록 이하, 여백 충분. 카드/표/타임라인을 섞어 단조 반복 금지.
- 금지(AI 티): 제목 밑줄, 풀폭 색 띠·사이드 스트라이프, 그라데이션 배경, 등호·슬래시 명사 나열, 기계적 대구, 과장어(완벽한·혁신적·엔터프라이즈급), 불필요한 하이픈/대시로 문장 잇기.
- 이미지: 폰 스크린샷은 라운드 폰 프레임, 다이어그램은 흰 배경 카드. 첨부 캡처를 해당 슬라이드에 배치(못 올리면 회색 자리표 + 파일명 캡션).
