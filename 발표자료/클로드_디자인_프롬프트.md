## 반드시 강화 (교수님 1순위)
교수님이 **Loop Engineering·Harness Engineering**을 가장 강조했다. 각각 **전용 슬라이드 1장**을 신설해.

**Loop Engineering 슬라이드** — 제목 "코드가 강제하는 자율 엔지니어링 루프 1바퀴". 원형 다이어그램으로 **생성→검증→수정→재생성**: SELECT → PREFLIGHT(게이트 GO/STOP) → IMPLEMENT → VERIFY(tsc+vitest, 실패 시 REPAIR≤2회 후 재검증) → CHECK-DIFF(게이트) → COMMIT(green만) → REVIEW(다른 계열 AI) → STOP(사람 대기). 핵심 메시지: "안전 게이트는 프롬프트 재량이 아니라 종료코드로 강제된다. 푸시·머지·배포는 루프 밖(사람)." 실제로 자동 게이트가 사람 눈 전에 구현오류 2건을 차단한 사례.

**Harness Engineering 슬라이드** — 제목 "git을 메시지 버스로 쓰는 자동화 평가 하네스". 3층 스택: [상] 사람 승인(main 병합 3조건 AND) / [중] 단일 오케스트레이터가 검사 6종(비밀값·링크·산출물·작업지시서·팀문서·코드 tsc+vitest)을 AND로 묶어 종료코드 1개로 / [하] git 훅(pre-commit 비밀값·pre-push main 차단). 핵심: "구현 AI와 검토 AI를 다른 계열로 코드가 강제 분리. AI는 자기 권한·게이트를 못 넓힌다." 브랜치 전략(feature/fix→develop→release→main, main에 자물쇠+3조건)을 하단 작은 박스로.

## 슬라이드별 개선 (요지)
- **표지:** 팀 4인을 이름+역할 한 줄로 축약, 시선 한 곳. 다크 배경+큰 타이틀+태그라인 1줄.
- **INDEX(빈 슬라이드):** 내용 없으면 삭제하거나 섹션 4개(제품/설계/품질/AI) 목차로.
- **모션그래픽(수어번역기) 슬라이드:** 하모니와 연결 약하면 삭제 또는 "팀의 AI 역량" 1줄로 축소.
- **해결:** "= + +" 등호·플러스 제거, 블록 제목을 동작형("코드 몰라도 눌러서 연주").
- **품질:** "12/12"→"34/34". 실기기 "9건 Pass+육안 한계 1줄".
- **AI 도구활용:** 8단계 가로 적층을 4묶음으로, 밀도 완화. Loop는 위 신규 슬라이드로 분리.
- **AI 진정성(독립검토):** 발표 클라이맥스로. "AI가 AI를 막다" 제목, No-Go(빨강)→수정→Go(초록) 좌우 타임라인. 실제 잡은 결함: 공개 세션 트랙 오염(소유권 누락)·신고 키회전 우회·XFF 위조 → 보안 7/7로 Go.
- **결과·한계:** stale("토스 등재 후속·익명키 mock·실기기 미완") 삭제. 진짜 한계만: 토스 심사 승인 대기·TDS 부분 적용·코드 스플리팅(번들 645kB).
- **후기:** 일반론("AI 시대 대비") 대신 정량: "검증 11검사·11스킬·Loop 커맨드 = 다음 앱은 하네스 0에서 시작 안 함."
