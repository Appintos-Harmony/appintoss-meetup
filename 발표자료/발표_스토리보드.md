# 발표 스토리보드 (PPT 제작 전 흐름 정리)

> 최종 PPT 제작 전 발표 흐름·메시지·증거를 정리한 초안. **제품 배포·테스트·시연은 아직 진행 중 → "예정"으로 표기(완료처럼 쓰지 않음).** SDK/정책은 미검증.

## 1. 발표 제목
- 주: **"앱인토스 소모임 미니앱 — AI 3에이전트로 만든 추적 가능한 개발 파이프라인"**
- 부: 초대 코드형 오프라인 모임 운영 도구 (대표 템플릿: 경찰과 도둑)

## 2. 발표 목표
- 평가 4축(발표/산출물/AI 활용/배포 가산)을 한 흐름으로 보여준다.
- "AI를 많이 썼다"가 아니라 **"역할 분리 + 독립검토 + 사람 승인이 추적된다"**를 증거로 증명.
- 미완성(제품 배포·테스트)은 정직하게 "예정"으로 구분해 신뢰를 얻는다.

## 3. 평가 항목별 대응 전략
| 평가 | 비중 | 발표에서 보일 것 | 상태 |
|---|---|---|---|
| 발표·시연 | 50% | 문제→해결→흐름 시연(현재 화면 흐름/목업, 배포 후 라이브) | 시연 **예정** |
| 산출물 완성도 | 25% | PRD·기능정의서·추적표·헌장 등 한글 산출물 | 일부 확보, 일부 예정 |
| AI 도구 활용·파이프라인 | 25% | 3에이전트 구조 + 실사례(REVIEW NO-GO→GO) + 재사용 | **확보** |
| 앱인토스 배포 | +10% | 배포 URL·실기기 | **예정**(MCP/계정 후) |

## 5. 슬라이드별 상세

### S1. 표지 (20초)
- 핵심 메시지: 제목 + 팀(4인) + 한 문장 소개.
- 화면: Toss 블루 배경, 앱 로고/아이콘, 부제 1줄.
- 증거: [README](../README.md). 미확정: 팀 최종 슬로건.

### S2. 문제 (40초)
- 핵심 메시지: 오프라인 놀이 모임의 모집·신청·승인이 채팅/메모로 흩어져 번거롭다.
- 화면: 흩어진 채팅 vs 정리된 앱 아이콘 대비.
- 증거: [PRD](../산출물/01_서비스기획/제품요구사항정의서_PRD.md) §1.

### S3. 해결 / 제품 (50초)
- 핵심 메시지: 앱인토스 미니앱에서 모임 생성→신청→승인까지. **초대 코드형**(공개 추천 없음).
- 화면: 핵심 기능 아이콘 6개(생성·초대·신청·승인·공지·신고).
- 증거: PRD §2·§3(FR-001~014). 미확정: 최종 UI.

### S4. 핵심 사용자 흐름 · 시연 (60~90초)
- 핵심 메시지: 진입→상세→신청→승인→상태 갱신 한 흐름.
- 화면: 9단계 흐름 다이어그램(§3.3) + 화면 목업.
- 시연: **예정**(배포 전). 백업: 화면 흐름 목업·녹화. 라이브는 배포 후.
- 증거: PRD §2.

### S5. 설계 (50초)
- 핵심 메시지: 미니앱 + API + DB의 단순 모듈러 구조, 서버 상태 강제(정원·중복).
- 화면: 시스템 구성 다이어그램(예정), 데이터 흐름.
- 증거: 시스템 구성도·테이블 정의 = **예정**(설계 TASK). SDK 연동 = 미검증.

### S6. 품질 (50초)
- 핵심 메시지: 자동 검증(문서·링크·비밀값) 통과 + 상호검토 게이트 운영. **제품 단위/통합 테스트는 예정.**
- 화면: 검증 PASS 캡처, 게이트 흐름.
- 증거: [평가 증빙 맵](../평가증빙/평가_증빙_맵.md). 제품 테스트 결과 = 예정.

### S7. AI 파이프라인 ① 3에이전트 구조 (60초)
- 핵심 메시지: 통제(ChatGPT Pro)·실행(Claude/Codex)·승인(사람) 역할 분리, 자기검토 금지.
- 화면: 3층 구조 다이어그램 + 메시지버스(작업지시서/독립검토서/합의).
- 증거: [하네스_소개](../산출물/09_AI개발파이프라인/하네스_소개.md), [라이프사이클_흐름](../산출물/09_AI개발파이프라인/라이프사이클_흐름.md).

### S8. AI 파이프라인 ② 실사례 (60초)
- 핵심 메시지: AI가 만든 코드의 보안 결함을 **다른 AI가 잡고 사람이 승인해 고침**.
- 화면: TASK-010 → REVIEW-011 **NO-GO**(pathspec magic) → 수정 → REVIEW-012 **GO** → 커밋/머지 타임라인.
- 증거: [라이프사이클_흐름](../산출물/09_AI개발파이프라인/라이프사이클_흐름.md) 실사례, git 이력.

### S9. 재사용 · 결과/제한 (50초)
- 핵심 메시지: 복사→치환→git init로 다음 팀 재사용. **결과: AI 운영 파이프라인 증명 / 제한: 제품 배포·테스트는 예정.**
- 화면: 재사용 3단계 + 정직한 현황(확보 ✓ / 예정 ⏳).
- 증거: [25점 대응표](../산출물/09_AI개발파이프라인/평가_25점_대응표.md).

## 6. AI 도구 활용 강조 (필수 2장)
- S7(구조) + S8(실사례)로 충족. 발표 시 원본 프롬프트 나열 금지, **요구사항→작업지시→구현→독립검토→자동테스트→사람승인→문서동기화** 한 흐름만 증거로.

## 7. 제품 시연 상태
- S4 시연 = **예정**. 배포 완료 전까지 목업/녹화로 대체, 라이브 시연은 배포 후. 완료처럼 표현 금지.

## 8. 디자인 방향 (전문가형)
- 컬러: Toss 느낌 파랑(#3182F6 계열)·흰색·회색. 강조 1색만.
- 아이콘 기반, 텍스트 최소. **한 슬라이드 핵심 메시지 3줄 이하.**
- 아키텍처/흐름 **다이어그램 중심**(스크린샷·표는 보조).
- 일관 그리드·여백, 장식 문구·이모지 남발 금지.
