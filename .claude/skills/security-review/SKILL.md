보안 검토는 §14(보안·오프라인 안전)·`.claude/rules/code.md` 기준의 독립 점검이다. 구현자 자기검토로 대체하지 않는다(§6.1-3). 산출은 `독립검토서`(REVIEW-…).

1. 대상 diff와 관련 작업지시서·요구사항(특히 `POL-`·인증/인가/삭제/신고)을 읽는다.
2. 비밀값: `node tooling/scripts/비밀값_스캔.mjs`(전체) 또는 `--staged`. 노출된 키·토큰·사설키·커밋된 `*.db`/`.env`는 P0.
3. 객체 단위 인가(IDOR): 모든 mutation·조회가 소유자·역할을 **서버에서** 검증하는지. 공개 세션 오염·코드 추측·키 회전 우회를 실제 요청으로 찌른다.
4. 입력 검증·주입: `node:sqlite` 파라미터 바인딩(문자열 연결 금지), XSS, 경계값, 정원·중복 신청 방지가 서버측 강제인지.
5. 경계: rate limit, 신뢰 프록시(XFF·X-Real-IP) 단일 실패점, CORS, 세션 만료, 감사 로그, 개인정보 최소수집·삭제 경로, 오프라인 안전 규칙(§14)이 제품 기능으로 강제되는지.
6. 실행 검증(블랙박스·스모크)을 돌린다. 못 돌리면 `Not Run`. 발견을 P0~P3 + 재현 근거(file:line·요청/응답)로 분류하고 사람 승인 질문과 함께 반환한다. 직접 수정은 요청 시에만.
