# 하네스 재사용 실증 (§19.1 사례 8)

> CLAUDE.md §19.1이 "반드시 포함"으로 요구하는 사례 8 — **새 앱에서도 재사용 가능한 하네스**의 실제 이식·작동 증거. 2026-06-27 실행. "재사용 가능하다"는 주장을 말이 아니라 실행 로그로 증명한다.

## 무엇을 했나

하모니 저장소의 **하네스 골격만**(앱 코드·산출물 본문 제외) 빈 임시 저장소에 복사하고, `git init` 후 검증 스크립트를 그대로 실행했다.

- 복사 대상: `CLAUDE.md` · `AGENTS.md` · `CHATGPT_PRO_운영지침.md` · `.claude/`(agents·skills·rules·settings.json) · `.agents/skills/` · `tooling/`(scripts·git-hooks) + 작업지시서 템플릿 1개
- 명령: `git init` → `node tooling/scripts/비밀값_스캔.mjs` · `작업지시서_검증.mjs` · `검증_전체.mjs`

## 실행 결과 (실제 로그)

```text
----- 비밀값_스캔 -----
# 비밀값 스캔
비밀값 패턴 없음
결과: PASS          (exit 0)

----- 작업지시서_검증 (템플릿만) -----
# 작업지시서 검증
검사 0개 (템플릿 제외)
결과: PASS          (exit 0)

----- 검증_전체 (오케스트레이터) -----
 FAIL  팀 공유 문서      ← 새 앱이 아직 6종 팀 문서를 안 만듦(정상)
 PASS  산출물 존재(보고)  ← 누락 산출물을 다음 할 일 목록으로 보고
 FAIL  내부 링크        ← git.md→재사용_운영지침.md(최소 복사라 미포함) 1건
 PASS  작업지시서
 PASS  비밀값
전체 결과: FAIL — 하네스 기본 검증 (2건)
```

## 해석 (정직)

- **전체 결과가 FAIL인 것이 핵심 증거다.** "all green"이 아니라, 새 앱이 아직 산출물을 안 채웠으니 게이트가 **즉시 그것을 잡아낸다**. 하네스는 빈 저장소에서 곧바로 "다음에 무엇을 채워야 하는지"를 가리키는 체크리스트로 작동한다 — **0에서 시작하지 않는다.**
- 포터블한 게이트(비밀값·작업지시서)는 **즉시 PASS**. 비밀값 스캔과 구현자=검토자 검사는 새 저장소에서 바로 강제된다.
- 내부 링크 FAIL 1건은 하네스 결함이 아니라 **최소 골격만 복사**한 결과다(`git.md`가 참조하는 `재사용_운영지침.md` 미포함). 전체 골격을 복사하면 해소된다. 동시에 게이트가 깨진 링크를 정확히 잡는다는 증거이기도 하다.
- 부수 효과: 이식 자산 수(에이전트 11 · 스킬 7+3 · 룰 4 · 스크립트 12)가 독립검토 REVIEW(파이프라인 감사)의 카운트와 **교차 일치**함을 재확인.

## 다음 앱 적용 절차 (이 실증에서 도출)

1. 골격 복사 → 2. 프로젝트명·앱 ID 치환 → 3. `git init` → 4. `검증_전체` 실행 → 게이트가 채울 산출물을 알려줌. 반나절 세팅으로 같은 거버넌스(구현자≠검토자·비밀값 차단·main 보호·산출물 추적)를 새 제품에 즉시 적용.

## 재현 방법

임시 저장소에서 위 명령을 그대로 실행하면 동일 결과가 나온다(원본 저장소 무변경). 본 실증은 원본을 수정하지 않고 복제본에서만 수행했다.
